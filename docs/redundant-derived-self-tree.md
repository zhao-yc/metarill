# R1 自树与同目标多选的派生名称缓存

日期：2026-10-28。对应进度 B94，开发起点 `803c34e`。本轮只完成下述固定 MySQL 子集，复杂关系整体保持部分完成。

## 实现与使用

R1 指保存名称缓存的冗余模式，R0 指按关系计算名称的非冗余模式。来源 R1 保存关联 ID 和物理名称缓存，目标为普通 R0 实体；目标名称来自已证明的单值字符串联接，例如树节点的 `name = company.name`，或继续经过 `company.brand_id → brand.label`。树拓扑、项目和删除范围保持物理字段。路径由原树读取器实时展示，物理缓存仍只保存叶子名称。

同一派生目标可以同时被自树和原 `MultiSelectPage` 消费。多选沿原 type=2 目标页、声明的名称列及辅助列发布；生成写入以实际目标当前锁读取值，不读取被 ORM 忽略的逻辑实体属性。自动辅助列和显式缓存采用同一存储规则，名称数组按所选 ID 顺序保存，省略、null、空数组及伪造名称仍沿原合同。

目标改名、关联切换和逻辑删除经统一维护／混合传播队列刷新来源缓存及后续缓存，全部加入目标原事务；不重新调用消费者 Service 或观察器。数组采用单独反向成员依赖，不能仅依靠同页自树更新恰好带动多选。反向 SQL 只由发布目录编译，业务 ID／项目通过驱动参数绑定，不增加任意 SQL 输入入口。

原维护 HTTP／按钮仍显式回填，当前读、物理预检、200项数组预算和128行来源批次保持。缓存投影保持全部已声明数组的历史预算检查；即使数组不含本次目标，来源历史超额仍使整笔事件或全量维护回滚。固定计划只编译一次，执行阶段不反复解析元数据。

运行时发布目录只为 R1 派生多选保留目标页 type 与名称列声明，继续清除布局及敏感配置。平台和既有普通生成产物不因此增加界面变化。
