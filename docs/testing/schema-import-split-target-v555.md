# V555 反查保存的分库同名归属验收

2026-11-08。使用 `b009fb65` 严格发布当前 Production 平台，在 Server-200 独占 MySQL 双库及独占 Redis 上从空库显式初始化。平台库和业务库分别创建一张同名合成表，两张表各有一条记录，列与索引成员不同，以实际结构辨别读取目标。原平台项目通过真实登录和原配置接口登记其同名表，再切到业务项目审核并导入。

| 检查 | 结果 |
| --- | --- |
| 审核目标 | 业务项目使用原单段表名成功审核。显式传入带数据库限定符的表名被拒绝，平台项目反查已登记表也被拒绝。 |
| 确认归属 | 切回平台项目提交业务审核凭证被拒绝。原业务计划仍为 prepared，回到业务项目可正常确认并返回 saved。再次确认和再次审核已导入表均被拒绝。 |
| 独立读回 | 平台配置库只有两条活动归属记录，各属正确项目且使用不同字符串 ID。业务导入只保存 `business_only`、`delete_no`、`id` 三列，一个索引及一个成员，零页面。业务库无配置表。两张源表的 DDL 摘要和原记录均保持。 |
| 清理 | 首轮完成原接口到确认阶段，但独立索引成员读回误用不存在的表归属列，整轮未通过。按 `config_index_id` 修正读回后换新独占双库复验通过。两轮各自独立核验双库、账号、所有权记录、Redis 容器与临时目录消失，转发端口释放。 |

本记录补齐同一 MySQL 实例下分库同名、跨项目审核凭证和限定表名三个固定场景。A11 的其他库名配置、实例组合与权限矩阵继续按 [实施进度表](../project-progress.md) 跟踪。
