# V440 同父导入锁前结构核验专项

2026-11-07，基线 `4b7bc827`。使用当前驱动连接 Server-200 的 MySQL 8.4.11，每轮各建两张独占合成表。测试在业务连接上显式开启可重复读事务，先执行待查语句，再由独立连接更新同一父记录并提交。业务连接随后分别使用 `FOR UPDATE` 和普通读读取父记录。更新未被待查语句阻挡，当前读均得到新值。普通读得到旧值说明待查语句已提前建立快照。MySQL 的可重复读以事务内首次一致性读建立的快照为准。[MySQL 8.4 一致性非锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html)

| 业务事务内的待查语句 | 普通读观察到旧值 |
| --- | ---: |
| 读取库名及报文上限 | 0/3 |
| 双表零行普通读或零行锁定读 | 各 0/3 |
| 原 `information_schema` 引擎与列检查组合 | 3/3 |
| 单独查询 `information_schema` 引擎或列定义 | 各 3/3 |
| 单独 `SHOW CREATE TABLE` | 0/3 |
| 单独 `SHOW FULL COLUMNS` 或 `SHOW TABLE STATUS` | 各 3/3 |
| `SHOW CREATE TABLE` 加 `SHOW FULL COLUMNS` | 3/3 |
| 先做一次真实父记录普通读的正对照 | 3/3 |

分离连接专项在业务事务只做零行锁定读，另一条同实例连接查询结构。三次并发父更新均能提交，业务事务的当前读与首次普通读均得到更新后的值。分别对父表和明细表发起真实 DDL，结构证明连接在 DDL 等待期间完成查询。DDL 在业务事务释放前均被阻挡，结束后重新执行成功。

完整定义分别检测到五类物理变化，覆盖引擎、复合主键、字段类型、可空性和生成列。两条独立连接读到的基线定义一致，每次精确复原后完整定义回到基线。显式 ID 插入和修改缓存列不会改变该模型的定义。当前证据不覆盖自动增长计数、临时表遮蔽及其它 MySQL 版本。

不能将原引擎、列定义查询或 `SHOW FULL COLUMNS` 移到同一事务的父锁之前。它们会改变原父候选首次一致性读的时点。下一候选可对已用原逻辑验证的两张物理表记录完整定义，在同一事务先固定结构，再用 `SHOW CREATE TABLE` 比对。必须把证明绑定到实际服务器、库和发布计划，任何缺失或变化都回到原校验，并用真实原导入验证快照、首错、回滚及同条件性能。
