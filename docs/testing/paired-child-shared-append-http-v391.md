# V390–V391 生成导入入口的可选共享父锁验收

2026-11-06，基线 `d44efff`。原 Excel 追加入口在明确配置时读取管理员安装的只读例程证明。默认仍取排他父锁。仅固定父键、叶子来源、单个物理关系缓存、默认 ORM 且无逐行宿主副作用的导入可尝试共享锁。两个连接都核验实际库名和实例 UUID。原事务用零行当前读固定父子表定义，另一个连接核对表结构、例程公开属性、明细触发器可见性和例程结果，避免提前建立业务快照。

V390 和 V391 使用实际生成 Controller、Service、原导入路由及隔离 MySQL。隔离 HTTP 宿主使用合成普通身份和原文件观察者。例程证明有效时，八行批次观察到父记录共享锁和共享重验，未出现父排他锁。两个并发同父请求均成功。自定义观察者逐行收到八次通知，并走排他父锁。共享路径保留了前序数据库错误的准确行号及整批回滚。

以下情况均观察到原父排他锁，且合成业务结果逐值核对通过。

- 配置例程不存在。
- 明细存在实际写父的 INSERT 触发器。八行仍产生八次原触发器更新。
- 定义者的明细表级 `TRIGGER` 被撤销。
- 父表实际有 `ON UPDATE CASCADE` 外键。

V391 额外以同一普通测试账号确认父共享锁查询实际在等待未提交的父行。另一个事务提交后，原导入的一致性读看到新父，八行写入和缓存值正确，确认前置证明查询未提前固定业务快照。最终实库轮次共核对 72 行成功写入及失败回滚，两个轮次的库、运行账号、锁定定义者及所有权记录均已独立确认清理。

严格构建零警告零错误。生成定向 21 通过，Data 1576 通过及 29 个条件跳过。配置和例程均未应用到现有部署。真实完整宿主的同条件性能复测仍待执行，首版继续以 [V382 无采样正式结果](paired-child-packed-append-timing-v382.md) 判定。部署权限边界与停用步骤见 [MySQL 共享锁配置](../mysql-shared-append.md)。
