## V966 同一父记录的四事务并发

2026-11-11。沿用 V965 签名的 MySQL 8.4.11 免安装文件及逐字一致的 V960 数据层 DLL。独立连接先持有合同父记录的主键排他锁，再向原生成导入动作同时发出四个请求。独立观察连接在放行前从 MySQL 锁表确认同一个主键记录上有四个等待事务和一个实际持锁事务。

放行后，三个批次均按后七行合并路径成功提交。独立 SQL 核对 24 个唯一明细 ID、父键、金额和缓存的 latin1 字节及尾空格。另一批由第 4 行缓存触发器导致失败，整批零残留，首错后的测试触发器计数保持。四个并发请求和先前 17 个请求共核对 58 条物理记录。

首轮锁观察错误地将等待队列中的阻塞事务与实际持锁事务一起计数，在放行前停止。复验分别读取等待事务和实际已授予的记录锁，保留四等待、一持有断言。两轮独占进程、回环端口及临时数据已由新进程分别核验清理。本轮只验证并发功能，正式吞吐和 p95 等待 Server-200。
