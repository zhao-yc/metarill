# 固定候选条件计划

目标是保留原 V8 候选条件及原前端协议：配置在生成/发布时编译，请求只提供值，查询、已选回读、写入、复制及导入最终使用同一范围。本文区分已经完成的数据适配基础与仍须接入的产品入口，不能把计划类或离线通过当成整个功能完成。

## 已实现的基础

`FixedConditionPlan` 识别字段白名单上的 AND、分组、比较、IN、LIKE、IS NULL/IS NOT NULL、数值/字符串/布尔/NULL 和独立变量符号。字符串中的 AND、逗号、SQL标点和双单引号保持字面量，反斜杠保持字符。未知字段、语句、注释、函数或其它表达式明确拒绝，不忽略尾部；定义、项数、分组和集合大小有界。字段及变量目录和条件节点均冻结。

`FixedConditionSqlPlan` 在编译时固定字段逻辑类型与常量，在数据适配层用已校验标识符和参数占位符构建条件。运行时只绑定显式窄变量，总是 AND 到原查询，缺失或错误变量在修改查询前失败。LIKE 保留模式语义，区别于已确认的关系名称字面 Contains；普通文本筛选保留原LIKE模式。=NULL、<>NULL 和 IN(NULL) 保持 SQL 三值语义，不偷换为 IS NULL。整数不经浮点转换，decimal 不静默舍入，非零 double 不下溢成零。逻辑 double 仍是浮点类型，不承诺任意十进制文字无损表示。

真实 MySQL 适配层已经验证高位 ID、LIKE、IN、比较、空值、字符串注入样本、参数化 count，以及整数/文本两种项目列；样本只使用本轮自有随机表。这些适配层验证本身不授予页面或记录权限。下述 List 常量分支另外通过了正式生成 Controller 的 HTTP/MySQL 验证。

## 已接入的 List 常量条件

原 List 字段及页面级 controlDetail 覆盖可以在既有项目/父范围上增加物理标量常量条件，支持比较、IN、LIKE、IS NULL/IS NOT NULL、AND 分组及字符串中的 AND/逗号。生成阶段验证完整语法、物理字段、逻辑类型及字面量，常量候选目标必须与外键及显示来源一致；生成 Service 中的静态不可变计划在装载时再次核对同版运行时，请求只绑定真实 Actor 项目和已经验证的目标父，不重复解释配置 SQL。

原数组候选、分页/count、已选回读使用同一 OptionsScope。新增、明确字段更新、默认值、标记提交字段的手写钩子和复制重新核对最终真实实体；目标父依赖字段改变时，即使没有提交关联外键也重验。写入通过同事务 FOR UPDATE 当前读检查真实父和选中目标，避免已有 RR 快照的计数误拒绝及父删除绕过。读候选不取写锁，普通写入仍沿用本页动作，不增加目标列表权限。

名称/数字导入使用同一候选范围；原目标父拓扑、默认及已锁定实体上下文保持，不能依赖 Excel 属性顺序。后行失败回滚整批。条件本身是候选限制，不额外改变来源记录详情及文件读取权限。

正式生成、编译及实际 HTTP/MySQL 已覆盖旧数组与专用已选、分页/关键词/count、默认与钩子、更新失败回滚、复制、合法与非法导入、乱序父依赖和父变化重验。另用两个普通连接验证 RR 当前值、父删除、目标/父锁等待、无关目标可写及提交释放；未新增全局或列级观测授权。原前端、请求槽及平台元数据不变。

## 已接入的本对象表单依赖

List 条件可引用本页已开放的同对象物理标量：`@formParameters.field` 和 `@formParameters.tableCamel.field`。字段、路径、逻辑类型、运算符及SQL常量在生成时固定；请求不能换表、换列或改条件。原UI按表名缓存，旧调用方也有平铺槽，后端按声明路径优先，仅在缺失时读取同字段的另一槽；明确null、重复键、容器和错误类型不会因此退回另一值。新建时尚未确定的主键/审计字段、凭据、数组、跨对象或未开放依赖仍拒绝。

旧数组转分页/只读回读保留原 formParameters，专用候选与已选合同消费同一槽。绑定先验证源字段逻辑类型，再按目标条件检查，不能借目标int64放宽源int32，也不能静默舍入或下溢。所有current_*身份值仍由宿主提供，客户端同名键不覆盖身份。

保存/复制从默认值、手写规则处理后的真实实体取值；修改任一声明依赖，即使省略关联外键也重验。 更新还保留关联、依赖及目标父的锁定原值；手写规则修改这些字段时必须把数据库字段名加入 submittedFields，未登记且实际变化则拒绝，不能用未持久化的临时值通过另一字段的校验。创建/复制仍整体写入实体。导入拓扑包含全部父及表单依赖，首列覆盖只先解析匹配闭包，锁定原记录后再使用其省略值；重复列、循环或后续错误仍拒绝/整批回滚。导出只额外投影必要依赖，并按父及实际联动值隔离名称缓存，不把隐藏依赖加到表头。

冗余与非冗余源表都经过正式生成、真实HTTP/MySQL、原平铺/嵌套槽、默认/钩子/复制、依赖变化、乱序和覆盖导入及真实XLSX验证。非冗余页级覆盖仅在where条件已完整编译且目标、名称与其它定义保持一致时放开；名称/目标变化继续拒绝。完整非冗余应用包另验原助手受管更新、手写保护和包内restore/build。此处的HTTP夹具使用固定服务端身份，不等于原浏览器或Production登录下的完整联动验收。

## 仍须接入的完整路径

页面物理标量常量见[页面固定条件](fixed-page-conditions.md)。非冗余多选 Excel 已接入物理字段附加条件，见 [B285](#b285-非冗余多选-excel-附加条件)。其余未接入的页面扩展、跨对象变量和关系附加条件继续按各入口验证。

- 页面固定查询、关系选项、单选/多选目标及文件来源采用同一条件证明；配置来源、字段、排序、页级覆盖和已发布目录不能由请求替换。
- 本对象物理标量的原 formParameters 槽已接通；跨对象/父对象及账号扩展变量仍需明确宿主映射和依赖证明，不能保存整账号或凭据。
- 写入按真实实体及当前锁定对象验证，关联外键或依赖字段变化都须重验；复制、默认值和手写钩子不能绕过。不能为了候选联动额外增加目标维护权限。
- 导入拓扑包含全部条件依赖，保持原追加/覆盖匹配规则，后续错误回滚整批；已选回读与普通候选不能采用不同范围。
- 参数化 SQL 必须在同一完整范围内完成分页/count/统计和写前当前锁定，不能先分页再过滤；未证明语法不得去掉条件继续生成。
- 最后通过正式生成包、真实 Web/MySQL、原浏览器和所需并发组合，才逐项放开能力门槛。复杂原生 SQL 仍需明确数据库方言及完整执行证明。

本阶段没有改前端、接口、平台配置、平台/现有业务库物理结构或现有生成产物，不需要 SQL 迁移。使用 List 常量/本对象表单条件的项目必须配套同步已列出的条件运行时和重新生成的 Service；其余未接线路径不能手工删掉旧拒绝检查。

## B285 非冗余多选 Excel 附加条件

原 Java 的多选弹窗使用目标页列表，Excel 名称反查在目标页条件上叠加来源控件的 `whereSql`。C# 在相同的导入入口恢复这部分行为。源表采用非冗余存储时，表级配置及页面覆盖均可对目标物理字段使用固定值、当前账号和本行表单值。项目或父键变量沿用目标页已证明的范围，目标名称可以来自物理列或固定联接。

导入把本行联动值、父级及当前身份绑定到参数化条件，与目标页范围一起做当前读。表单字段加入原整行解析依赖，仍以唯一匹配解析名称数组。目标页自身已编译的账号条件会与导入附加条件一并执行。控件引用目标逻辑字段的实现见 [B286](#b286-多选-excel-逻辑字段条件)。

22 项定向生成回归通过，新增用例装载实际生成程序集，检查有效页覆盖、父键精度、账号和表单参数、目标页条件以及未证明的父键拒绝。同步生成的后端后即可使用，实库专项验收按首版进度表安排。

## B286 多选 Excel 逻辑字段条件

非冗余多选原 Excel 导入可按控件附加条件读取目标的跨表逻辑 ID 和层级名、自树叶名及普通单值联接字段。生成时核对实际候选页、级联路径及终点类型，发布目录保留该路径涉及的页面条件。稀疏层位从可见级联还原，自树叶名沿完整祖先链求值。目标页已有的账号、父级及其它条件一同作用于名称匹配。

附加条件在原导入事务内绑定。Excel 仍按名称唯一命中生成 ID 数组，普通弹窗沿目标页查询，保存按既有字段合同校验。最终数据层 438 项、生成专项 8 项通过。 实库专项按首版进度表安排。

## B287 单选 Excel 附加条件

非冗余业务页的原单选控件通过实际目标页打开弹窗。Excel 名称反查在目标页条件上叠加表级或业务页覆盖的 `whereSql`，允许固定值、实际项目和父键、当前账号及本行表单值。非冗余目标也能沿固定级联或普通单值联接读取逻辑字段。

导入先校验来源权限与真实父记录，再在原事务内用参数化条件查找唯一目标。冗余物理目标使用原实体查询，非冗余目标使用包含实际候选页的固定计划。表单字段进入整行解析依赖，继续使用原 Excel 名称、ID 和整批错误协议。

数据层 438 项、定向生成 20 项通过。 验证包含原前端生成检查、实际生成服务装载、已证明父键与高精度 ID 的参数绑定。已有工程同步后端运行时并重新生成，实库专项按首版进度表安排。

## B288 覆盖导入保持首列关联一致

Excel 首列为依赖联动值的下拉或单选时，按当前页面范围解析首列并锁定匹配记录。整行解析用锁定记录的旧联动值补足省略项，然后在更新前核对首列解析结果。如果同一名称在旧联动范围内指向其他 ID，按原导入错误协议报告行号和列名，并撤销该批次。

31 项定向回归通过，覆盖两种控件的生成分支、原中文错误定位、逻辑首列和完整包生成。已有工程同步后端运行时并重新生成。真实工作簿和 MySQL 事务验收按首版进度表安排。
