# 固定非冗余 crossTable 的空库与正式 Web 宿主

本项延续[B40完整包](nonredundant-cross-table-full.md)，不以包构建、Node挂载或固定授权器替代真实宿主。正式测试由 `FreshCrossTableMySqlTests` 从元数据工厂生成 FullApplication，在 Production/Web 模式运行包内主程序；数据库、文件服务和身份解析均为真实实现。

## 四种独占新库

来源ID／目标父键的 string/string、string/int64、int64/string、int64/int64 各使用自己的随机新库。每组确认0表，普通启动和预览后仍0表；显式同步安装4业务表、3文件表和6安全表，共13表。重复同步无差异，重复安全初始化不改密码。没有对现有 `metarill_test` 或 `metarill_business_test` 执行安全初始化。

目标三表故意复用同一个大于JS安全整数范围的数值主键，证明层级来自固定链而非数值猜测。种子仅写本轮新库，产品表结构由元数据与 SchemaService 创建，无手写产品DDL。

## 直接执行的原接口

- 原form登录、按项目／后台／目标页严格核对真实菜单回读、数据库持久会话、宿主重启后沿用令牌，以及注销后拒绝。
- 根／中／末层选择、双控件与逻辑父交集、错误父拒绝、整体清空、复制、来源软删除；直接读取物理稀疏槽与实际结构，名称不落物理列。
- 原上传计划、multipart上传、完成、保护文件下载、文件引用复制／解绑；错误父或非法文件同时比较来源记录及全部引用墓碑，确认整笔回滚。
- 普通数据库账号与角色权限，来源只读拒绝新增，目标查询未授时拒绝候选，授权后原逐级候选与路径可用；同一会话撤销目标查询后候选立即拒绝，来源读取与文件仍按来源权限判断；来源撤权后记录和保护文件均拒绝。
- 通过真实目标更新端点改名，来源回显实时名称且物理槽不变；目标失效后拒绝保护文件访问，恢复后再次核对文件流。

测试没有注入固定 `IRuntimeAuthorization`，没有使用开发认证。当前正式宿主的失败合同保持：普通内部业务拒绝返回统一500，缺读取授权的文件引用返回401，页面动作权限返回403；用例分别严格核对HTTP和R业务码，不把任意非200当作通过。

## 受限场景与清理

`fresh-mysql.ps1` 保留默认 Baseline（4库／3项）；新增 CrossTable（4库／4项）和 All（8库／7项）。服务端只接受固定场景后缀，创建与清理使用同一所有权清单及实例pin，临时账号仅获本轮库权限；未知场景、场景变更、既有对象碰撞和外来对象均拒绝。

所有Docker命令在核对Server-200主机名与192.168.31.200地址后，使用该服务器固定Unix socket执行。管理员凭据仅在容器内读取，不输出到本机或版本库；临时凭据只通过SSH标准输入／子进程环境传递。本机没有运行Docker。

可选 `CredentialBackupRoot` 备份本轮受限配置并附中文说明，不复制原连接账号。成功清理后删除工作区临时配置、撤销随机账号并在备份说明中记录凭据已失效。每轮均核对TRX场景数量、实际执行及零跳过，清理后独立查库／查账号；失败证据保留，不覆盖旧记录。
