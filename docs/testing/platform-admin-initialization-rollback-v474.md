## 故障与核验

在目标库只对本轮原会话的 ID 添加 MySQL `CHECK`。会话有效时允许，原中央按钮尝试写入会话的删除标记时由数据库拒绝。约束 DDL 在独立连接执行，业务仍走原 HTTP、授权和事务。以服务端日志中该约束的实际违反为故障证据，通用失败响应仅用于核对原接口协议。

- 在独立读回中核对原账号所有字段、原会话所有字段和超级角色不存在。共库使用原 Web 会话访问权限接口，分库另核对本来缺失的目标项目、后台归属仍未写入。
- 移除合成约束后，向同一中央按钮重试相同请求，并完成原直调重复重置、保留账号 ID 与档案、角色和密码变更、会话撤销及墓碑拒绝。
- 共库使用真实旧会话和新密码登录。分库在业务连接检查目标会话和账号，并确认平台源账号与权限保持。
- 本轮验证初始化事务内的实际写失败和重试。独立业务宿主登录、初始化与登录并发争用、浏览器操作及 Agent 刷新授权策略继续跟踪。
