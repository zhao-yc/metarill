## 本批行为

示例：全局终点 `global_target.name` → 全局R0逻辑名称 `global_source.global_target_name` → 普通项目的多选／数据库复选。

- 普通R0/R1来源保留真实项目列、原物理ID数组、原页面与权限。多选保持type=2固定目标页；复选继续自己的候选与来源动作授权，不增加目标列表权限要求。
- 无行项目的全局R0目标必须显式发布。名称只沿已证明的物理单值键读取非凭据字符串；每步核对当前目录、真实非空int64主键、软删、固定页面和路径。字符串内层外键沿既有二进制精确比较。
- R0不增加名称物理列，数组表达式在独立目标子查询内按原序号读取，保留缺失位置，名称筛选不扩张来源行。R1名称数组进入完整混合传播／原维护计划，R0中间表不伪造可更新名称副本；多选200、复选5000预算保持。
- 全局R0上的真实物理字符串标签继续走原直接数组读取和物理传播，显式／自动名称归属一致，不强迫标签变成逻辑字段。
- 循环、超过原16层／跳数、虚拟／多值／文件或敏感字段、未发布或矛盾目标、动态目标条件及带行项目的全局R0目标仍拒绝。级联、共享父及文件父不会借此新用途放行。

生成／静态装载时完成证明，请求执行固定计划。继续生成Entity、DTO／VO、Mapper、Service、Controller和原页面，不新增动态解释器或新界面。
