# 同页混合控件与必填校验

本批保持原uni-app页面、样式、控件、按钮和接口，只修复C#生成Service的校验，并实际验证普通独立跨表链、自树级联、多选同页组合。

## 三种约束分别处理

| 配置 | 生成后行为 |
|---|---|
| 数据库`NOT NULL`，页面未要求必填 | 只拒绝`null`，允许非空值`""`；默认值仍按原入口处理。 |
| 原显式可写页面字段`isMust`/`IsRequired` | 字符串拒绝null/空白；多值拒绝null/空白/JSON null/空数组；标量拒绝null。 |
| 只读字段带必填配置 | 不因级联加入隐式级ID而重新启用页面必填；物理非空约束仍保持。 |

原YZP的UniappService约1224行只对`isMust==1 && isReadOnly!=1`生成必填规则。现在使用模型扩展前的`DeclaredWritable`确定页面必填归属，普通表单仍可传控件需要的隐式级ID，不新增页面字段。

`RequiredFieldValue.IsEmptyArray`按JSON数组值判断，避免`"[]"`作为非空文本绕过必填；非数组或无效JSON明确报输入错误。该方法在Core中，独立包必须携带同版源码。原跨表末级字段必填仍绑定末级：只选择根不能满足末级必填，不擅自改成“任一级有值即可”。更新先合并旧值再校验，省略字段保留，明确清空按原约束校验；失败事务不留下部分更新。

## 同页组合

同页crossTable显示来源行已存名称，自树显示当前目标路径；目标改名后，无关来源更新保留跨表旧名并读取自树新名，显式复制重新归一化跨表名称。查询同时使用来源已存跨表ID和自树后代范围，保持既有异步自树边界；选择确认与复制沿原路由。

覆盖来源string/int64与父键string/int64四组合实际生成编译；Server-200隔离业务库执行两种同型键的五表样本，验证上述三种校验、默认值、显式null、更新省略与回滚、末级必填、混合显示/筛选/选择确认/复制。固定测试身份HTTP不等于正式登录、原浏览器或设备验收。

修复前真实响应和失败TRX已保留：数据库空字符串错误返回500、必填空多选错误返回200、只读祖先为空的更新错误返回500。修复后定向6/6通过；随后Metarill.Generation.Tests完整回归（明确排除需专用新库的FreshInstallMySqlTests）1168/1168、Data全量174/174，均零失败零跳过，专项不重复累加。独立BackendOnly包内Core检查器源码摘要与仓库一致，生成Service实际引用；移除仓库定位环境变量后从包内源码构建成功。未完成用途FullApplication原子拒绝，没有残留输出。

## 跟进与剩余范围

已有C#应用更新同版Core及生成器，再生成Service后构建。本批无新增DDL或回填；缺跨表辅助列的旧库仍先按跨表保存合同预览、显式同步并核验。前端、共享模板与元数据无需变化。

本批仅证明上述固定混合组合。跨表非空Excel策略仍待用户确认，其它目标图/非冗余/传播、完整原浏览器/跨端、同条件性能、完整MySQL首版及其它数据库不据此标完成。


## 最终证据

正式平台199、示例16个产物两轮逐字节一致，且与修改前相同；24个手写partial保持，前端、共享模板和平台元数据无diff。最终501份后端源码/测试摘要与完整回归时一致。11组随机表名由新连接核对Server-200实例后逐一确认不存在，共923个，含失败未建表的表名，不代表本轮新DROP923张表。用户授权的六张旧失败表另用新连接核零，本批未重复DROP或新增观测权限；旧失败、清理和修复前反例保留。

本批没有重跑专用新库初始化、原网页登录/浏览器、设备或同条件性能；不将上述生成HTTP及包构建当作这些验收。未合并main或生产部署，新提交CI另行核对。
