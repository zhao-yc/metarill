# V369 同父追加复用缓存锁读的 MySQL 对照

2026-11-06，基线 `0cbe19fd`，隔离 MySQL 8.4.11、MySqlConnector 2.6.1。两组均在可重复读事务中持有原父记录排他锁，复用相同的父候选、索引、合成数据、八行批次和每行一次驱动命令。

对照组沿用 V365 同包路径。候选组把来源排他锁与目标共享锁读到的 ID、旧副本和目标值写入会话变量，更新复用已读值，随后返回更新计数、捕获值和物理读回。进入锁读前清空变量，因为 MySQL 的 `SELECT … INTO` 在零行时保留原值。 [MySQL 8.4 SELECT INTO](https://dev.mysql.com/doc/refman/8.4/en/select-into.html)

六组输入双向核对物理字段，覆盖 NULL、空串、四字节字符和尾空格。重复主键未触及旧缓存，晚行约束撤销首行，错库和候选拒绝均未访问已锁来源，非严格模式下的截断由读回核验拒绝。拒绝路径预置会话残留值，命令结束后核对四个变量均已清空。本轮未覆盖不同字符集之间的写入，也未验证触发器修改会话变量时的预期值独立性。

四连接交替执行三对，每端每轮 24 批，合计 144 批正式计时、8 批预热。独立连接核对 1,216 行的缓存及金额。下表按候选／对照计算相对值。

| 轮次 | 对照批次／秒 | 候选批次／秒 | 吞吐比 | p95 比 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 7.38 | 6.70 | 90.7% | 121.6% |
| 2 | 7.51 | 6.02 | 80.2% | 113.0% |
| 3 | 6.71 | 6.04 | 90.0% | 113.3% |

专项三轮吞吐均下降，保留产品当前 SQL。测试资源已通过独立连接确认清理。本轮直接执行驱动命令，MySQL 首版仍以 [V366 双端正式回放](paired-child-parent-write-batch-timing-v366.md) 判定。

下一轮对照多行命令能否缩短父排他锁持有期间的往返。候选必须按原行顺序检查父候选、执行单行写入、核验物理缓存，并在首个失败后禁止执行后续行；含手写规则或写入观察者的路径仍逐行执行。
