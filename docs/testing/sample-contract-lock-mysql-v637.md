# V637 合同样板真实 MySQL 行锁复验

2026-11-08。固定 `4c2b4450`，Server-200 独占 MySQL／Redis 和 Production Full。2865 份源码、973 份完整包文件及 156 份测试执行器文件均核对摘要。严格构建通过，离线准备与租约回归 13 项通过，正式用例 1 项通过且零跳过。

| 场景 | 验收结果 |
| --- | --- |
| 阻塞方提交 | 独立事务持有合同记录，普通账号从原中央按钮用旧摘要发起请求。释放前观察到真实等待。阻塞方提交更名后，原按钮返回 HTTP 200／R500 和重新查询、预览提示。整库业务及附件引用快照只出现阻塞方的更名。 |
| 阻塞方回滚 | 另一宿主通过直接 Web 回滚动作等待同一合同。阻塞方撤回临时更名后，原摘要继续通过，实际业务走到负金额规则，首笔写入随外层事务回滚。整库业务及附件引用快照一致。 |
| 独立读回 | 两个场景分别看到本轮账号的不同请求连接处于 `LOCK WAIT`，已知阻塞连接各锁定一张表和一行。同一合同 ID 的独立 `FOR UPDATE NOWAIT` 均得到 MySQL 3572，随后再次确认等待仍在，才向测试发放释放信号。最终另开连接读回 3 个合同和 3 条有效文件引用。 |

前两轮通过 `performance_schema` 查询未取得锁证据，均终止并独立核零。只读现场确认该实例 `performance_schema=0`。最终以 `INNODB_TRX` 状态和独立 `NOWAIT` 复验，查询限定本轮库、账号和合同，不读取其他会话的 SQL 正文。三轮测试库、账号、归属记录、Redis 容器与配置、本机转发及临时凭据均已清理并独立核零。

本轮覆盖固定单库合同样板和正式 HTTP／CLI。跨库权限与文件竞态、人工浏览器审批、实际设备及性能继续按各专项验收。
