# 业务按钮的生成记录范围

2026-10-28，C18的记录读取/锁定子集。沿用原Java专用记录入口的边界：实际按钮授权独立于普通页面query权限，持久化与标准CRUD仍由元数据和生成Service管理。

## 生成及执行边界

只有当前固定目录中属于该页且 `actionType=1` 的按钮生成此入口。生成的Service提供 `ReadButtonRecord{pageId}Async`、`LockButtonRecord{pageId}Async`；二者返回实际持久化Entity，未新增Controller或HTTP路由。无业务按钮的页面不生成这组方法；整张表没有业务按钮且不需要其它授权能力时，不因此增加授权构造参数。

查询在访问数据库前完成以下约束：

- Actor须与宿主当前真实身份一致；按钮ID须属于该页固定业务按钮集合，并通过宿主实际按钮授权。
- 固定主键、Mapper逻辑删除、实际项目/父范围、非冗余逻辑父与页面常量均进入SQL，复用原固定查询编译计划，不从请求接收SQL或账号声明。
- 页面声明精确字段时，按该按钮自己的范围决策追加参数化AND；页面query/is_all或其它按钮不能取消它。空匹配集合固定不匹配任何记录。
- 锁定入口要求同一Service实际DatabaseSession已有事务，主记录使用FOR UPDATE；派生匹配来源也保持写锁至事务结束。调用者开启了另一个Session的事务不能满足此边界。

派生读取使用单条相关EXISTS查询，不在普通读取中附带写锁；派生写锁仍要求真实事务。`ExactDataManageSql.ApplyDerived` 原七参数方法和默认锁语义保留，新增显式八参数重载用于区分这两条可信服务端路径。首期派生SQL仍只支持已接线MySQL，未因此宣布其它数据库正式支持。

## 现有项目如何跟进

元数据与表结构没有变化，无需DDL或数据迁移。生成器与运行时须同批同步后重新生成；不修改标准请求/响应、页面、CSS或原交互。新的Service方法及注入由生成器维护，手写partial保留。普通CRUD继续使用原入口，不能把业务按钮作为任意页面动作权限的替代。

## 验证及尚未完成的链路

三种实际生成模型覆盖物理字段、非冗余隐藏物理字段与派生精确字段；真实ORM命令在打开连接前截获，核对Int64大ID及范围参数、主键/项目/父/逻辑删除/页面常量、空集合、越权、错Actor及缺真实事务。初次断言把参数化ID当作SQL字面量，失败记录保留，改为核对实际DbParameter而非放宽精度要求。随后完整包零警告门禁发现FreeSql任务返回可空类型不匹配，修正生成器为async可空返回并给三种生成模型启用零警告门禁；结果以最终TRX为准。
