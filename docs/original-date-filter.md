# 原日期与月份筛选边界

原 `uni-datetime-picker` 日期范围以及月份筛选的末日会发送严格 `YYYY-MM-DD` 字符串。旧 C# 查询把末日解析成当天零点再用 `<=`，导致当天白天数据被遗漏。本切片只调整共享查询的边界，不修改原控件、默认值、按钮或请求结构。

`PageDateRange` 从原始两个字符串判断终点语义：只有严格日期格式采用 `>= 起点 && < 截止日次日`；完整日期时间（包括显式 `00:00:00` 或零小数）仍采用 `>= 起点 && <= 精确终点`，不能只因解析后是午夜就扩成整天。最大合法日期没有可表示的次日，使用 `DateTime.MaxValue` 包含该整天而不溢出。开始值与结束值继续按既有 Invariant 日期时间解析，不引入时区转换规则变化。

缺边界、非字符串、无效日期、超长值和倒序范围明确拒绝；判断倒序时使用实际截止边界，因此“当天中午到同一天日期终点”合法。原空数组清筛选仍由 Query 直接处理；单值日期仍保持既有相等筛选。页数据、count 以及导出共用同一个固定 Query；SQL 使用已解析的日期值作为强类型表达式参数，不接收任意 SQL。

2026-10-20 定向 18/18 通过、零跳过：17 项纯边界测试及 1 项扩展后的实际原页面 HTTP/MySQL 测试。后者在既有随机三表 fixture 的来源表中参数化预置 2024 年闰月月初、月底午夜/中午/晚间、次月零点和 null，真实 page/count 证明日期末日整天包含、完整午夜精确、混合中午起点有效、空数组清筛选、非法/倒序/不完整数组拒绝；原实体新增/保存/删除、父/项目权限、选项和不分页回归继续在同一测试内执行。仅删除本轮随机表并反查不存在。私有 TRX 为 `.local/original-date-filter/original-date-filter-v1.trx`，不替代浏览器或首次安装验收。
