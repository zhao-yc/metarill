# 非冗余跨表级联：逻辑父范围与当前锁

## 当前范围

2026-10-23，固定 MySQL 数据层与生成后端已接通逻辑父范围。来源为普通非冗余表，目标为同项目的独立普通冗余表；沿用原主子页面父参数、固定跨表链、目标页面条件及字符串／int64 层位。

生成 CRUD、type=2 已选回读及原首列覆盖导入已用真实 HTTP／MySQL 验证。Full、正式身份宿主、文件父范围等宿主组合及原浏览器仍需继续，不能将整个复杂关系模块或 MySQL 首版标为完成。

## 为什么不能比较物理祖先列

选择城市后，来源只在 `place_id` 存城市 ID，物理 `country_id`、`area_id` 为空。主子页面的国家父范围必须沿当前城市、地区、国家链定位，不能用物理 `country_id=parentId` 判断，也不能将请求祖先 ID 当作已存外键传给守卫。

列表对失效关系保留所选 ID，方便原页面回显。写范围另外要求完整已选路径存在、未删除、属于当前项目并满足目标固定条件；直接选中的失效根／末层也不能只凭原始 ID 放行。

## 固定生成流程

- 父目标从唯一固定读取链推导，不再由隐式列名猜表，也不递归调用尚在证明的写计划。普通物理父外键继续原流程。
- 每页只编译 `id` 与实际逻辑父层位。更新、复制、删除和导入匹配显式使用当前锁，相关 `EXISTS` 绑定同一来源主键、真实项目、稀疏有效性和目标路径；双父范围取交集。
- 项目、父 ID、目标条件常量全部参数绑定。使用固定短前缀隔离多父参数，避免长辅助字段名叠加超出标识符长度限制。
- 创建前不单独先锁逻辑祖先；请求与父上下文合并后，由完整路径归一化按末层向根锁定并检查父归属。普通父校验保留，空导入批次在末尾验证真实父，避免绕过与反序锁。
- 更新省略整项关系时保持实体原始稀疏值。真正提交关联后，先归一化检查逻辑归属，再编码为单个所选层位；未提交的祖先不因页面父范围被虚构为存储值。
- 逻辑祖先不进入物理守卫提示／快照。正常 DML 后统一复读当前逻辑范围与实际稀疏位；删除则在最后写守卫之后、删除之前复核。未标提交字段的钩子改位、守卫换父、数据库改位都必须整体回滚。
- 观察器收到真实物理稀疏值。原 DTO／VO、字符串 ID、省略与 null、页面、组件、样式、交互和模板不变，ORM 不在启动时同步业务结构。

## 原导入及 type=2

父范围内的覆盖匹配使用同一当前逻辑计划，不能用物理空位误判为没有原记录并新增。只有本页原可写表头开放；父字段本来不在表头，末层本身作为父范围时也不重新开放该列。

空单元格的新建按原父上下文保存根／中／末层；省略关系的覆盖更新保留原值。测试撤销来源普通写动作与全部目标 list，导入仍仅用 import 权限、真实身份与固定数据范围执行。非空路径继续按 B14 门禁拒绝，批次中后行失败必须回滚前行。

type=2 已选回读沿同一固定链验证真实父记录，在原读快照内执行，不申请写锁。所选来源必须全部命中本页逻辑父范围，不能静默丢弃越权项。
