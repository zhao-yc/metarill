# 配置字段候选的固定源父归属

本切片仅支持两条已发布 List 关系的一跳归属，不提供任意路径表达式或客户端 SQL。声明保存在现有 `controlDetail.sourceParentOwnerColumnId`，不会增加物理列。

| 来源列 | 真实来源父 | 固定归属字段 ID | 目标 |
| --- | --- | --- | --- |
| `2076977805534564352`（索引字段的 config_column_id） | config_index | `2076977821456142336`（config_table_id） | config_column 页 `6217715532627968` |
| `1676901024774926338`（页面字段的 config_column_id） | config_page | `1671100304320462849`（config_table_id） | 同上 |

来源父 FK、归属 FK、目标父 FK 和关联目标都必须有准确稳定引用；每条边必须属于预期表且为物理单值整数。页级配置不能改写字段的固定归属声明。未知、错边、联接边、其他类型或不唯一父范围继续进入能力 Gap，候选调用明确失败，不递归按字段名猜测。

原详情已有 `parentId` 请求承载来源父：索引字段传真实索引 ID，页面字段传真实配置页面 ID。服务器验证来源父未删且属于真实 Actor 项目，读取固定 config_table_id，再验证真实配置表同项目且未删。`targetParentId` 省略时从此推导；显式提供时仅核验与推导值相同，不能用于选择另一张表。`formParameters` 按原协议继续传递，服务器不读取其中的归属值。

目标SQL还用固定强类型相关 EXISTS 再核对源父仍指向该目标父，以及归属表仍同项目未删，防止初读归属与目标查询之间换表时返回旧范围数据。原数组、`/page`、`/selected`、只读 `id` 回读及关系名称读取共用同一固定范围，保留原数量限制、完整已选匹配和字符串 ID。服务端在读取前检查真实当前身份以及来源/目标页面 list 权限。导出则保留来源 export 与目标 list 的独立权限，不额外要求来源 list；最终目标范围与身份仍由相同解析器复核。索引候选恢复原 sort_no asc，并追加 id 作为稳定顺序；只允许物理列，保留工作台排除虚拟、联接和布局控件的规则。页面字段候选不套此限制，仍可配置原派生/联接字段。

页面字段保存阶段在 BeforeSave 后、名称派生读取前验证目标页面权限，原 ValidateRelations 阶段继续负责既有检查和名称派生，其后再核验最终关联 ID、来源父及归属表一致，然后才写数据库。省略关联且父未变时不重读历史值；显式清空保留原 null 语义。标准删除也在逻辑删除前执行最终范围与权限核验。索引字段普通新增/修改/删除继续全部禁用，完整索引保存仍走 IndexWorkbench 聚合及原项目→表→列→索引→索引字段锁序。

候选和已选读取不取写锁。平台写入口先由 ConfigurationMutationGuard 获取项目锁，再锁来源行；最终关系校验在同一 DatabaseSession/事务中对源父、归属表和目标列作当前读，不能用早先快照或别的连接。只读相关 EXISTS 不混入写校验路径：写入以已锁当前源父/归属派生值约束当前目标行，避免外层旧一致性快照造成无故拒绝。该项目锁是平台配置写入串行化前提，不能将此设计当作任意手写 Business 省略准备守卫的许可。双连接竞争及事务回滚由主线独占数据库阶段验证，本切片不宣称已完成真实并发验收。

原 zxz 组件、DOM、props 和事件不变。ServerDerivedTargetParent 仅让生成方法继续发送既有来源 parentId，不读取客户端祖先 ID，不增加页面操作。原整页只读规则仍不自动加载编辑候选，只展示详情；只读 id 回读另由生成方法的离线测试覆盖。父或项目变化继续按原上下文/nonce丢弃迟到结果，保留实体已选 ID。

这两个控件都是 List。原 SelectPage/type=2 的 parent_id 仍代表目标父，其通用 page/selection 请求没有来源绑定上下文；本切片没有将它们宣称支持此一跳推导，也没有滥用 parent_page_sn。后续若接入，必须设计固定来源入口并独立验收。

首次安装源已补齐引用及声明。既有库不会被升级自动覆盖，应通过原配置入口按上述稳定字段核对并修正声明和链接，再预览、生成，保护手写 partial。没有表结构变化，无需 DDL 或回填。物化名称派生切片与本切片分别维护，集成时须保留权限→派生→最终关系校验顺序。
