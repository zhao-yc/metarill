## 原因与源头修改

第一轮真实小程序编译失败；CLI返回码仍为0，不能只检查退出码。仅编译日志明确指出登录页动态`<component>`不受支持；修正后又定位到首页同类用法。

- 平台手写登录页和独立应用登录模板：H5继续使用原生DOM表单、密码管理器标识及POST/回车；非H5使用uni-app form/input/button，调用同一个登录方法。输入事件兼容H5的target.value与uni-app的detail.value，空字符串优先保留，不取旧target值。
- 平台首页及独立应用首页模板：H5保留动态加载和keep-alive；非H5静态登记原组件。平台只在首次访问配置页后挂载，以v-show保存已访问页面实例；未知菜单不改变当前页。原显隐和具名解绑继续执行。
- 平台与模板共四源的H5 template/style逐字对照旧5d8aa40均相同。登录H5仍通过既有模板摘要`b214cdf33062`及样式摘要`a96c9c4c87d9`，没有刷新旧基线。

只维护这四个手写/模板源头及配套测试，不在生成页面补丁。旧包不会被自动修改，已有应用需经原受控运行时更新流程引入新的壳模板，再分别构建和验收。

## 实际命令与证据

三个副本先按锁文件执行npm ci，两个生成应用的副本只设置用户已提供的uni-app AppID，微信AppID保持原空配置。使用：

```powershell
D:\HBuilderX\cli.exe project open --path <副本工程绝对路径>
D:\HBuilderX\cli.exe publish mp-weixin --project <副本工程绝对路径> --upload false
D:\HBuilderX\cli.exe publish web --project <副本工程绝对路径> --webTitle Metarill --webHosting false
D:\HBuilderX\cli.exe project close --path <副本工程绝对路径>
```

诊断时，UI编译会提示配置微信开发者工具；取消设置后使用官方仅编译参数`launch mp-weixin --ui false --compile true`取得具体错误，不改用户工具设置。最终成功使用上述publish命令，明确不上传微信或Web托管。

证据留在忽略目录`.local/weixin-compat`：原失败日志、开发中标签闭合与旧内嵌模板的失败包、原壳全模板比较夹具失败、最终重新严格构建的CLI、两个新Full包、六份成功编译日志、产物核对和TRX分别保留。临时七个HBuilderX工程已关闭，未停止用户原HBuilderX或其他项目。
