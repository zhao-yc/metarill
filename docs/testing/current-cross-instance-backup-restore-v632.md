# V632 跨 MySQL 实例的平台分库与本地附件恢复

2026-11-08。固定产品 `5c8fcb823491e2e25029ffa40cb2cfdc851c0abb`，复用 [V630](current-split-backup-restore-v630.md) 的 51 份 Windows Production 宿主及合成元数据。Server-200 上启动两个相互独立的 MySQL 8.4.11 容器。两个实例的主机名、服务器 UUID、应用账号及平台／业务库名均不同，各用自己的 Redis 及回环转发。MySQL 镜像摘要相同，容器存储为本轮专属 tmpfs。

| 阶段 | 实测结果 |
| --- | --- |
| 源端安装与停写 | 正常执行平台显式初始化。真实普通账号上传并绑定公开和受保护附件，退出后确认源宿主停止监听。 |
| 跨实例导入 | 逐次核对两个容器归属及实例指纹，源库级账号分别导出平台 24 表和业务 13 表，目标库级账号导入各自空库。比对真实表、列、索引、约束、键列及 CHECK 六类目录，数据语句逐字一致。复导出的冗余字符集词组按 V630 合同核验，源再次导出的原始字节相同。 |
| 恢复目标运行 | 目标通过正常启动命令读取恢复后的账号、业务记录和文件引用。源附件路径移开时，目标独立返回公开附件 32 字节、受保护附件 35 字节，SHA-256 与备份一致。22 个原 HTTP 请求验证普通只读、匿名公开下载、无授权拒绝、旧注销会话拒绝及禁止只读写入。 |
| 独立读回及回收 | 目标业务库中客户、文件和引用逐值匹配，三条 Web 会话均为已注销。重新核验两个 MySQL 和 Redis 容器、私有目录及监听、转发、合成文件和本机配置均已清理。 |

本轮覆盖两个同版本 MySQL 实例间的分库和本地文件恢复。两个实例位于同一台 Server-200。跨版本、跨物理主机、联合 S3 恢复及活动会话快照分别验收。
