# 平台物理派生缓存写入

本切片接通原平台三个冗余物理缓存，不增加读SQL联接，不清除isJoinColumn，不修改物理结构，也不自动修复全库历史数据。

| 来源 | 目标 | 缓存 |
|---|---|---|
| config_page.config_table_id | config_table.table_name | config_table_table_name |
| config_page_column.config_column_id | config_column.column_name / sort_no | config_column_column_name / config_column_sort_no |

## 请求与原界面

所有isJoinColumn从服务器Writable、严格DTO、导入和Agent请求schema移除。原HTTP整entity只剥离本页已知可读回显，未知键、伪项目、跨父请求继续拒绝。原冗余详情仍按页级isReadOnly生成原输入、校验、props/events；非冗余派生字段保持原只读分支。前端不是写保护的授权边界。

生成器仅为上表固定物理字段、完整columnFullName、显式外键目标、冗余存储和匹配物理类型建立写绑定。未知派生列没有查询目标全实体的回退：创建/复制非空缓存，或更新时将其加入submitted，均明确拒绝；创建/复制真正null的无效果值不阻断其他合法字段。

## 保存与事务

继续使用现有异步ValidateRelations，不新增Core生命周期。标准create/update/copy及复用标准方法的import中，创建或实际提交FK时：

1. 现有配置守卫校验真实管理员/页面权限，最先锁真实项目；更新再锁真实源记录。
2. 保留目标同项目、活动记录COUNT预检。
3. 同一predicate执行窄SELECT FOR UPDATE当前读，只读取id及固定源值；页面字段双缓存共享一次读取，并再次核对目标身份。
4. 填内存Entity及submitted，Mapper写入，原观察器执行，原VO从该Entity产生回执。

显式null清空对应缓存，再由既有必填、父/表归属规则决定是否允许；省略FK不会清空或历史回填。没有保存后Scope重读，所以合法修改后离开旧可变筛选范围不会额外阻断回执。源记录、派生引用和文件观察器继续同一个DatabaseSession事务，任何后续失败一起回滚。

目标表名或字段名/排序实际提交时，仅同步该目标的活动引用。先只读发现异常项目、引用归属，再按引用ID锁定自身记录并重验；拒绝异常引用，不跨项目修补。普通字段保存仍保留原同表/索引校验。排序工作台直接更新已接同一传播入口；新建页面字段用已验证目标值填充；CopyPage用已锁目标覆盖复制的旧缓存。软删除流程不变，删除记录不被恢复。

同项目正规写入口由项目锁串行；没有承诺任意手写Business反向加锁无死锁。

## 查询成本

以下是源代码可计算的额外往返，尚不是性能实测：

- FK触发重算：原COUNT之外增加1次窄当前读；config_page_column两缓存共1次。FK省略或null不新增此目标读。
- config_page_column观察器归属校验新增5次当前读：项目、源记录、页面、字段、所属表。页面字段只有创建/提交FK时才核缓存。
- 字段引用校验由原批量锁改为先发现、再逐ID锁定重验。设活动页面字段引用F、索引引用I，相对原实现额外增加2F+2I次读取；字段名/排序传播最多F次单行写入，无变化跳过。
- 表名传播复用原页面发现查询，每个活动页面引用额外1次锁定读取及最多1次写入。
- 排序旁路每个受测列额外执行项目和源当前读、完整固定引用校验及最多F次缓存写入；不把它描述为零成本。
- 自动补字段、复制只使用其已读取/锁定目标对象填值，不因此额外查询目标。

真实MySQL阶段须记录实际SQL与往返，并在同数据、SQL、索引、并发和资源下比较p50/p95、吞吐及失败数。MySQL行锁、隔离、真实尾部失败回滚和并发尚待独占排期，不以离线代理通过替代。

## 验证与跟进

离线回归执行真实生成代码编译、DTO/Legacy/Agent schema、Service创建/更新/复制/导入和VO回执；显式离线ORM代理仅记录执行顺序。Runtime测试执行真实SqlRowStore、观察器、排序和CopyPage，使用仅测试内的内存参数化命令适配器，覆盖null、历史保留、异常引用先拒、自动补字段和尾部失败回滚。它们不证明真实数据库行为。

已有项目更新生成器后预览并再生成，保护手写partial；运行时同步配置观察器。无需DDL；本次不提供自动全库回填，历史修复需独立差异预览和明确执行范围。
