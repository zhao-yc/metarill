# double 逻辑类型基础链路

本项补齐原本已在元数据词表和 C# 实体生成器中存在的显式 `double`，保留原控件、样式与交互。只做已有默认值和 C# 接口的数据适配，不新增界面选项。当前为本地验证子集，尚未执行真实 MySQL double 的 DDL、CRUD、浏览器或性能验收。

## 语义与源头

`double` 使用有限 binary64 近似浮点数；金额等精确小数继续使用 `decimal`，不能据此自动迁移既有字段。MySQL 的 DOUBLE 同样采用近似数语义，详见 [MySQL 官方浮点类型说明](https://dev.mysql.com/doc/refman/8.0/en/floating-point-types.html)。

- `MySqlSchemaPlanner` 将显式逻辑 double 编译为裸 `double`，默认值先验证、按往返格式生成；零与负零的默认值统一为 `0`。快照比较和指纹按同样规则规范化，避免数据库指数和尾零造成假漂移。
- 结构反查草案保留裸 double 的逻辑类型；`float`、`double(M,D)`、unsigned 及其他未能无损表达的特征继续明确拒绝。不能借本项宣布所有物理类型可反查。
- `FiniteDoubleJsonConverter` 在平台和独立宿主共用的 JSON 设置内接入，并在包含 double 的生成 Service 查询选项中接入。数值文本有界；拒绝 NaN、无穷大、溢出及非零下溢为零，支持原有允许的数字字符串，不缩窄到 decimal 范围。可省略字段与显式 null、字符串长 ID 协议继续保留。
- `SqlRowStore` 将 double 标量规范为实际 double 参数；生成 Service 对手写钩子最终产生的非有限值再次拒绝。校验走原事务边界，异常不进入写入。
- 生成默认值与原详情数值默认绑定使用同样的有限数值规则，保留原表单和校验提示结构。现有物理 double/float 到逻辑 decimal 的自动推导规则未改；本项只支持显式逻辑 double。
- 更新器要求所有当前完整候选包带齐转换器及精确数值解析源码：公共 JsonDefaults 始终引用它们，不能因业务模型没有 double 就裁剪；同时删除源码与归属清单也不能绕过检查。旧目标包仍可正常预览成套运行时升级。

## 接入与回退

源头为 Core／Data／Generation，生成项目要成套同步运行时并正规再生成 DTO／Service；手写 partial 不覆盖。无 double 的既有模型无需为本项执行 DDL，生成内容应保持稳定。已有业务库的类型变更仍需原结构预览、审核、执行和核验流程，禁止 ORM 启动自动改表。本项不保存或回填 live 元数据，不修改冻结验收包，不使用任何已结束租约。

回退需成套回退生成器和运行时；若后续已采用 double 元数据，应先保留数据并评估兼容，不自动把它转为 decimal。复杂派生、全局来源及各关系组合的 double 运算、驱动范围边界和数据库间映射不在本地证明范围。
