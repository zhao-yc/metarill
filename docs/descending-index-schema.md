## 已接通的链路

- 逻辑快照IndexSchema保留原三参数构造，新增可省略的Directions位置数组；省略等于全ASC，JSON不输出null扩展属性，全ASC归一后的指纹与旧模型一致。
- 元数据按sortNo排序后，将方向与每个实际索引字段绑定；只接受ASC／DESC，未知方向或位置数量不匹配明确拒绝。禁用索引不参与结构编译，原普通和唯一索引规则保持。
- MySQL创建表／增索引计划对同一字段仅在DESC时输出后缀，原ASC SQL逐字保持。已有同名索引的唯一性、字段次序或方向不同仍拒绝，要求单独制定迁移；不自动DROP／重建，也不借禁用配置删除物理索引。
- 真实STATISTICS反查读取每一项COLLATION，A映射ASC、D映射DESC，未知非空方向拒绝。指纹纳入方向，即使SHOW CREATE文本相同也会阻断预览后的方向漂移。
- 反向草案保留每一列方向；修复SchemaMetadataImportBusiness原本写死ASC的问题，将服务端已验证草案的sortDirection存入原配置。原同事务回读／两向物理核验仍保留，不能用拟插入字典代替最后数据库结果。
- 预览及实际执行重新建连后均检查握手版本。含DESC时保守要求MySQL 8.0.11及以上正式版，未知／旧版及MariaDB拒绝；普通ASC不新增此限制。目标表已有InnoDB检查保持，新表DDL明确InnoDB。官方说明MySQL 8才实际存储DESC，且该能力限于InnoDB，见[MySQL官方降序索引说明](https://dev.mysql.com/doc/refman/8.0/en/descending-indexes.html)。不因为驱动连接成功就宣布其它数据库／版本通过。

降序主键、前缀、函数／表达式、隐藏、非BTREE索引、外键及CHECK等未表达特征仍独立报告缺口，没有借DESC放行。DESC不等于重复索引自动清理，也不代表特定查询会采用该索引或已经获得性能提升。
