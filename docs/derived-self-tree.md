# 固定派生名称自树

## 本次范围

B51在原selfTree合同上增加独立普通R0目标：来源只存叶子ID，目标节点的名称可来自已证明的固定单值字符串联接。候选、完整路径、列表回显、后代筛选／统计、最终写校验和Excel逐层反查共用固定读取计划；前端、模板、按钮及请求响应保持原样。

- 来源与派生目标均为R0，独立目标具有唯一可读页面。父结构、项目身份和页面条件必须是物理标量；仅名称本身允许派生排序，其它未证明派生排序仍拒绝。
- 固定名称路径使用匹配编译证明，拒绝凭据、数组、多值路径、非int64中间关联键及未支持拓扑；不能借名称联接开放任意表达式、条件或SQL。
- 字符串／int64来源ID与字符串／int64父键分别交叉；原null根、空字符串根、原500同层／64层限制、断链和循环检查继续保留。
- 新CurrentRowsAsync仅在真实业务事务内运行，直接读取有界投影而不执行COUNT，使用FOR SHARE锁住节点及联接终点。旧RowsAsync签名保持，查询与导出不因此额外获得写权限。
- 来源页内部回显、筛选及原导入权限不额外要求候选查询授权；公开候选与直接编辑仍分别检查来源及目标的原权限。

同时覆盖独立R0物理名称目标的生成分支。R1物理缓存、同表派生树、全局目标及其它未证明范围不因本次变更自动开放。名称实时计算，无需把改名传播到R0来源，也不新增名称缓存列；B21／B22的其它传播及维护范围继续。

## 跟进方式

既有项目无数据库迁移／回填：物理结构仍由相同R0元数据决定，不新增名称列。保持元数据归属，更新生成器与配套运行时后，经原在线助手预览、生成页面／后端及运行时同步，保留手写partial；以新的完整包或同批Data运行时构建部署。不能只更新生成Service而保留缺少CurrentRowsAsync的旧Data程序集。

已有物理名称树沿原分支；需要采用派生名称时，先在项目元数据声明固定单值路径及目标页面，再预览结构与生成能力报告。未证明配置保持明确拒绝，不手补生成文件或直接改表。整个B18／B23及MySQL首版仍未完成，原浏览器、正式宿主混合矩阵、跨端与性能继续验收。
