# 原 List 分页的表单联动上下文修复

日期：2026-10-30。C56 起点：`688c25440c2de6847ca44f292e1c53148da4d4fc`；代码与进度表同提交。

C55 完成原平台标准 List 接线后继续核对旧请求，发现 C54 的分页状态机只带父键和已选 ID，遗漏了后端已支持的 `formParameters`。普通 List 不受影响，条件中存在表单变量的 List 会缺少固定标量上下文。共享运行时实际 Vue 反例先复现两项失败，本轮修复此缺口，不改变页面、样式或原联动规则。

## 修复范围

- 生成器从已经验证的 `RelationConditionsCompilation.Forms` 发布 `formFields`，只包含本页已开放、非凭据物理字段的字段名与原表名槽。没有表单依赖时维持原九项描述及输出字节。
- 详情和筛选均从原 `formParametersName` 缓存提取这些字段；保留平铺及原表名驼峰嵌套两种槽，后端仍按原声明路径及 fallback 优先级读取。缺失不补成 null，明确 null 不回退成其它值。
- 只发依赖叶值，不发送整个缓存、其它字段或身份/SQL配置。错误容器用空对象或 null 保持后端拒绝，避免把无关内容送出。表名与字段同名、特殊对象键也经过回归。
- 同一个窄快照进入 `/page` 和 `/selected`，并参与请求失效判断。原 `isAutoPostBack` / `initDynamicLists` 继续触发重读；条件改变后分页从首屏重新开始，旧响应不能填回名称。运行时不清空实体或筛选的原关联值，最终合法性仍由服务端验证。
- 原平台同步器只接受生成器新增的明确字段/表槽数组；空值、重复项、额外路径或属性整体拒绝。无依赖的页面不发送 formParameters，不因无关缓存变化使候选失效。

未改后端请求合同、SQL条件、写入验证或授权流程。客户端表单上下文不是身份和父记录授权；真实 Actor、来源页/目标页权限以及项目/父范围仍由原固定入口检查。

## 跟进与回退

已有带表单条件的生成项目，需要使用本版生成器重新生成页面，并配套同步两个共享运行时 `originalRemoteOptionsMixin.js`、`remoteRelationOptions.js`；只有新运行时或只有新描述均不构成完整接通。生成之外的手写扩展按原保护边界保留。平台现有十二页不含本轮表单依赖，已经再生成确认稳定。

若回退本修复，应配套回退描述与两个运行时。回退会重新缺少表单条件上下文，不能通过省略后端条件、伪造身份或放宽候选范围使请求成功。带联动条件的真实 MySQL/普通身份/原浏览器完整场景继续单列，不标为 V02 整体完成。
