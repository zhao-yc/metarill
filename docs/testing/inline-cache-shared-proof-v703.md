# V703 复用部署证明的同父单次缓存写入

2026-11-09。原 Java 的固定八行导入在 INSERT 内绑定缓存名称，C# 默认在 INSERT 后同事务补写。此前 C# 单次写入路径需要直接读取触发器元数据。此次让该路径复用已配置、已在当前事务校验的共享锁证明。证明绑定原业务事务、源表和父表。仅在本次证明成功时复用触发器结论，仍独立验证列、字符集、索引、约束、原父候选及写后读回。运行账号无需新增权限。 [V322 双端实际 SQL](paired-child-excel-sql-v322.md) · [MySQL 触发器元数据](https://dev.mysql.com/doc/refman/8.4/en/information-schema-triggers-table.html)

两轮严格编译的生成导入宿主使用同一数据层程序集。在 Server-200 的独占 MySQL 8.4.11 上分别完成 7／11 次真实接口请求，各轮独立读回 48／80 条合成明细。探针使用原生成 Controller 和 Service，身份由合成测试入口提供。四并发补测实际同时提交四个八行请求，均沿用共享父锁和后七行单次写入，32 行逐值核对。

| 状态 | 每八行缓存 UPDATE | 父锁 |
| --- | ---: | --- |
| 例程缺失或撤销运行账号的例程执行权 | 8 | 排他 |
| 有效例程且物理布局符合 | 1 | 共享 |
| 有效例程但明细新增 CHECK | 8 | 共享 |
| 有实际 INSERT 或 UPDATE 触发器 | 8 | 排他 |

有触发器时独立核对实际金额变化。移除触发器后恢复单次写入。第 6 行超长仍报告原行号，前序明细整批回滚。运行账号没有库级或明细表级 TRIGGER。锁定定义者、例程、临时库、运行账号和归属记录都已独立核零。并发夹具首编因局部变量重名失败，修正夹具后严格编译通过，产品代码相同。Data 套件 1,602 通过，32 项条件跳过。

已有配置更新宿主运行时即可复用现有证明。没有配置的部署继续走原默认路径。本轮完成已配置路径的功能与四并发写入核对，默认配置的 Java／C# 正式性能仍由 V694／V702 继续追踪。见 [现有部署方式](../mysql-shared-append.md)。
