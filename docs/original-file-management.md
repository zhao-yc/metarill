# 原文件库浏览与管理

本批仅适配C#文件基础设施及完整包更新链路，未修改原uni-app页面、样式、控件和前端生成模板，也未修改元数据、物理表或原YZP参考仓库。

## 原行为与接口

依据原V8的FileLibraryControllerSys、FileLibraryQueryBusiness、FileLibraryFolderBusiness和FileLibraryBusiness核对。文件夹属于项目共享展示元数据，创建者不是独立权限边界；同一项目成员可以整理完整父子树。目录名修剪后非空、最多100字符，同级名称按数据库排序规则判重，移动拒绝自身/子树及跨项目，只有空目录可删除。上传到共享目录仍要求真实上传者完成自己的文件，不允许超级读取身份接管他人上传。

原目录JSON使用parentId、id及fileCount，文件列表/完成对象补回id并保留解析对象fileId；HTTP长ID由既有序列化器输出为字符串。文件夹列表允许无请求体，返回完整项目树，由原组件按parentId组装。重命名文件/目录和移动目录返回更新后的安全描述，文件移动、文件及空目录删除成功返回原字符串。

文件列表要求当前项目已发布的物理FileLibrary字段，并按其PUBLIC/PROTECTED模式筛选，再核验真实读取权。ready保护文件上传者无可读引用也不能仅凭所有权出现在列表中；他人上传但确实可读的文件可以显示和整理。有字段的目录数量复用同一可见文件规则；无字段的原目录列表按项目非删除文件统计，不由数量反向授予内容访问权。

没有关键词时按目录筛选，空目录ID表示根。有关键词时跨目录搜索，按空白分词，每个词的Unicode字符按顺序构造LIKE，词之间AND，全部值参数化；沿原数据库LIKE通配含义，不改为简单Contains。

文件重命名及移动按真实读取权，显示名最多255字符，可改变显示扩展名；存储对象键、已验证MIME、内容摘要与历史引用保持。流响应使用已保存的MIME，不能因显示扩展名重新解释内容。物理删除仍要求上传者、平台管理员或当前后台真实super，并且没有有效业务引用；读取权不授予删除权。

## 错误、事务和已有工程

继续沿平台和完整包各自的既有HTTP/R错误映射。完整包中重名、目录循环、目录非空和文件仍被引用等业务状态拒绝仍为500通用错误，不新增宽泛异常透传。正式验收同时检查拒绝后目录/文件/引用没有被改写。

文件删除由文件库入口开启独立事务，数据库记录失效并提交后才删除物理对象。手写业务在原事务内解除业务引用，提交后再调用文件库删除。物理对象清理失败时原前端必须收到R错误，不能显示删除成功；这不构成文件系统与数据库的原子提交，也没有自动清理重试或云存储补偿保证。

同一上传计划已保存对象但数据库结果未知时，本地与 S3 均按实际大小和 SHA-256 核对原对象。相同内容可恢复上传状态，更换内容需重新申请上传计划。原单步公开导入仍在自身事务中完成。

既有Service构造和方法签名保留，新返回对象由附加包装方法在同一实际事务取得。原FileFolder的CLR ParentFolderId保留，只调整JSON名称。新FileLibraryService.Browsing.cs是固定共享运行时，须通过sync-runtime一并下发并重新构建；不改页面、不执行结构SQL或启动自动DDL。更新前审阅预览，手写partial和宿主自有配置继续保护。旧包若已依据此前错误的parentFolderId做了自定义接入，应核对其自定义序列化约定。

## 验收范围

真实MySQL服务层、正式独立完整包Web/HTTP、离线JSON与更新器合同分别记录于总验收。Windows实际占用物理对象验证删除报错，不能代替Linux相同文件占用语义。目录修改复用项目目录范围锁；不宣称全部隔离级别下无死锁、目录唯一性的性能基线或并发撤权全程线性一致。

本批没有浏览器点击/布局或真机证据，不关闭完整云存储、复杂记录范围/精确数据管理、同条件性能、多数据库、完整安全管理/初始化及其他原目标门槛。原先失败报告保持失败，后续通过不改写历史。

## V1069 当前候选原 Web 文件改名、移动与删除

2026-11-11。固定 abbe89fb 的独立 Full Production 宿主及原桌面 H5。使用 49 份宿主、53 份 Web 文件，实际浏览器为 1280×840。独占 MySQL、Redis、SeaweedFS 和浏览器来源通过实例及资源归属检查。普通编辑与普通查询各自从原菜单进入示例客户。两个身份从原业务引用分别下载同一受保护 ZIP，字节一致。

| 场景 | 实测结果 |
| --- | --- |
| 原文件库改名与移动 | 普通编辑将已引用公开 PNG 改名为 .dat，再用原目录树移到新目录。MySQL 三次独立读回确认文件 ID、项目、拥有者、对象键及原业务引用。改名和移动仅改变展示名称及目录。 |
| 内容保持 | 原业务引用预览仍显示同一张图片。独立 HTTP 读回的内容类型为 image/png，字节摘要与原 PNG 一致。独立签名 S3 读回同时核对公开图和对照 ZIP。 |
| 有引用拒绝 | 原文件库删除确认发出一次请求，返回 HTTP 200／R500，并显示文件仍被业务记录引用。数据库和对象均保留。 |
| 解除引用后删除 | 在原详情移除公开图片并保存，实际文件字段写入空数组。原文件库再次删除成功，重开目录已看不到文件。独立 MySQL 核对软删除及引用墓碑，独立 S3 清单只剩对照 ZIP，原公开地址已拒绝访问。 |
| 回收 | 受保护 ZIP 的记录、引用和对象字节保持。三个普通 Web 会话已注销。合成库、临时账号、Redis、S3 桶与容器、代理和浏览器任务空间均独立核清。 |

首轮已验证改名、移动和引用拒绝，浏览器脚本未关闭原拒绝提示，停在解绑前。两条引用均仍有效。第二轮通过解绑和删除，脚本误以为重开文件库会自动回到根目录，停在重开检查。两轮资源独立核清。最终轮按原面包屑操作复验。 最终轮完成全部业务断言和独立 S3 清单核对。执行器清理阶段因变量覆盖提前退出，随后按同轮租约回收并以独立连接核零。正式结论来自原始操作、MySQL、HTTP、S3 与回收证据的再次核对。

本轮覆盖独立应用原桌面公开文件的管理操作，以及受保护附件的读取与引用保留。平台分库和共库的附件路径另见原 Web 专项。
