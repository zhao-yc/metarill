# 原角色后台名称计算投影

原角色列表和只读详情读取 `yzAdminTypeName`。旧 Java 在保存时补齐冗余物理名称；固定投影接入前，Metarill仅保留 `yz_admin_type_id` 与原 List 声明，缺少物理名称列及行补名，导致原页面空白。当前固定计算投影已补齐列表、详情、生成写回执、type=2选择确认与实际启用时的后台名单选导出；候选返回名称与行回执仍是分别验证的用途。

本片只证明固定角色表 `1692532858499969026`、原页 `1692532858529329154`、后台字段 `1692533179766878209` 与真实后台表 `1696799308939239425` 的声明。来源必须是明确的非联接 `int64` 物理 List 字段；目标ID、名称、项目和软删除列须同时完整。既有 `table/tableId/nameField` 就是源声明，仅允许空 `whereSql/orderBy`；重复键、未知键、任意SQL、页覆盖冲突及物理名称重名继续保留能力缺口，不从客户端推导查询。

`yzAdminTypeName` 是只读计算别名，不增加物理冗余字段、不回填数据。统一页VO供列表、详情、新增、更新、以后显式开启的复制回执及type=2完整所选行回执使用。列表与详情分别按照自己的原可见字段决定是否补名；共用VO在未使用的用途中名称为null。完全隐藏后台字段时不生成别名、查询、DTO字段或Legacy回显白名单。原 DOM、样式、选择器、事件、POST和formParameters槽保持原结构，只将已证明显示绑定接回原名称。

名称查询复查真实来源身份和当前来源动作，沿用原页面授权，不额外要求后台目标页query。只取当前actor项目未软删除后台的ID/name。每页先去重，最多5000个唯一后台ID，超限整体拒绝，不截断；每200个ID串行查询，不逐行补名、不在同事务并发SQL。正常列表增加`ceil(唯一后台ID数/200)`次读取；详情和单条写回执增加最多1次，空ID不查询。缺失、软删除或外项目目标保持原ID且名称为null。

原整entity回传中的精确 `yzAdminTypeName` 只作为已知只读echo剥离，不写入DTO、实体或数据库；近似名称和内部DTO夹带该字段仍拒绝。此名称投影不能代替安全写协调器对合并后角色后台、引用及撤权的校验。

生成的`AddGeneratedServices`会为角色Service注入现有`IRuntimeAuthorization`。仍手动构造Service的宿主必须传递真实授权依赖；漏传时名称投影明确拒绝。写回执与Mapper写入仍位于同一`DatabaseSession.InTransactionAsync`内，投影失败必须回滚整个操作，不能先提交再补名。离线回归同时验证真实生成DI解析及旧手动构造缺依赖后的rollback调用；这不替代MySQL实际事务证明。

当前未实现通用关系名称计划或传播。type=2确认先以准确来源list权限读取完整同范围所选行，再批量补齐本页可读固定后台名称；不借候选的其他动作权限，不改变原选择事件。原v8单 `_id` 关系导出辅助名称，当前固定后台单选导出同样输出string/null，并以准确来源export动作和当前真实actor查询；不再沿普通候选额外要求目标后台页query，也不将缺失名称回退为ID。固定证明成功的这两项用途不再保留旧`usage=selection/export`缺口。

原角色页导出、复制开关均为0，未更改；测试仅在私有元数据副本打开导出。账号的冗余角色复选列仍按原v8导出ID数组JSON文本，不能把此后台名称修复称为角色名称导出。未知声明、隐藏字段及冲突仍受原证明限制，独立Host Runtime A与平台五处Custom组件的独立前端依赖门禁均保持，Full发布不能由该读合同单独放行。

最初固定名称切片采用真实生成C#程序集、实际FreeSql SQL翻译、明确的内存行替身及原详情真实Vue挂载，覆盖整页批次/预算、源动作、空值/删除/外项目、精确echo与隐藏。后续 `5612451` 完成固定选择/导出用途，相关离线136/136、零跳过；新增实际生成Service/DI、执行前SQL/参数捕获、权限阴性、内存范围和真实XLSX单元格回读，详见[固定用途合同](architecture/fixed-role-read-uses.md)。

内存谓词、SQL翻译和本机XLSX不算真实MySQL、RR并发或浏览器验收。主协调者对本片的正规再生成、MySQL及原页面复验仍待后续实际批次另计；不手改旧产物，不把平台现有Runtime/RR证据当作独立Host下发完成。
