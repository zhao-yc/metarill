# 规则逻辑值与实体物理存储分离（C25，2026-10-29）

起点 `aba4d5e92d1a524886982b2b84e41d00b7b09103`。C24 的普通标量派生规则已有离线闭环，但共享跨表组合还缺实际验证。本轮发现：同一个 country_id 既是稀疏物理存储位，又能在页面读取中由已选末端解析为逻辑祖先。把普通页面读取计划直接用于实体填充，会把物理空位补成逻辑ID；反过来，只读规则若直接取物理空位，又会与页面显示的逻辑值不一致。

## 最终合同

- 新规则专用固定计划在数据适配层区分输出与条件。实体字段选择真实根物理列；父范围、项目隔离、精确管理和固定条件继续使用原逻辑表达式。普通页面计划没有此覆盖，列表／详情输出保持原样。
- 规则需要的物理但逻辑派生的ID，通过另一个固定别名与同一SQL返回。别名只由编译器生成并避开已声明输出名，不能由请求指定；派生名称继续使用原联接投影。查询结果的内部别名不进入DTO／VO或原页面。
- 生成实体保留物理 country_id=null，同时内部装载证明可持有逻辑 country_id=P。Agent／原按钮规则优先消费装载证明；需要证明却缺失时明确拒绝，不能回退到实体默认值。已装载null与缺失不同，普通物理字段保持原属性合同。
- IGeneratedRuleRecord 新增必须装载字段判定。实体显式实现该方法并固定字段集合；方法和私有状态不成为JSON字段，客户端回显不能初始化证明。只使用逻辑ID的规则也启用该读取合同，不要求同时引用派生名称。
- 根记录FOR UPDATE、后续同事务派生当前读及普通预检RR快照沿C24保留。标量不额外COUNT；多值补名仍是同一快照内的分批查询，不宣称性能已验。

## 更新与回退

本轮无需SQL或元数据迁移，未改变原前端页面、样式、交互、路由和请求／响应合同。已有C24派生规则项目必须由原在线本地助手协调更新运行时与再生成后端，再重新构建；不能只替换Core或Agent程序集。新增内部接口方法意味着旧生成实体需要再生成，未成套更新的工程不能当作已兼容。

新Data分文件加入精确运行时更新清单及候选依赖检查。更新器原有RequiredActions继续要求配置／运行时／生成产物成套，手写partial保留；同时删源文件和清单也会拒绝。回退同样成套回退运行时与生成代码。BackendOnly既有工程更新仍由原更新器明确拒绝，未因本项扩展其交付承诺。
