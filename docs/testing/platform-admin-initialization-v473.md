# 平台后台账号初始化 MySQL 验收

日期 2026-11-07。生产宿主固定于 a13159203dfe9dada0c6d56f8779c67a5f1839f7，本次只增加验收用例和台账。两种连接拓扑使用同一个 Production 宿主及四份元数据。数据库、账号和 Redis 均为 Server-200 本轮独占资源。

## 验收范围

- 平台真实管理员从原工作台参数选择业务项目，经 `POST /api/admin/sys/config_button/execute` 触发首次重置，经 `POST /api/admin/custom/index/init_admin` 重复重置。原成功回执的 `data` 为空，客户端实体夹带的口令没有写入。未切到对应项目、指向平台后台和同名墓碑均应返回原拒绝协议。
- 目标账号保留高位 ID、姓名、档案和启用状态，口令、角色按已保存配置重置，物理会话记录标记为删除。两次执行保持账号和角色标识，平台初始管理员密码和会话仍有效。
- 共库从原表单登录获取真实旧会话，首次重置后旧会话及旧密码被拒绝，新密码登录和超级角色可用，第二次重置再使新会话失效。分库验证目标账号及合成 Web 会话物理状态、目标后台最小归属以及源库无该账号。分库业务宿主的独立登录不在本用例。
- 本用例通过 HTTP 验证原接口。浏览器点击、初始化与登录争用及待确认的 Agent 刷新授权策略仍单独跟踪。

## 构建和留证

Generation Release 严格构建、Production 发布通过。固定 69 个宿主文件和 156 个测试文件，独立核对两个改动测试文件的 Portable PDB 源码摘要。离线准备及原 HTTP 协议 17 项通过、1 项按条件跳过。

首轮两组未通过。Portable PDB 证实并行编译读到了旧自举夹具，后者正好将初始化按钮标为删除。首轮两组的数据库、账号、所有权记录、Redis 和凭据均已独立核清。复验使用改过墓碑对象的夹具，并在编译完成后比对源码摘要。

分库复验通过后，共库首次复验已验证重置和旧密码拒绝，重新登录却被认证中间件提前拒绝。正式宿主日志显示第二次登录请求未到登录端点。原登录页使用 `notSendSessionId: true`，因此最后一次共库复验在验证旧会话拒绝后，按原登录页规则移除失效会话头。该修正只在共库分支，已通过的分库路径未改动。

随后共库复验中新密码已登录成功。夹具将平台权限回执的 `isSuper` 错作业务后台超级角色标志。最后一轮用例改为核对该账号仍没有平台管理员标志，并通过真实角色工作台验证该业务后台的超级角色标识。所有未通过的试次均保留独立清理回执。
