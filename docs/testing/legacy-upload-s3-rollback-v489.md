# V489 原单步公开上传的真实 S3 回滚

2026-11-07，固定产品 `9d6b410f`。从当前源码严格发布 Production 宿主，独立 AWS SDK 工具单独核对对象清单和实际字节。Server-200 每轮使用新建独占 MySQL 双库、临时账号、Redis 及 SeaweedFS S3 容器，所有存储访问经回环 SSH 转发。

## 实测路径

1. 空库显式初始化，在平台库建立非超级普通账号及原页面权限。
2. 普通账号通过原表单登录，调用原 `/api/admin/sys/upload/uploadImage` 上传合成 PDF。响应包含原 `location` 和 `data.url`，匿名公开下载字节一致。
3. 另一个合成 PDF 在 S3 写入并完成内容验证后，由独占文件表的 CHECK 拒绝发布。原 HTTP 返回 200、业务码 500，失败响应没有公开地址。
4. 新 MySQL 连接确认失败文件记录不存在，已提交对照行的所属项目、上传者、状态、长度及摘要正确。分库时另核对平台库无本轮文件记录，共库时独占备用库无业务表。
5. 新建 AWS SDK 客户端列举完整桶清单，只允许一份已提交对照对象。GET 核对该对象实际长度与 SHA-256。失败上传对象不存在，对照文件经原公开路由再次下载保持。
6. 普通账号通过原删除入口清理对照文件并退出。独立查询确认墓碑和会话撤销，SDK 确认空桶、删除空桶并以新客户端核验 404。

## 结果

| 拓扑 | 正式请求 | 业务及独立核验 |
| --- | --- | --- |
| 共库 | 8 次原 HTTP | 普通身份、成功上传／公开读取、数据库拒绝发布、失败对象清理、对照字节、原删除和退出全部通过。 |
| 分库 | 8 次原 HTTP | 同一链路全部通过，另确认文件只落在业务库，平台库没有本轮文件记录。 |

两个正式轮次的独占 MySQL 双库、账号、所有权记录、Redis、SeaweedFS、私有 IAM 配置及转发均已从新连接独立核验清除。本机临时凭据和缓存对象已清理。每轮验证前后核对固定 84 份宿主、SDK 和执行器文件，摘要一致。

首轮执行器的函数名与 HTTP 模块重名，在登录请求发出前退出。该轮保留失败回执，全部独占资源已独立核清。修正命名后，用新资源完成上述两种拓扑，产品源码和验收断言保持。

本轮验证原 HTTP 与 SeaweedFS 的真实 S3 协议读写。浏览器、其它存储品牌和同条件性能继续分别验收。
