# V698 嵌入子表沿用原列表页编辑

2026-11-09。原 Java v8 的 PC 列表在 `isListEdit=1` 时逐行挂载详情组件，并把子记录 ID、父 ID、父页面编号和继承的只读状态传给详情。普通输入失焦时调用原 `saveEntity()`。嵌入子列表也经过这套生成逻辑。

C# 列表和详情渲染器已有同一分支。嵌入子页的元数据校验原先一律拒绝 `isListEdit=1`，导致合法的 Java 配置无法生成。现在接受普通、生成详情的嵌入页使用 `0` 或 `1`。父表归属、后台类型、父范围和未知配置仍由原校验处理。生成页面复用现有行内详情、失焦保存和移动导航。

修复前，整数父键和字符串父键的两例在生成阶段按相同原因失败，其他 25 例通过。修复后，固定 .NET SDK 10.0.402 严格运行子页和原详情定向回归，44 例通过，零跳过。两类父键均验证实际生成的 Vue、传入父范围及只读状态、原更新路由与写入体，以及继承父只读后拒绝再次写入。定向 Vue 挂载使用受控 HTTP 回执。

## 真实桌面 Web 与 MySQL

固定提交 `291b5813cead868a5997458577a00967b4018f54` 生成 680 份 Full 包文件，严格发布 49 份 Linux x64 宿主文件，HBuilderX 导出 62 份 H5。Server-200 独占 MySQL 8.4.11 的空库预览保持零表，显式安装生成 15 表。Caddy 同源入口实际返回固定 H5。

首个自动化脚本在登录后停在菜单定位。核对同一浏览器会话的登录与菜单响应后，从已登录首页接续。

普通编辑账号从原合同菜单打开父甲，在嵌入子列表的原详情输入修改名称。点击原子表标题触发一次失焦写入，原请求携带父甲字符串 ID。重开父甲回显，父乙仍只显示自己的明细。普通只读账号重开父甲可见新值，行内输入和写入按钮受只读约束。

独立 MySQL 读回验证父甲、父乙本身和乙明细保持，甲明细名称与审计账号正确，两个普通账号均注销。111 份运行文件复核通过，库、账号、容器、网络、临时凭据及回环转发独立核对回收。
