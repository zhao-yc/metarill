# V355 同父追加的插入与缓存同包实库对照

2026-11-06，基线 `50c5ee1`，Server-200 独占轮次 `226d81fd84001683`，MySqlConnector 2.6.1。驱动直接连接同一 MySQL 实例，比较原先分别发送插入和缓存批次，以及把两者合到一个参数化命令。两条路径均保留实际写入、缓存当前读、按字节比较、物理读回和原事务提交。合并命令用两个独立的 ROW_COUNT 结果区分插入和更新。[MySqlConnector 2.6.1 批命令行数接口](https://github.com/mysql-net/MySqlConnector/blob/2.6.1/src/MySqlConnector/MySqlBatchCommand.cs#L35-L40)

- 三组功能样本的父键、中文及引号、尾空格、decimal、null 和缓存逐值一致。重复插入后原陈旧缓存未被更新。晚行约束失败撤销首行，非严格模式缓存截断也被实际回读识别并回滚。
- 独立事务同时锁住相关父记录和原子记录。切换到错误库后，合并命令确认库名不符，插入与更新均为零，两次读取均为空，在一秒锁等待限制内完成。
- 在固定 FreeSql 3.5.311 和实际生成实体上另行验证，能从原插入构造器读取 16 个类型化参数，保留大整数、文本父键、decimal、日期和空值。ToSql 不重放 AppendData 值审计，可以识别宿主已注册审计。该试验仅使用本机回环，未发写入命令。[FreeSql 插入构造器源码](https://github.com/dotnetcore/FreeSql/blob/master/FreeSql/Internal/CommonProvider/InsertProvider.cs)

四连接争用同一父记录，每事务插入八行。先各预热四批，再交错比较三组，每种路径每组 24 批。计时含事务提交。共 144 批计时与八批预热，1,216 条记录独立核对缓存和数值。
