# V488 单步公开上传的事务回滚清理

2026-11-07，以开发分支 `a1b5ccff` 为基线。在 Server-200 的独占 MySQL 库中分别复现平台与业务共库、分库。旧版单步上传在同一事务内创建计划、写入对象并发布。数据库在发布阶段拒绝写入，或外层业务随后回滚时，记录消失，已经写入的对象仍留在存储中。

修复后，只有本次确认创建的对象才登记清理。仅当数据库尚未尝试提交且成功回滚时，才清理固定对象键。相同字节的同键重试继续校验已有对象，其结果不会取得清理权。普通分步上传仍保留对象供原计划重试。提交结果不明时保留对象，避免清掉数据库可能已经提交的文件。清理使用独立超时，失败另记诊断并保留原事务异常。

| 检查 | 实际结果 |
| --- | --- |
| 修复前 | 两种拓扑均复现。真实 MySQL 拒绝发布及外层事务回滚后，独立连接只读到已提交的对照记录，存储中仍有无主对象。 |
| 修复后 | 实库文件事务矩阵 18 项通过，零失败、零跳过。两个新用例逐字核对已提交的对照文件，并确认两个回滚路径均清理对象。原分步上传重试、引用、删除和文件回滚用例继续通过。 |
| 本机回归 | 事务测试 21 项通过，零跳过，覆盖成功提交、明确回滚、提交失败和回滚失败。文件模块 256 项通过，60 项按外部环境条件跳过，含 S3 条件写入与重试的模拟传输检查。 |
| 独立完整包 | 基线与修复包各 656 份文件，差异仅四份运行时源码和包清单。前端、生成代码、元数据逐字相同。修复包严格发布零警告、零错误，产生 69 份宿主文件。 |

两轮分别从新连接核验独占数据库、临时账号及所有权记录已清理。本机临时凭据与合成对象已清除。故障注入使用真实 MySQL 和本地文件存储，真实 S3 的回滚故障注入及浏览器仍按各自验收项跟踪。
