# 双端独占容器资源工具

2026-11-01，V22。`tools/performance/server200_paired_resources.py`补齐资源生命周期子工具；它不安装数据库、不播种、不发送HTTP，也不是完整双端正式执行器。V08及MySQL首版保持未完成。

## 固定边界与调用

工具只在核验hostname=Server-200且IP包含192.168.31.200后，通过显式Unix socket执行每一条Docker命令，并清除客户端DOCKER环境覆盖。只接受已经核实的Java329f43e、C#4820313和Redisff02b58完整镜像ID，不拉取浮动tag。

输入通过stdin传递不含秘密的JSON描述：version=1、purpose=paired-resources-v1、32位runId、authorizationStatus、leaseStatus、images三项完整ID、ports中两个不同的20000至40000回环端口、materialsSha256。公开example保持pending/not-started，实际入口在读取私有文件或运行子进程前拒绝；样例不是授权。

私有服务器根固定`/tmp/metarill-paired-<32位运行号>`且必须0700，不接收任意目录。materials.json固定三项摘要：java.env、csharp.env、redis.conf。两份env必须0600，Redis配置0444且受0700父目录保护；只允许固定环境键、该运行号前16位对应的paired两库和受限mtf账号、200端点、独占Redis别名。两份独立64位十六进制口令仅在私有配置，不进入参数、输出和归属记录。不接共享Redis、不读其密码或键；配置禁止Redis持久化。

| 命令 | 行为 | 不代表的验收 |
| --- | --- | --- |
| create | 一个独占bridge网络、Redis及Java/C#三个容器；只启动Redis，两个宿主保持created | 没有空库安装、真实连接、账号或HTTP成功 |
| start-hosts | 上层明确确认databaseInitializationVerified=true后，只允许启动两宿主一次 | 此布尔值只是调用合同，工具本身不验证数据库；上层必须保存真实初始化/结构核验回执，不能把标记当证据 |
| cleanup | 先核全部现存对象归属和ID，再按宿主/Redis/网络反序删除；逐个独立重新查询不存在 | 数据库/临时账号、私有配置和文件目录须上层分别清理，不因容器核零宣称所有对象清理 |

Java与C#均非root10001、只读根、丢弃所有能力、no-new-privileges、无自动重启；两宿主同为1GiB内存/同额swap上限、CFS period100000/quota100000、cpuset0、256PID及受限tmpfs，各自只发布127.0.0.1的明确8080映射。Redis不发布端口、256MiB/64PID/0.25CPU；数据仅tmpfs。实际CPU可用性、端口、镜像身份、资源限制及启动后的运行状况仍须正式前置检查与V18实测探针验证，不能只凭构造参数记为同资源通过。

## 归属与失败保留

同一运行号的命令互斥锁采用独占创建；检测已有锁时零Docker调用，崩溃遗留不能自动删除或接管。资源状态绑定完整稳定描述；只有上层初始化确认位不参与描述摘要，端口、镜像、用途、授权及输入清单变化均拒绝。创建前精确同名对象存在即拒绝，不收养外来资源。

每个待创建对象先写归属，再执行创建，成功完整ID另记；三个标签为本轮run、随机owner token、target。创建成功而回执丢失时，也只有后续观察到相同随机token才允许清理待判定对象。已记录ID变化、token变化或归属记录出现非白名单项均拒绝。全部对象预核之后仍在每次删除前重核；单命令失败保留状态，不自动重建或重试。ended不能再次create/start/cleanup。

工具不注册服务，不改现有页面、生成模板、业务权限、Java/C#二进制或初始化规则。完整资源执行前仍需要冻结上层协调器和精确新对象计划，取得对应授权；C19、旧双库或已结束租约不覆盖本工具的新对象。
