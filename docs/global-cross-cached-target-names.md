# 跨表级联引用全局R1名称缓存

后续B109验证共享/短级联引用受管全局名称缓存的本地子集，见[共享缓存名称验证](global-shared-cached-target-names.md)；公开发布与正式实库仍待，旧批次范围不扩大。

2026-10-31，B108；产品起点4d35bdc。普通R0/R1跨表级联的根、中或末层，现在可以引用已证明的全局R1物理名称缓存。本批完成本地数据/生成链路及不可发布原宿主准备验证；原导入导出开关保留，公开Full门槛、真实MySQL、完整Excel往返和正式事务验收仍未完成。

## 实现范围

- 复用B105的受管全局名称证明：无项目列、当前目录明确发布的全局R1物理List生产者，真实主键、后台页、精确副本路径、全局上游和非凭据物理字符串终点；循环及16层限制保持。不把任意Join、数组、文件或全局R0名称当成普通字典。
- 新 `GlobalCrossTableTarget.RequireName` 同时供级联候选、R0读取、R1缓存及维护使用。旧物理字符串仍走原物理证明；新增缓存名称的目标页条件还必须是非凭据物理标量，不开放缓存/动态身份谓词。
- 来源项目、普通目标项目、各层软删、原稀疏ID与完整父链保持。缓存名称只是显示值，不使父键、其它排序字段或其它Join列取得资格；默认名称排序可使用已证明的当前缓存列。
- R0直接读取目标已有物理副本，不额外联接上游字典，也不为来源新增名称存储。R1各级 `country_name/area_name/place_name` 继续由原物理传播定义管理；上游全局List名称由原混合协调器维护。这里证明的是静态闭包，真实改名传播及回填尚待实库。
- 同一C#元数据夹具由Data和Generation测试链接编译，覆盖根/中/末、其它两级普通/全局及四种来源键/父键组合。原组件、页面、样式、模板、接口与业务分层未修改。

## 公开门槛保持

测试模型始终保留 `isImport=1/isExport=1`。首轮生成发现它们被既有Excel完整往返验收门槛拒绝；不能通过关闭开关、修改能力报告或只验证BackendOnly来把它们宣布为可发布完整包。

本批使用现有 `CrossTableExcelApplicationPreparer` 进行独占、不可发布的原应用准备。该通道本身未修改：先确认只剩既有Excel缺口、物理结构不变及其它公开检查全部通过，再组合原正式宿主和原前端，并恢复实际元数据、控制器及导入导出开关。输出移除普通包标记，明确 `readyForPublication=false`；公开Full和本地更新器必须拒绝。四份准备应用不是可交付的Full，也不是已通过真实业务验收的应用。

## 使用与剩余验收

同版更新Core、Data和生成器，按元数据配置明确全局生产链、名称及目标页，保留真实来源项目和物理父键。需要R1新缓存列时仍执行预览差异/SQL→执行→核验；R0不新增名称存储，不使用启动CodeFirst。正规再生成并同步同版运行时，保护手写partial；原维护入口回填后须实库验证候选/已选、保存、改名/删除、维护/重复零变化、原Excel路径往返、权限、晚期文件及整批回滚，再解除对应公开缺口。回退需配套还原元数据/运行时/生成产物，不自动删列、删数据或重映射ID。

全局R0实时目标、其它缓存生产模式、共享/重复角色的新组合和正式业务验证仍待。B106单值四库冻结包/待答授权及B102八组合准备范围没有变更，本批没有混入其代码或复用其授权。B11/B14/B20/B21/B22及MySQL首版总验收继续保持部分/待验状态。
