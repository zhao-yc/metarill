# 原V8文件状态与首次绑定授权

## 读取规则

原规则来源为只读YZP的`FileLibraryAccessBusiness.canReadProtected`及`FileLibraryBusiness.canCreateFirstReference`：超级身份、私有草稿上传者、就绪文件真实记录读取是不同的授权路径。不能把上传所有权作为就绪文件的永久读取权限。

C#保留内部上传阶段：`planned`尚无可用对象，不能解析；`uploaded`映射已上传私有草稿；`ready`为已完成就绪；逻辑删除对象不参与读取。PUBLIC必须ready才能公开；PROTECTED的uploaded对象可由同项目上传者或当前超级身份读取。ready保护文件除同项目平台管理员或当前后台超级身份外，均走真实引用→当前页查询权→记录实际文件值及父范围核验，上传者也不例外。解析与实际流读取使用同一规则，拒绝状态码仍沿原实现。没有重写页面或上传交互。

`IRuntimeAuthorization.IsCurrentRealmSuper()`缺省false，保持旧授权器的必需方法及构造函数不变。平台真实Web授权器必须当前项目/后台匹配认证主体且不是Agent；独立Full宿主还要求包内已发布项目/后台、非平台管理员。工作区选择、客户端字段或包外后台不能声明此特权。宿主每次正式认证仍读取当前角色，撤销下一请求失效。

## 保存引用规则

文件行按ID排序锁定并复核同项目、ready及控件策略。就绪保护文件上传者只有在本文件**从未有过引用**时，首次保存可以免业务查询权限；这个例外不赋予普通读取权。历史核验使用当前业务事务的锁读，包含软删引用，不能使用RR快照或忽略墓碑。历史解绑后不能再次借上传所有权绑定。

记录及父读取在业务观察器内复用实际连接/事务，能够看见本批刚创建而尚未提交的父、业务行和引用；独立解析请求才创建自有连接，查询结束不处置外部业务连接。不能另开连接将同批第二次合法引用误判为无权限，也不能改成不查真实记录。

其他保护文件必须具有当前可读真实业务引用，因而他人上传但确实可读的文件可以按原V8选择绑定；不能只按文件所有权一概拒绝。PUBLIC仍须满足当前字段公开级别及其他策略。文件引用与业务字段共用事务，授权失败使整笔写入回滚；省略、显式null和空数组仍沿原协议。

## 已有工程跟进

平台更新Core、Files与Runtime中的真实Web授权器。独立完整包须同步Core、Files及`backend/Application.Host/WebAuthentication.cs`并重新构建；该Host文件已列入本地更新器的sync-runtime范围。只换Files二进制或保留旧Host不会自动获得后台超级证明，默认拒绝。先预览计划并核对这三个范围，手写partial及宿主可编辑配置继续按原保护规则处理。已有带文件的导入/复制Service仍按上一批要求再生成；本批没有改变物理列或要求自动DDL。

## 验收边界

离线实际编译完整包授权类检查普通身份、包外/工作区项目、后台、Agent、平台身份及缺身份；平台授权器另检查当前认证主体一致性。正式空库场景通过真实Web请求验证私有草稿上传者、ready无引用拒读、首次保存例外、缺查询权拒读/拒历史绑定、恢复查询权、解绑墓碑拒再次首次绑定、按真实读取绑定他人文件，以及后台super撤销/恢复。实际结果与清理证据以本批验收记录为准，不用离线授权上下文冒充登录。

当前后台超级证明本批只接读取和引用，不据此关闭重命名、移动、删除及目录管理各自的验收门槛。文件目录/管理列表、完整云存储供应商、复杂记录范围与精确数据管理、浏览器、真机、性能及多数据库仍有各自门槛。本批不宣称它们全部完成，不宣称并发撤权与流读取全程线性一致。
