# 原单选页的固定派生名称

## 已接通行为

R0来源SelectPage可以使用普通R0目标的单值字符串联接名称。例如订单customer_id选择客户，客户company_name来自公司name；来源的customer_company_name保持只读逻辑值。保留原type=1列表选择页、弹层、清除、回执和父上下文，不另写页面或样式。

此前NonRedundantSelectionCompilation只接受物理名称，派生名称的共享计划又只允许List。现新增独立目标证明后复用既有固定目标读取：目标页自身按逻辑名称在SQL内筛选／分页，辅助候选、已选、原名称导入与票据导出沿同一范围；名称终点使用固定单值匹配证明，凭据／文件数组／错误路径继续拒绝。普通请求不重新解释元数据或接受SQL。

目标页面必须是真实type=1、名称已开放读取、普通同项目R0实体；项目／软删、真实父与附加条件按原目标页执行。SelectPage的附加条件只能是目标页已执行的固定条件；来源表单动态条件、未证明排序、全局／逻辑父／精确权限等组合继续保留门禁，不能借宽目标页代替窄条件。

原List的证明与生成路径保持；能力声明按实际控件写SelectPage，未把所有派生名称都标为List。无目标父、同父以及由来源实体物理FK推导的独立目标父分别验证；隐藏关系仍执行默认值与最终FK校验，不增加公开候选入口。

## B190 单选弹层的派生整数名称

普通 R0 来源的 SelectPage 可以使用普通 R0 目标页中已开放读取的 int32 或 int64 联接编号。来源显示辅助字段沿用原命名和联接路径，类型与目标名称一致。弹层沿原 type=1 页面、选择回执和父记录上下文。int32 仍为数字，int64 通过原 JSON 字符串协议保留精度。

来源列表的名称搜索接受编号片段，通过固定联接表达式参与分页和计数。目标弹层的编号输入按整数精确匹配，辅助候选沿用目标页默认排序，包括主键次序。Excel 的数字和文本单元格以业务编号反查，在原项目、父记录及目标条件范围内取唯一结果。导出沿 B189 的编号文本格式，保留高位整数。

隔离源码严格构建通过，46 项定向验证全部通过。验证执行了生成的来源与目标筛选和回执投影，并构建三个完整包。其中整数包使用原 Vue 挂载探针验证编号片段、父记录、取消／确认及权限撤销时的迟到回执。挂载探针使用受控请求替身。

已有生成包使用 B189 或更新的 Data 运行时，再从元数据生成受影响的服务、接口、DTO／VO 和页面。专项 MySQL、正式浏览器和性能验收按首版计划后续执行。

## B191 全局目标的派生整数名称

普通 R0 来源的 List、SelectPage 可以使用明确发布的全局 R0 目标提供的 int32 或 int64 联接编号。编号终点来自同目录上游字典的真实列。生成计划沿用已发布的候选页及其条件，有行项目归属的全局目标仍按原范围处理其普通 CRUD。

两种控件沿原候选、名称搜索、已选回读和固定目标页执行。原 Excel 使用同一范围反查和导出编号，高位整数在回执和工作簿中保持精度。适用范围为普通 R0 来源和全局 R0 派生整数目标。26 项定向回归通过，其中两个新模型完成实际生成编译。专项 MySQL 及正式浏览器验收后续执行。

## 跟进与边界

本批没有新增数据层API或业务DDL。已有同版正确逻辑名称模型更新生成器后，正规再生成受影响Service、DTO/VO、Controller与原页面；沿原三动作预览／应用保护手写partial、AppID和私有配置。元数据变更仍先维护定义并预览结构，不建立新的物理名称缓存或自动回填。
