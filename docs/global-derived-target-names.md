## 本批范围

例：`global_target.name` → 全局R0的逻辑名称 `global_source.global_target_name` → 普通项目消费记录。此前C#在目标存储模式处拒绝；本批接通经过证明的 List／SelectPage 单值用途。

- 普通R0或R1消费者保留真实项目列；List内外外键分别支持已有int64／string，SelectPage保持原int64物理外键及type=1弹层。
- 全局中间表必须显式发布在当前目录，具有真实非空int64主键及正确软删类型；每步只走已声明的物理单值键、固定目标页和非凭据字符串终点。
- R0名称沿原联接读取当前值，不读不存在的物理副本。生成实体的该属性为 `IsIgnore=true`；普通R0只存ID，R1消费者的原名称副本进入既有混合传播／原维护图。离线图不代表实库已传播。
- R0逻辑名称与R1缓存共用活动字段栈；循环、超过16层／16跳、冲突声明、虚拟／多值／文件及敏感字段不能冒充名称。原严格物理标量API不变。
- 全局资格只改变关联目标角色；根自身有真实项目列时，Data读取继续按来源项目过滤。全局候选根及生成服务绑定发布目录身份，普通与超级账号换项目均在连接前拒绝。

本批需要实时名称读取、且带行项目的全局R0目标目前仍不能发布完整应用：对象自身范围与全局候选范围需要分别接线，不能静默清除项目过滤。旧 `GlobalCrossTableTarget.Require/RequireName` 继续保持R1用途，新R0另走单值入口；多选、级联、共享父和文件父组合没有因此顺带开放。精确管理匹配仍保留原int64路径约束。
