# 自关联级联 Excel 完整路径合同

保留原 uni-app 导入、导出按钮、模板标题、请求与下载流程。生成后端按原 Java 自关联级联规则导出和反查完整路径，例如 `根/子/孙`，不把单元格数字当作节点 ID，也不只凭叶子名称猜目标。当前范围仍是固定目标、明确物理 ID/名称列的普通冗余 selfTree 子集；不因此解除 FullApplication 门槛。

## 路径、数据范围和权限

导入按元数据冻结的完整分隔符切分，去首尾空白和空段，从空父根开始逐层匹配名称及父键，每层必须唯一。最大 64 层；缺失、同父重名、循环、跨项目、已删除或固定条件排除的路径拒绝。数字名称按名称查询，没有 ID 捷径。名称值均参数化，客户端不能指定表、列、SQL、目标范围或操作身份。

原来源页面的 import 动作授权覆盖整批导入；不额外要求来源 create/update 或目标 list。内部生成的私有 Core 调用传递 Import 枚举，不开放请求切换入口。普通新增、修改、复制继续沿已接线的目标 list 校验，候选和独立路径仍校验两页 list；所有入口保留真实 Actor、目标项目、软删和固定条件。来源读取、导出不增加目标 list 门槛。

导出复用分页查询的来源范围、RR 读取快照和批量祖先缓存。Excel 单元格由真实节点链重新拼接，名称为空、两端空白、包含完整分隔符或关联链失效时拒绝，避免将不能表示的路径伪装为空值或 ID。普通列表坏关联仍按既有合同显示空路径并保留 ID。名称路径若存在同父重名，导入明确拒绝，不承诺导出能提前检测全部重名。

## 事务和服务规则

追加、按第一业务列覆盖均复用现有导入及页级白名单。新增省略级联字段使用默认值；覆盖省略保持原值，显式 null 或空单元格按原导入规则清空。受管名称由最终 Service 从当前节点计算，不能用导入名称绕过关系校验。

逐层名称反查在来源批次事务内加当前读锁，锁保持到整批提交；默认值及手写钩子之后再次验证完整祖先、名称长度和关联范围。任一行、规则或提交前步骤失败，整个批次回滚。锁定路径会增加锁持有时间，与其它写入顺序交错仍可能发生正常死锁并回滚；本批不是整体并发容量或 Java/C# 同条件性能验收。
