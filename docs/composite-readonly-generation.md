# 复合只读条件页面生成

2026-10-29，`f9674c5` 基线上的 C23 子集。保持原详情模板、控件、主子页和保存/删除/复制操作；补齐此前只允许单字段的 C# 生成限制。

## 实现与边界

原 V8 `UniappService` 把 `this.entity.` 与配置文本拼入 computed。新生成器复用 C21 的 `ReadOnlyConditionRule` 受限语法树，静态输出字段、常量和固定运算符；原配置文本不会直接插入脚本。没有新增浏览器条件解释器，也不使用 eval、动态Function或请求执行脚本。

例如 `locked || (this.entity.approval_state === '已审' && entity.name != '允许')` 在生成时绑定本页实际JSON字段，保留括号及运算顺序。支持裸字段、entity/this.entity前缀、受限比较、与或和否定；函数调用、赋值、原型路径、未知字段及歧义仍拒绝。原长度/令牌/层数限制保持。

字段必须属于现有 `PageModel.Readable` 上限。仅详情可读的条件字段不会因此进入列表响应；列表和详情都关闭的字段不能借只读条件取得读取权。投影只登记条件实际引用的列，不回退到全表或全Readable。JSON嵌套路径只允许已声明JSON对象根，不能反射普通标量或未声明来源；实际对象加载、空路径及派生字段的全部端到端组合未验收，不将其标为完成。

单字段仍输出 `Boolean(this.entity.field)`，空条件不增加表达式。原权限、记录加载完成、路由/全局/父只读门禁继续与条件共同决定只读状态。两轮既有平台/示例生成的逐字稳定结果另据本轮回执核验。

## 前后端语义

前端保留原JavaScript原生标量、比较与短路语义；服务端继续执行原Java兼容的受限求值及BigDecimal规则。静态JS输出不能替代服务端门禁，不宣称两种语言所有大数、转换和缺值边界完全一致。仍由服务器实际原记录决定Agent/可写按钮是否执行，客户端回显不能覆盖。

字符串通过JSON转义；数值仅由已解析的十进制令牌形成合法静态JS数字，去除前导零造成的旧式八进制语法问题，Unicode十进制数字映射到ASCII。不会把这些数值提前经double舍入。

## 更新与回退

运行时和生成器按同一提交升级；复合条件页面需正规再生成。既有单字段/空条件无须更换界面资源，仍应预览候选差异并构建。没有数据库、接口DTO/VO、DDL、回填或手写partial迁移。回退前须恢复旧版可生成的单字段配置，再成套恢复旧生成器/运行时与匹配产物；不能用旧生成器处理新复合配置。
