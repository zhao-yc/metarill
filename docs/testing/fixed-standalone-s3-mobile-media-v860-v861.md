# V860–V861 固定候选独立 Full 移动双附件

2026-11-10。固定 `867759828577fe26cc57218004f84ee6f25ae6a9` 的 CLI 从合成双附件目录生成 661 个 FullApplication 文件，逐项复核 660 个清单条目。Windows x64 Release 按警告即错误构建 51 份宿主文件。391 份前端输入仅在验收副本配置现有 AppID 和回环 API，HBuilderX 导出 53 份 Web 文件。独立应用使用 Server-200 的专属 MySQL 库、Redis 和 SeaweedFS。

| 检查 | 实测结果 |
| --- | --- |
| 显式安装 | 首次结构预览 13 项差异。独立连接确认预览前后零表。显式应用结构及初始化安全后，重复预览零差异。 |
| 原移动 Web | 390 × 844，编辑及只读账号分别通过独立原登录、菜单和详情。56 个浏览器请求，两次上传后只保存一次。两个账号重开详情均未自动下载，分别预览 12 × 8 PNG 并各单次下载 ZIP。 |
| 独立 MySQL | 两个附件描述、活动引用及就绪文件均在独立应用库。原备注、中文文件名、长 ID 和字符串字节数保持，两次普通会话均撤销。 |
| 匿名与独立 S3 | 匿名 PNG 为 HTTP 200，读回 283 字节。匿名受保护 ZIP 为 HTTP 401／R401。两份下载均为 183 字节并保留原名。独立 SDK 读回两个 S3 对象，长度和 SHA-256 分别匹配，精确删除后从新连接确认桶不存在。 |
| 回收 | 两轮独占数据库、账号、所有权、Redis、SeaweedFS、私有配置及转发均核清。另从独立连接核对两个远端 TCP／UDP 端口和本机四个监听端口，原浏览器空间已关闭。 |

准备阶段曾把逻辑元数据摘要当作物理文件摘要，改为对照生成清单后继续逐文件验证。V860 从真实空库得到 DDL 预览，执行器因 UTF-8 编码名错误在应用结构前停止。V861 保留同一固定包、宿主和 H5，修正读取方式后通过全链验收。
