# V613 当前 Linux 候选空库安装与会话验收

2026-11-08 在 Server-200 实测 MySQL 8.4.11 与 Redis。产品基线 `5c8fcb823491e2e25029ffa40cb2cfdc851c0abb`。复用 V612 固定的 Linux 平台与公开 Full 发布物，各 49 份，另核对平台四份元数据及 `global.json`，两轮共用同一份逐文件清单。三个 Production 宿主都从本轮只读挂载的发布物启动。

| 安装形态 | 普通启动后 | 显式安装后 | 原 HTTP 验收 |
| --- | --- | --- | --- |
| 平台分库 | 平台库 0 张，业务库 0 张 | 平台库 24 张，业务库 13 张 | 所有者登录、原菜单、客户 CRUD、重启、注销 |
| 平台共库 | 0 张 | 25 张 | 所有者登录、原菜单、客户 CRUD、重启、注销 |
| 独立 Full | 0 张 | 15 张 | 所有者登录、原菜单、客户 CRUD、重启、注销 |

- Full 执行原结构预览、结构应用和安全初始化。空库预览产生变更计划，表数仍为 0。重复结构应用的计划为 0 项，安全初始化报告凭据未修改。逐表核对业务 3 张、文件 3 张、安全 7 张、编译内置 Agent 2 张。
- 两种平台形态执行原 `--initialize`。三个宿主均以不同的引导密码重跑安装，随后验证原密码有效、替代密码被拒绝。
- 三条客户链验证字符串 ID、查询、更新时保留省略字段和显式置空的区别、分页与逻辑删除。通过 MySQL 核对三条独立业务记录和删除时间，平台分库的配置库无客户业务表。
- 三个宿主互换会话共 6 次，全部拒绝。原会话可在本宿主重启后继续访问，注销后再次访问被拒绝。Redis 拒绝匿名请求，认证后返回 PONG。

首轮在显式安装后因夹具只计入独立包的三份 JSON，遗漏编译内置的 `sys_agent_grant` 和 `sys_agent_task`，整轮按未通过保留。复验从固定发布元数据及同提交的编译目录派生预期表名，并按原 `menu`、`permissions` 字段读取菜单。产品与发布物逐文件摘要保持一致。两轮均在销毁独占 MySQL 容器前，以新数据库连接核对精确库名及账号已清除，之后再从新 SSH 连接核对容器、网络、数据根和临时凭据已回收。

本次覆盖独占内部网络上的 Linux 后端 HTTP 和初始化所有者。严格 MySQL TLS 另见 [V565](mysql-strict-tls-web-v565.md)。实际浏览器直接 HTTPS、普通角色矩阵、真实 Tiny Cloud、剩余同条件性能与最终提交 CI 仍按 [首版签收清单](../mysql-first-release-milestone.md) 跟踪。
