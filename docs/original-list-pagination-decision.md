## 实施前缺口

恢复原前端后，详情页与筛选页继续生成原 `zxz-uni-data-select`，但候选初始化仍请求原 `findNameId...` 数组地址：

| 位置 | 当前行为 | 影响 |
| --- | --- | --- |
| `OriginalUniappDetailFields.cs` 的 List / InitList | 原 zxz 控件，整个候选数组回填；原 formParameters 与父范围 | 超过 5000 个合法候选时，接口明确报错，控件不能取得候选 |
| `OriginalUniappListFilters.cs` 的 List / OriginalOptionsRequest | 原 zxz 控件，筛选初始化请求整个数组 | 同样受上限影响，不能只修详情而遗漏筛选 |
| `BackendRenderer.cs` 的候选生成 | 数组读取最多 5001 条，超过 5000 整体拒绝；另有 `/page` 与 `/selected` | 后端分页存在，不等于原页面已经接通 |
| `remoteRelationOptions.js` 与 zxz 可选 remote 属性 | 已有分页、搜索、已选独立回读及加载事件 | 当前原页面没有绑定这些属性；不能以组件单测当成页面接线完成 |

`GeneratedRelationUiTests` 明确验证恢复后的生成页面使用原 zxz、原数组与父范围；它并未验证超过 5000 候选的实际浏览器操作。`relation-options.md` 中“新生成页面已改用 wrapper”的描述属于 2026-10-19 恢复前实现，不能继续当作当前产品结论。

另已核对原 Java 的 `GenerateDetail` / `GenerateList`：标准 List 没有生成 multiple；当前 C# 原详情也为单选。组件支持 multiple 不代表存在已实现的“多选 List”元数据能力。原多值关系应分别按 `MultiSelectPage` 和 `MultiCheckBoxDatabase` 验证，不新增一个未约定的 MultiList 控件。

## 建议方案与操作影响

保留原页面、布局、样式、原 zxz 控件及选择/清空事件，只为已编译的数据库 List 接回已有远程候选：

1. 详情和筛选都使用固定字段的 `/page`，每次加载一页；关键词传给服务器，继续在原搜索框输入。
2. 在原下拉列表内滚动到底部加载下一页，复用组件现有的可选“加载中／加载更多”状态。不会改成新选择页面；但候选加载由“一次全部载入、本地过滤”变为“分批载入、服务端搜索”，这是本次需要确认的操作差异。
3. 已选项用 `/selected` 独立回读，搜索或首屏不含已选项时仍保持原值；失败、超范围或切父范围不得偷偷清空持久值。
4. 保留来源/目标页权限、真实父范围、项目与登录隔离、长 ID 和异步请求失效规则。不放宽旧数组 5000 上限，不无条件拉完所有分页。
5. 固定配置目录、常量下拉及原数据库复选的全选逻辑维持当前边界；只有确认可编译并满足完整范围的数据库 List 采用此接线。不能把分页第一屏当成复选“全选全部”。
6. 生成器和共享运行时一起维护，再生成页面，不逐个手改生成产物。本轮已按用户选择实施；后续超出该方案的交互变化仍须确认。

## 验收与回退

确认方案后，先验证实际生成脚本和原控件，再用 HBuilderX 构建与 ego 浏览器验证超过 5000 候选、非首屏已选、搜索、清空、切父范围、迟到响应及失败保值。原多选页面另外验收；合成 HTTP 只证明受控前端链路，不替代真实登录、MySQL 与权限验收。

后端分页/已选协议不变，旧数组调用者继续得到原合同；回退本次生成器/运行时接线并配套再生成，不修改数据库结构。保留当前上限错误，不能以静默截断掩盖回退后的限制。
