# V418 复用同父追加首行已持有的父锁

2026-11-06，基线 39a82572。固定父追加导入在入口按原位置锁定父行。只有原生成分支允许合并、当前确为已声明的 MySQL 可重复读追加事务、首行之前无宿主写入副作用且 ORM 无自定义过滤或钩子时，首行复用已持有的排他锁。首行固定候选按原位置重新核对，后续行照常校验。短批次、未知观察者及手写规则保留原路径。

从固定元数据重新生成并严格编译，在 Server-200 隔离 MySQL 用原生成 Controller 和 Service 完成 9 次 HTTP 请求。默认八行批次的直接父锁读由两次变为一次，后七行仍使用一条合并命令。两行短批次及自定义观察者场景各执行两次原父锁读，观察者仍逐行收到 8 次通知。

另有 24 个共享和排他候选原式实库对照，校验空值、候选不匹配与不同快照。原 HTTP 验证无权限不写、数据库首错与行号、末段输入及第 6 行数据库错误均整批回滚。最终只有三个成功请求的 18 条明细，正常批的 Unicode 缓存值和尾空格逐值核对。库、账号及所有权记录已用新 SSH 独立核清。

本轮是生成入口的专项测试。完整独立应用默认配置的无采样正式计时仍需执行，首版性能以 [V412 正式结果](paired-child-default-single-command-timing-v412.md) 为准。
