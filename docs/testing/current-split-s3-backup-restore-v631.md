# V631 平台分库与 S3 对象恢复演练

2026-11-08。固定产品 `5c8fcb823491e2e25029ffa40cb2cfdc851c0abb`，沿用 [V630](current-split-backup-restore-v630.md) 的 51 份 Windows Production 宿主及合成元数据。Server-200 使用四个独占 MySQL 库、两套 Redis 和两个独立 SeaweedFS S3 兼容容器。两套对象服务分别使用自有 IAM 凭据及物理地址，桶名和对象前缀相同。探针使用与候选相同的 AWS SDK，严格构建零警告、零错误，库存门禁 8 项通过。

| 阶段 | 实测结果 |
| --- | --- |
| 停写与恢复 | 源账号上传公开及受保护附件，绑定到同一客户后退出，源宿主停止监听。源平台 24 表、业务 13 表逻辑恢复到空目标。六类有效目录和数据语句逐项一致，复导出中重复字符集词组按 V630 合同核对。 |
| 真实对象备份 | 独立 SDK 核对源完整键集合和目标空桶，读取两份对象备份并按原键条件写入目标。目标新客户端复核完整库存、35／38 字节和 SHA-256，未上传计划未产生对象。 |
| 位置约束 | 源两个对象、桶及容器已核清。目标沿用自己的逻辑端点时，客户记录与原引用可读，但公开和受保护内容均按原 HTTP 200／R500 拒绝。随后将原逻辑地址指向目标物理服务，使用目标凭据并保留别名、区域、桶、前缀及寻址方式。原只读会话经重启保留，原文件引用无需改写，两份实际下载字节与备份一致。 |
| 权限和回收 | 25 个原 HTTP 请求、13 项独立 S3 操作通过。匿名访问受保护附件、无页权限、旧注销会话及只读写入均被拒绝。独立 MySQL 验证业务库的客户、文件和引用，平台库的三条 Web 会话均为已注销。按对象键及摘要删除本轮对象，空桶删除后独立确认不存在。四库、账号、两套 Redis 和 S3、临时 IAM 目录、转发及本机配置已独立核清。 |

本轮验证同一 MySQL 实例内分库和独占 S3 兼容服务恢复。跨 MySQL 实例、实际云服务供应商、版本桶历史和改变逻辑位置的迁移按各自合同验收。
