# 安全协调的有界当前读基础

本片只增加 SqlRowStore 的 `ReadForUpdateByIdsAsync`，还没有接入角色协调器，也不代表锁内撤权闭环完成。

- 表与整数 ID 字段来自宿主已发布基础设施模型；只接受最多 1000 个不重复正整数，未知表/列、非整数键及超限明确拒绝。
- 所有值使用驱动参数；复用原登记列投影、逻辑删除、过滤条件和当前事务，不提供客户端 SQL/列名入口。
- 空集合在事务内直接返回空结果，不发命令、不退化全表读取；取消令牌在构建命令前生效。
- 集合参数按数值排序，SQL 另按真实主键 id 排序后 FOR UPDATE，但 ORDER BY 只规定查询/返回顺序，不能单凭它保证 MySQL 使用二级索引或 filesort 时的物理取锁顺序，更不能把 IN 参数的排列当作取锁证明。协议仍依赖项目、后台统一聚合预锁及实库并发验证；此入口不会代替该顺序或授权决策。

离线 10 项使用真实 SqlRowStore 和命令传输适配器核对参数化、固定范围、软删除、事务、空集、非法集合、取消。没有连接数据库，不能证明 MySQL Repeatable Read 下等待锁后撤权或死锁行为；这些将随 Runtime A 独占实库用例验收。原 project-files clone 的三个未提交文件完整保留，仅将自有差异提取到新的角色协调分支。
