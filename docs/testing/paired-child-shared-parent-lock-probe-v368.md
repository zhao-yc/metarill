# V367／V368 同父追加的共享锁实库对照

2026-11-06，开发基线 acc7944。Server-200 MySQL 8.4.11，固定 MySqlConnector 2.6.1。两个独占轮次分别为 f95e6a1c7295b773 和 cc826c013092529a，本轮仅运行独立驱动专项。

V367 在同一父记录上分别使用排他锁及共享锁。两条路径均保留当前读、原可重复读快照、固定候选、子行排他锁、缓存更新及物理读回，候选、写入和缓存继续每行一条驱动命令。两个事务持共享锁时均可写入不同子行，第三连接的改名、软删除和候选变更均等待。只提交一个写者时父记录仍不可改名，两个写者都提交后改名成功，后续新增读到新名称。失败末行撤销首行。两个共享事务随后都尝试写父表时，实际出现一次锁升级死锁。

四连接，每事务八行。各四批预热后交错三组，每种方式每组 24 批，计时包括提交。144 个计时批及八个预热批共 1,216 条明细逐值核对。表内按排他／共享排列，时间单位为毫秒。

三组共享锁吞吐分别变化 +29.6%／+83.5%／+75.7%。首次父锁调用包含数据库读取和驱动开销，父锁返回至提交开始是客户端可证实的持锁区间。共享锁下提交调用中位数增加，与总体吞吐改善同时出现，不能用单次提交时长解释吞吐。

V368 在新独占库安装确实更新父表的子表触发器。原最小权限运行账号从触发器目录读到零行，实际插入却更新了父表。两个共享锁写者通过该触发器同时升级锁时，再次触发真实 1213，回滚后无残留。仅对本轮临时账号授予精确子表的 TRIGGER 权限后，能看到同一个触发器。另一个事务先用 LIMIT 0 固定子表元数据，管理连接安装第二个触发器得到 1205。回滚释放后同一 DDL 成功。两轮临时库、账号及所有权记录均用新 SSH 核清，临时权限随账号回收。[触发器可见性](https://dev.mysql.com/doc/refman/8.4/en/information-schema-triggers-table.html) · [事务元数据锁](https://dev.mysql.com/doc/refman/8.4/en/metadata-locking.html)

共享锁可作为有明确适用条件的方案继续验证。原最小权限账号的零行结果无法证明无触发器。普通导入应保持原排他路径，只有能核验当前表的触发器可见性和缺失、固定元数据，并能证明宿主、传播与观察器均不会写父表时，才可尝试共享路径。完整应用功能及正式同条件验收仍待。MySQL 首版门槛继续以 [V366 正式计时](paired-child-parent-write-batch-timing-v366.md) 判定。
