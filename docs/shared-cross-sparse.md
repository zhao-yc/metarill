## 整组存储

两个原控件共用国家、地区，城市和仓库是独立末端。非冗余模式同时选择城市和仓库时保留两个末端 ID，共同国家、地区及名称不重复缓存；只选择仓库时，其路径也恢复短控件的公共地区。只存一个最终末端会丢失另一分支，逐控件调用旧稀疏打包器也会互相覆盖，因此新增整组计划。

`SharedCrossTableSparseSelection` 从固定元数据复制不可变分支与槽位，计算不可由其它已选末端推导的节点集合。编码前要求已验证路径的公共祖先一致，读取原始值时拒绝祖先与后代同时持久化、非规范 ID、未知或缺失字段。不同目标表的相同数字 ID 仍通过字段身份区分。名称不写进 R0 来源物理表。

原 `CrossTableSparseSelection.Compile` 继续拒绝共享；整组签发的分支身份只用于 SQL 及原始位验证，不能再分别打包写入同一实体。统一存储计划据此识别真实 ID 位，不将共享辅助列冒充独立业务关联。

## 固定 SQL 读取

每个控件保留自己的线性目标链；整组编译全部同伴，目标页、固定条件、共享字段的目标／父关系／祖先必须一致。公共祖先从可达分支合并，两个活动独立分支实际祖先不一致时拒绝，不能仅用 COALESCE 隐藏冲突。

分页计数、统计验证整组，明细另投影私有校验标志，因此无 COUNT 导出式读取与事务当前读也验证冲突。标志及原始稀疏位不会出现在公开结果。逻辑父范围接通同组的可达分支，保留原项目、软删、固定条件及事务锁语义。没有共享组的路径保持原入口和 SQL。

当前固定范围只处理普通 R0 来源、独立固定目标；全局／来源直接参与继续拒绝，匹配、维护及派生跨对象用途仍遵循已有门槛。明确绑定全部目标页不等于建立身份或授予页面权限，生成宿主仍须执行原授权。

## B76 接线合同（固定范围已实现）

- 原始稀疏快照与完整逻辑快照分离；部分更新在请求合并前按需恢复，省略整组不增加读取。手写钩子后来改变组内关系时仍须识别真实变化，使用同请求缓存的原逻辑快照协调，不能拿原始祖先空位当作关系变化。
- 原逻辑路径读取加入当前事务并直接持有需要的目标锁，避免先取共享锁再升级。只访问实际独立末端；短控件没有自己的持久化末端时，其共同祖先从另一分支补齐。
- Service 先整组协调，再校验依赖上级的普通关联及页面范围；全部组最后只打包一次，不能循环调用成员的旧 PackCross。
- 创建、更新、复制均保存归一化后的预期逻辑快照。打包后实体只剩物理末端，不能再以这些空祖先位作为预期路径。
- 正常 DML 后先核对实际原始 ID，再恢复实际路径，验证整组共同祖先和预期逻辑值，防止触发器改变目标父关系后两个成员各自有效却彼此冲突，或逃逸页面父范围。不得补写修复来掩盖失败。
- 复制先验证源原始存储无歧义；原服务钩子只执行一次，缓存传播／文件引用与通知仍在同一事务。生成 `.g.cs`、DTO／VO、原详情事件统一来自元数据／生成源，手写 partial 保留。
