## 修复与边界

- 普通物理字段通过StringNameQuery.ApplyPattern生成列LIKE，只将`%关键词%`绑定为参数，不对原%/_或反斜杠模式另加转义。无客户端SQL、表／列或collation入口，映射与provider在Data层校验；当前仅MySQL正式适配。
- 非冗余固定计划新增LikePattern，枚举追加，原值不重排；COUNT、分页和统计共用原项目／父／删除范围及同一模式参数。Contains仍为已确认的字面关键词，名称数组仍只匹配解码后的成员。
- 普通冗余／固定非冗余生成入口统一选择原模式；searchType=equal、数组IN、null／空白跳过和名称控件分支保持。没有派生关系的R0页沿既有强类型路径，同样使用物理字段的ApplyPattern。
- 关系名称字面搜索仍用原ApplyLike及ESCAPE规则，不恢复其已经明确排除的通配含义；固定候选条件本身的LIKE模式也保持。

无需元数据修改、DDL、回填或数据迁移。已有工程须配套同步后端运行时及重新生成页面：三个Data查询源码与新Service调用必须同版，不能只生成页面后用旧运行时编译。旧／新前端均保持原接口。
