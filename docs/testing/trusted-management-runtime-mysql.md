# 可信管理模块的真实身份、HTTP与MySQL验收

本批验证内部工厂签发的三管理页：账号、角色、后台类型，以及原权限工作台的生成Controller。模板、三个必要Service partial、数据库当前读与事务协调器均使用产品实现，不注入固定身份或权限替身。默认FullApplication发布门禁仍保留；本批不等于整个独立应用已发布。

## 实际执行链

专项为每轮分配全新项目、两个后台、普通编辑角色与账号，在写入前核对指定测试实例、账号会话必要索引，以及六表中包含墓碑的项目范围均不存在。种子仅用于准备普通编辑者的原页面动作权限，不授平台管理员或后台超级角色。

通过工厂组合固定模块并正规生成，真实编译生成程序集。宿主直接执行 `ApplicationSecurityCatalogRegistration.Add`、`ApplicationWebSecurityCoordination.Add` 与生成的 `AddGeneratedServices`。正式Web授权/身份保持同一Scoped实例，完整目录绑定编译摘要；Service与协调器共享同一个实际DatabaseSession。

回环Kestrel通过实际 `ApplicationWebAuthentication.LoginAsync/ResolveAsync/LogoutAsync` 建立和验证持久Web会话。测试用 `/login`、`/logout` 只是承载上述模板方法的夹具路由，未接原登录输入解析与完整Program启动流程；三页和工作台则直接访问生成的原HTTP接口。因此本批是正式认证实现、实际生成Controller、Service及数据库闭环，不宣称完整独立Host原登录页已验收。

## 已验证行为

- 匿名请求拒绝；登录取得真实普通编辑身份，没有平台管理员或后台super身份。
- 普通编辑者按已确认原规则创建super角色、创建账号并绑定本后台角色；数据库保存PBKDF2，回执只有原八位密码掩码，启用控件映射正确。
- 更新省略密码保留摘要；显式null密码与跨后台角色均拒绝，目标账号全行摘要保持不变。
- 后台初始化配置的短密码仍按原50字符配置语义保存，超长值拒绝并保持全行；没有执行初始化按钮或账号重置。
- 原权限工作台可读写同后台super角色的资源草稿，保持super属性；旧revision拒绝且授权行含墓碑的快照不变。
- 普通编辑者可沿原账号页修改权给本后台账号绑定super角色，新账号真实登录具有后台super身份，仍不是平台管理员。
- 原工作台撤销操作者自身页权后，下一HTTP请求返回403；注销后原令牌下一请求返回401。

## 结果与清理

最终冻结用例1/1通过、零失败零跳过。前两轮分别也是1/1，属于同一用例的逐步增强重跑，不累计成3项。未配置私有测试参数的预编译批次0通过、1跳过，仅证明测试工程能编译。

每轮停止并释放自有Kestrel，核验随机项目标记及两个后台归属，在一个事务只删除本轮项目的六表行，含会话与逻辑删除记录。完成后另起独立只读连接，重验实例并逐轮查询六表，全部零残留。没有DDL、GRANT、初始化或既有项目数据修改，私有收据不进入公开仓库。

仍待验收：完整打包/Program及原登录页、原三管理页浏览器、其余事务并发组合、初始化的行为确认及跨业务库入口、设备与同条件性能。既有RR核心专项和本批单请求HTTP不能互相代替，也不据此删除Runtime A门禁。

## 实际生成管理HTTP的并发跟进（2026-10-21）

在正式Web身份模板、内部工厂生成的三管理页Controller/必要partial、共享协调器和同一实际DatabaseSession上，新增三个场景。仍使用既有隔离MySQL中的随机项目及两个自有后台，不启动或修改Docker、不执行DDL或SQL GRANT，不读取锁观测表。

| 场景 | 实际证据 |
| --- | --- |
| 认证后撤权 | 认证已读取持久普通编辑身份，夹具在同一外层RR事务暂停；另一真实HTTP请求由原权限工作台撤销操作者的账号页权限并提交。恢复后普通SELECT仍读旧权限，生成Service当前读拒写，外层事务回滚且目标完整行摘要保持。 |
| 目标迁后台 | 另一真实生成账号update请求提交目标的新后台及匹配角色；旧RR普通读取仍看到原后台。原请求明确YZP_CONFLICT，目标全行等于第二请求合法提交；回滚前原后台行实际持锁、新后台行可写，未逆序补锁，回滚后原锁释放。 |
| 无关后台持锁 | 一个实际事务同时锁住本轮另一后台的账号、角色和授权行；事务持续持有时，原工作台保存和生成角色DELETE完成，数据库确认目标角色墓碑。前后独立连接对该无关账号精确UPDATE均得到1205，证明持锁窗口真实重叠。 |

两个旧快照场景由测试中间件额外套RR外层事务并缓冲响应到回滚结束，用来验证长事务中的旧视图，不声称默认完整Program所有请求本来就使用这一外层事务。身份和权限不使用替身，屏障只位于测试Kestrel；`/login`与`/logout`仍是前述模板方法的夹具承载，不是完整Program原登录输入解析验收。

锁探针先用自有项目/主键证明精确行存在，再在独立事务执行不改变值的UPDATE；有锁要求1205，无锁要求完成，最后全部回滚。`innodb_lock_wait_timeout=1`仅设置本次探针连接；不以耗时阈值、任务未完成或锁状态文件推断锁存在，也不使用观测授权。

最终`TrustedSecurityRuntimeMySqlTests` **4/4通过、零跳过**，包含原单请求闭环1项和新增并发3项。无配置编译批次0通过/4跳过，不计实库通过。最初实库为2通过/2失败：测试误把驱动沿用数据库默认隔离时的Unspecified当作非RR；独立诊断保留0/1失败。修正仅在同一真实事务连接读取`@@transaction_isolation`并明确要求REPEATABLE-READ，两个场景2/2复验后再完整4/4，不修改产品隔离级别或超时，不累计重复运行。

全部11轮随机项目（含失败轮次）依既有所有权检查精确清理；测试结束后新的独立连接重核实例，对六表项目范围逐项查询，**66组查询均零残留**，包括会话、账号、角色、授权、后台和项目墓碑。独立核验只SELECT，不执行补清理。私有证据位于`.local/trusted-security-concurrency/`的各批TRX及`cleanup-independent.json`，逐项目原回执位于`.local/trusted-security-runtime/mysql-*/`；源代码与文件摘要另入集成收据。

本批没有产品源码、元数据、模板或前端变更，没有原页面/完整独立Program浏览器、设备和性能验收。完整管理包发布、初始化待确认行为、跨库入口和其余并发组合继续保留门槛；不能用本批解除Runtime A或合并main。
