# 非冗余多选：固定字符串名称与原页面合同

日期：2026-10-22。开发父基线：`b3bcf2c`；最终 654 份源码／测试快照 SHA-256：`2de892abb36b56420bb088b88da1b8dcf8b3e57951de440dd4f7a82debad20d1`。本项属于整体复杂关系模块的第一批，不解除级联、复杂联接、混合传播、回填或完整 MySQL 首版门槛。

## 范围

支持非冗余普通实体表的 `MultiSelectPage`：物理字符串 `_ids` 列保存原 JSON ID 数组，目标为明确的 type=2 页面。目标名称为本页可读的物理字符串，或原 `nameField=id` 合同；同父与唯一物理外键确定的独立目标父继续沿既有规则。目标必须属于同一发布项目，未知或矛盾目标拒绝，不能回退另一张表。

名称数组可以是已声明的只读联接列，也可以由生成器自动投影；自动属性不创建配置行、实体存储列、页面布局项或数据库列。存在与自动名称同名的真实业务列仍明确拒绝，不擅自删除或转换。页级目标或名称覆盖若未与同一读取计划绑定，则在写文件前拒绝。

保留原列表、详情、弹层、确认／取消、row[] 回调、字符串 ID、整 entity 回传及 JSON 名称数组单元格。原确认后立即更新可见名称，`changes` 仍只记录 ID；名称仅为显示，保存后由后端重读。该运行时修复未改布局、样式、按钮、菜单或路由。

## 读取和性能边界

- 元数据在生成期和宿主静态初始化时编译，执行阶段不重新解释元数据。
- 普通列表／详情先按固定来源范围完成分页，再合并该页各关系 ID，按 200 个唯一目标 ID 分批读取名称；不是每行一次查询。
- 目标项目和软删除范围独立检查；源行不会因目标失效而丢失，名称按 ID 原顺序保留 null 位置。空选择显示空名称数组。
- 名称筛选使用数据库中的 `JSON_CONTAINS`／`EXISTS`，业务文本参数绑定并转义 LIKE 元字符；不使用序列化数组文本 LIKE，不让联接扩大分页或 COUNT 的基数。
- COUNT、分页和完整范围统计使用相同筛选。只有显式按名称数组排序时才启用预编译数组表达式。
- 普通读取沿原快照语义；保存、复制后的私有回显使用真实事务当前锁读。外部请求不能提交当前读开关。
- 双连接专项已证明：RR 快照建立后目标在另一连接改名，普通读仍看到旧快照，当前读返回已提交的新名称，故障后源变更整体回滚。

以上为实现及专项验证范围，不是 Java／C# 同条件性能结论。批量补名有明确额外往返，性能总验收仍须执行。

## 保存、导入和导出

写前仍验证真实身份、候选页动作、目标父、项目、软删除及所有 ID。普通显式选取沿原目标 list 权；省略字段不主动重选，父依赖变化或复制仍复核。输入兼容数组与旧已编码 JSON 数组文本，null、空数组、省略保持各自语义；重复、非规范或溢出 ID、数字数组、超过 200 项及越界候选拒绝。

Excel 沿原 JSON 名称数组。整行按已编译物理父依赖解析，属性顺序不能决定目标父；每个名称必须唯一命中实际范围。空值、追加、按首列覆盖复用正常 Service 事务；第二行失败撤销整批。真实导入动作只由私有生成方法传递，来源只授 import 时不借用 create／update 或目标 list 权。

非冗余多选导出从已授权来源的保存 ID 派生当前名称数组，独立窄投影保留原列、筛选及 selectedIds。下载继续由共享导出服务签发票据，不新增接口或操作。目标表改名直接影响非冗余读取，不表示冗余消费者的名称传播已经实现。
