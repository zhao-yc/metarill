# V926 同合同明细导入的 redo 写入线程对照

2026-11-10。对照 MySQL 8.4.11 的 `innodb_log_writer_threads` 开启与关闭。沿用 68af5319 的固定 C# 镜像及相同的原 Java、Redis 和工作簿环境，两组先开后关，分别使用 Server-200 的独占 MySQL 和相同存储设备。23 项启动实测设置中只有写入线程不同。两组保留 ROW／FULL、`sync_binlog=1` 和 `innodb_flush_log_at_trx_commit=1`，均关闭 binlog 压缩。 [MySQL redo 写入线程](https://dev.mysql.com/doc/refman/8.4/en/innodb-parameters.html#sysvar_innodb_log_writer_threads)

每组 1,200 个正式请求和 32 个预热。12 个窗口的两端真实普通身份、响应、业务资源和两端各 4,928 条物理新增明细均通过独立复核。每个窗口的前后均读取线程设置，两组共 48 次设置核对。应用逐语句观察关闭，数据库统计在请求计时窗口外读取。两个工作簿只归一化八个合成编号后，内部 10 项内容摘要一致。对应窗口中两组各自的 INSERT、缓存来源读及缓存更新计数一致。
