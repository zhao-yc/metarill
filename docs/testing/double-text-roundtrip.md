# double规范文本、默认值与固定条件证明

日期：2026-11-02。编号：A27。起点：`ba3c17f5159d8ca3e9b15a8c1982b9a6ec812b70`。仅修复有限double在文本桥中的失真，保留原界面、请求／响应字段、JSON数值类型、字符串ID、权限策略、事务及元数据归属。

## 在数据库连接之前定位根因

当前固定Windows x64、SDK 10.0.402／运行时10.0.13的新进程，在未读取设置或连接数据库时得到：

| 原位型 | 当前R文本／默认JSON文本 | 将该文本回读后的位型 | G17文本 |
| --- | --- | --- | --- |
| 0410000000000000 | 4.104536801298376E-289 | 040FFFFFFFFFFFFF | 4.1045368012983762E-289 |
| 040FFFFFFFFFFFFF | 4.104536801298376E-289 | 040FFFFFFFFFFFFF | 4.1045368012983758E-289 |

独立Python IEEE位型及高精度十进制计算也确认，上面的二次幂是2^-958，两个原值实际不同。A25／A26观测到的文本与二进制输入差异现进一步定位到客户端格式化阶段；原实测结果保持，但不能据它们认定MySQL把正确文本解析错。

这是一组对当前固定环境的实际复现，不推断所有.NET版本均存在同一问题。Microsoft的Double格式说明也建议需要可靠往返时采用G17，见[Double.ToString说明](https://learn.microsoft.com/en-us/dotnet/api/system.double.tostring?view=net-10.0)。A26仍然必要：已固定驱动在文本参数路径中自行使用R，平台统一格式化器不会改写该驱动；浮点参数继续沿其二进制准备路径。

## 源头修复

ExactNumericValue.FormatDouble统一有限double文本：先按原R格式生成，再按原位型回读校验；验证相同则保持原文本，仅失真时回退G17。已有0.1、1.5及显式数字字符串的正确短文本保持，不能为解决边界值而改变正常数值的原规则语义。

| 消费路径 | 当前合同 |
| --- | --- |
| 平台／独立宿主／MCP的共同JSON选项 | FiniteDoubleJsonConverter用已验证文本输出JSON数字；显式WriteAsString继续输出字符串，null／Optional省略语义及非有限拒绝保持 |
| MySQL默认SQL及结构指纹 | 默认常量和相等比较使用同一规范文本，相邻值不再共享错误指纹；零默认仍归一0，decimal保持原精确通道 |
| C#及原详情默认值 | 两处生成源头调用统一格式化器；只修正数值字面量，原模板节点、样式、控件与交互保持 |
| 原只读规则的double行值 | 合法字段比较使用可靠文本，不把上值变为下值而错误判为可写；原0.1等BigDecimal比较语义、非有限错误类型和受限语法保持 |
| 固定目标条件证明 | SameConstants比较使用包含有限double转换器的私有JSON选项，不能把两个不同常量计划证明为相同；字段类型、绑定与授权来源不变 |

未开放double常量控件：其现有生成门槛仍拒绝该组合，不能因为内部通用导入表达式存在就宣称完整支持。普通double导入仍保留原数字／数字字符串单元格及原列名，不增加字段或新操作。

## 失败与校准记录

- JSON实际红灯0通过／4失败；结构红灯1通过／2失败，准确复现位型丢失及指纹碰撞。只读规则最初夹具误用原语法不支持的指数数值字面量，不能将该编译拒绝算作数值故障；随后独立编译ba3c17f的原规则源码，以合法score > threshold比较真实复现应只读却为false，当前同向量正确。固定条件证明另有真实相邻值碰撞红灯。
- 只读规则保留原受限语法，没有放开指数字面量或原生脚本。正常0.1合同仍精确验证；曾试用全面G17导致1.5e100旧短文本断言失败，最终改为先验证原文本、仅必要时回退，没有缩小位型期望。
- 尝试double常量导入夹具在正式生成前即被原类型门槛拒绝；保留该失败，改验已支持的普通double数字／字符串导入，未修改ImportRenderer或放宽能力。

## 升级、回退与未完成范围

已有C#应用成套更新Core／Data和生成器，通过原CLI／在线助手同步运行时，并正规再生成有double默认值的Service／详情；手写partial保护保持。没有新源码文件进入SDK，只更新已有ExactNumericValue、转换器及规则／条件模块，旧目标不能只更新调用新方法的某个文件。

仅修正应用JSON和数值文本不自动执行DDL或回填。已有库默认值若与预期位型不同，应重新预览原结构差异，审查后按原显式流程处理；本轮未修改任何旧库。回退需匹配整套运行时及生成产物，回到旧格式化状态会重新引入已测的输出、默认值、只读规则或条件证明风险。

格式化增加一次回读校验，尚未量化同条件延迟／吞吐及分配成本；不能宣称性能不退化。实际持久表DDL／COLUMN_DEFAULT反查、完整CRUD／Excel及关系／文件事务、真实身份／浏览器、跨端与性能继续验收，A17／A23、V09及MySQL首版不因此整体完成。
