# 固定开发平台基础定义升级工具

此工具只处理2026-10-30核实的Server-200 metarill_dev开发平台缺口：一个文件内部期限字段、四个普通索引及其十三条配置元数据。不属于普通生成CLI，不随独立应用下发，不在服务启动或页面点击时自动运行。不得拿它升级生产、其它项目或任意SQL。

## 命令与范围

先用已登记SSH核对Server-200主机/IP及实际MySQL UUID。私有设置必须明确指定该开发库，源根必须是当前已验证的Metarill发布源。不要把连接串、口令或旧批准复制到命令。

- preview --settings 私有设置.json --source-root 源根 --server-uuid 本轮UUID --plan 新审查计划.json：只读实际实例、十三个全局标识（包括墓碑）与五表结构；计划文件只能新建。
- apply --settings 私有设置.json --source-root 源根 --plan 已审查计划.json --confirm-sha 审查SHA256 --receipt 新回执.jsonl：明确获准后执行。先在当前状态重新预览，摘要/目标/源/结构或缺口改变即停止，再沿SchemaService执行相同五条以内新增DDL，随后沿MetadataRepository在事务中只补这十三个元数据对象。
- verify 与apply参数相同：只读独立核验十三条记录和结构零差异，不执行修复。

实际启动为项目 .NET SDK运行编译后的Metarill.PlatformFoundationUpgrade.dll，参数按上列顺序或明确键值传入；--help只显示用法。普通平台CLI、Web接口、元数据表单及页面交互不变。

## 写入与失败边界

计划包含固定profile、UUID/库名、四份发布元数据源摘要、十三个对象的逐条摘要和实际前后结构指纹。只允许新增可空datetime(6) upload_expires_at和四个固定非唯一索引，不允许改列/删表/改索引/覆盖或复活配置。计划未知键/重复键/任意SQL/多余对象/无确认摘要均拒绝。

apply不会执行审查文件里的SQL文本，而是从同一固定源与实际库重新预览，再比较完整计划并调用同一SchemaService实例。维护调用为每次实际结构连接额外固定UUID；普通SchemaService调用继续原先预览/执行绑定规则。工具单独关闭连接池保证阶段和独立核验使用新物理连接，不改变私有配置文件或TLS设置。

DDL先于配置，不承诺分布式或DDL回滚。配置事务先锁有效平台项目，再按固定顺序锁十三条主键保留（包括墓碑），全局标识已有即停止，不跳过或覆盖。窄种子只访问三个配置表，写后按原物理类型逐字段核对；空数值引用写null，字符串空串保持。配置十三条一起提交或回滚。

回执在任何写库前以CreateNew创建并逐阶段强制落盘。失败保留已确认DDL数量、可能已生效的在途语句或配置提交不确定状态，禁止盲目重跑、全量种子重置或自动DROP回退。最终成功须关闭首会话，再新建会话从实际库核对十三条和零结构差异；实际执行后还需单独进程verify与平台原用例复验。
