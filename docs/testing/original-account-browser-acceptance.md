## 实测退出缺口与修复

原平台 `common/yzp.js` 沿用公共运行时的本地清理退出，没有调用 C# `POST /api/admin/sys/yz_manager/exit_login`。独立 SQL 终审发现本轮普通账号仍有一条未注销会话，原失败记录保留。不能把“回到登录页”当作服务器已注销的证据。

平台适配与独立应用 `frontend-yzp.js.tpl` 现在保留原按钮、确认框和路径：确认后携带当前会话调用原 C# 注销接口，成功才清理本地身份、发出原 onLogout 并返回登录页。取消不发请求；服务器拒绝不伪装成功；旧确认框及迟到响应不能清理后来登录的身份。页面、样式、布局和标准生成模板没有改变。

修复后重新经 HBuilderX 发行，在同一个 Ego Lite 验收空间重新登录，验证同一令牌退出前可读当前权限、原退出确认后被服务器以“登录超时”拒绝，刷新仍在登录页。独立 SQL 按该轮会话摘要核对唯一会话已经逻辑注销；原始令牌只在单次验收进程中使用，没有落盘。

旧缺口留下的测试账号会话在确认账号与角色均已软删、名称/主键/创建者/项目属于本轮后，仅逻辑撤销精确一条；另开连接确认该账号活动会话为零。该测试清理不是修复后浏览器退出证据，不清理其它账号会话，不声称全部操作者历史会话均已盘点。
