# selfTree 自动物理名称列

原级联 selfTree 只配置叶子 ID 时，平台会派生同前缀名称物理列。Metarill 的共用 `CascadeTreeStorageColumns` 现将这一规则用于结构计划、基础设施行存储及 C# 生成，保留原页面、组件、样式、控件和交互。派生仅是编译结果，不插入配置表、不新增页面字段，也不在启动或生成时执行 DDL。

## 定义与优先级

只为普通冗余实体表、非虚拟非联接、字符串/int64 的 `_id` selfTree 全局字段派生 `_name`。定义必须为无重复键的有效 selfTree 形状，使用 id 主键和 blank 根；页级覆盖不能派生数据库列。非冗余、视图/函数表、布局、其它模式及损坏定义不猜物理列。

自动名称是可空 string，不继承 ID 的默认值或必填状态。字符串叶子继承配置长度，空长度按原规则使用 50；int64 ID 扩展的名称长度使用 50。已显式配置的名称始终优先，包括长度、类型、虚拟或大小写冲突；不把冲突配置悄悄改成合法物理列，正式写入/读取编译仍会报告缺口。

派生字段使用由表、来源字段 ID 与列名确定的稳定内部标识，保留前缀不能由显式元数据占用。同一声明重排或重复编译不改变定义。物理计划复制快照，运行时基础设施仓储构造时编译一次，不逐行解析级联元数据。

## 结构与业务

预览仅产生差异。对缺名称的已有表，显式应用添加可空列，核验结果后才使用新生成服务。原数据保留，不自动回填旧行、不缩窄或删除既有列；需要特殊长度时先显式配置名称元数据。已有物理定义与期望不兼容时仍按现有结构安全边界拒绝。

生成实体/Mapper 与结构计划使用同一名称定义。最终 Service 继续当前读验证路径、计算名称、处理默认值/省略/null/复制及事务回滚；严格 DTO 不接收名称，原完整表单仅允许只读 echo。VO 的隐式叶子名称和 DisplayText 沿[隐式名称合同](cascade-tree-implicit-name-contract.md)，导入导出沿[Excel合同](cascade-tree-excel-contract.md)，没有新增输入或请求参数。

## 更新与剩余范围

已有 C# 应用先配套更新 Core/Data 的共用规则，按元数据预览结构，确认后显式执行并核验，再重新生成 Entity、Mapper、Service、VO、Controller 和相应运行时后构建。无需新增名称配置记录或页面字段，手写 partial 不覆盖；禁止只替换某个 DLL 后跳过结构核对。

跨表级联、来源父范围、非冗余级联、全局名称传播继续实施。用途 SQL 整体投影、原浏览器/设备、同条件性能与 MySQL 完整首版尚未完成，64 层/候选单层 500 项边界及 FullApplication 门槛保持；不合并 main 或部署生产。
