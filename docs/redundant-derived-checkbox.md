# R1 数据库复选的派生名称缓存

日期：2026-10-28，对应进度 B95。开发起点 `dd42db4`。本轮完成固定 MySQL 子集，复杂关系整体仍按进度表继续。

## 原协议与实现

普通 R1 来源的 `MultiCheckBoxDatabase` 现在可以缓存普通 R0 目标的单值派生字符串名称，包括 `target.name = company.name`，以及继续经过 R0 中间节点的 `company.name = brand.label`。实际缓存仍为同前缀物理 `_names` 数组，显式及自动辅助列采用同一证明。

候选和保存仍按来源页原动作授权；候选可由 list、create、update 任一已开放动作访问，不借用目标列表权限。原父记录、真实项目、软删除、表单 segment 与固定 status 条件继续生效。保留原复选组件、全选、只读和整 entity 回传，5000 项完整选择与 5001 项拒绝均不截断。

**Excel 保持原合同：R1 导入／导出使用 ID JSON 数组；R0 使用名称数组并校验可逆性。派生缓存不会把 R1 改成名称导入。** 名称由保存事务内的当前读取派生，客户端伪造缓存无效；省略、null、空数组和原隐藏默认值验证保持。

名称、关联切换和软删经统一混合传播／原维护计划执行，数组具备独立反向依赖，普通标量审计缓存参与同一事务。消费者缓存更新不重新调用其 Service／观察器。旧 RR 快照后实际重选读取最新名称，旁路 SQL 本身不发事件；显式原维护可按已存 ID 修复缓存，重复执行零变化，不修补源 ID。

补齐两处原映射一致性问题：完全没有有效目标声明时，数据读取器遵循原复选按字段前缀定位；已明确表或页时，旧单项提示不再参与目标匹配。坏表／页、冲突、虚拟缓存、凭据及未证明名称仍在发布前拒绝。四段配置前两项继续不参与查询。

## 边界与升级

固定普通身份的生成 HTTP 不代替正式宿主登录、原浏览器、跨端或同条件性能。未重跑文件全量。全局派生目标、数组作为标量中间路径、非字符串名称及未证明配置继续拒绝，整个多值／复杂关系不因此全部完成。

只在 Server-200 既定隔离业务库建立随机前缀样本，逐组核实例、结构及行摘要后清理，并用独立连接确认不存在；不使用旧四库租约扩展新数据库或账号。

既有应用需成套更新 Core、Data、生成器及运行时，保持元数据为源头，预览并显式同步必要物理缓存列，再生成并构建；原维护页按权限显式回填。普通启动不 DDL，不自动转换或清空存量数据；回退成套恢复版本并核对绑定与物理缓存，不自动删除业务列。
