# V384–V389 同父共享锁的触发器可见性证明

2026-11-06，产品基线 `8ac6ea2`，隔离 MySQL 8.4.11。普通运行账号没有触发器权限。仅在随机样本内创建不能登录的定义者账号，并对单张明细表授予 `TRIGGER`。运行账号只额外获得该只读例程的 `EXECUTE`，视图或例程均不返回触发器正文。MySQL 的定义者对象与调用者权限分别检查。 [MySQL 8.4 存储对象访问控制](https://dev.mysql.com/doc/refman/8.4/en/stored-objects-security.html)

| 轮次 | 结果 |
| --- | --- |
| V384–V385 | 定义者视图没有给出有效可见性证明。同表确有已知触发器时，普通调用视图仍返回空可见性，独立管理查询可见。 |
| V386–V387 | 定义者自身也需要该例程的精确执行权。补齐后，受限运行账号通过只读例程看到同表哨兵及真实写父触发器，撤销表级触发器权后证明失败。 |
| V388 | 例程在定义者上下文内可同时读取该表的直接授权和 INSERT／UPDATE 触发器存在性，无需同表哨兵。普通账号原查询仍隐藏触发器，定义者视图也未提供直接授权证明。 |
| V389 | 复验撤权及真实触发器后，在无相关触发器的同一明细表验证共享锁。两个事务各自先固定明细元数据，再取例程证明与同一父键共享锁，分别插入并提交。并发父更新在持锁期间超时，释放后成功。 |

当子表已在事务中固定元数据时，另一个连接创建触发器等待超时，释放后成功。安装的实际 INSERT 触发器确实写入父记录，例程将它标记为存在。撤销定义者精确表级权限后，例程返回无证明状态。样本运行账号不能创建触发器或替换视图。所有独占库、账号及所有权记录均从新连接独立确认清理。

这轮确认了共享锁所需证明的一个实现方向。产品仍执行原排他父锁。接入前需核验部署端例程定义与所有者，处理部署权限变化，逐项排除其他写父入口，验证缺例程或失去证明时回到原路径。共享锁与完整应用同条件性能尚未复验。
