## 发布和执行边界

- 来源必须在当前发布目录明确声明 `scopeKind=global`、R1、普通实体，具有真实非空 int64 主键，完全没有 `yz_project_id` 列。表、字段、页面和后台归属必须一致；不能以缺字段推断全局许可。
- 本批只接原物理 `List` 单值外键，允许 string/int64。目标和名称复用现有全局发布证明；名称副本必须有真实物理列和精确单层路径，不能是任意联接、凭据、虚拟字段或页级关系覆盖。
- 完整目录存在这一来源时，生成 Service 固定当前 Actor 项目等于发布项目，目标事件也受约束；超级身份不跳过目录身份。维护读取计划及其投影、传播入口在发 SQL 前拒绝项目覆盖。
- 来源 SQL 按真实全局实体省略不存在的项目列，保留软删除、真实主键和页条件；原按行项目范围的模型继续原路径。没有给来源补假项目字段。
- 隐式名称副本参与原响应、保存后的混合传播及维护计划，不增加列表/详情控件或可写字段。完整传播与维护计划未覆盖全部副本时，生成阶段整体拒绝。
- 子页的原父键必须对应已证明的 List，写入检查真实父记录并取当前锁，候选仍使用原父上下文；不将目标页列表权限附加为新的父操作门槛。文件父范围复用同一发布证明，锁定实际父键、活动状态和规范 ID，不读取虚构项目列。

普通 R0、无发布证明、跨目录、多值、级联、任意额外全局联接、精确管理范围等不因本批而扩大支持。
