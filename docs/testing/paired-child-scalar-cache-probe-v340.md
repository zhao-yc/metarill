# V340 同父导入缓存回写的数据库片段对照

以当前分支 `5b3234bd` 的精确缓存锁读、条件写回和物理核验为比较依据。Server-200 使用新建的独占合成表和仓库固定的 MySqlConnector 2.6.1。片段测量由本机测试进程直接连接已核验的测试实例，完整应用接入和正式同条件计时待完成。

候选用一次驱动发送依次核对库身份、读取来源旧值及目标当前值、按真实主键条件更新、读取实际物理值。目标条件来自相同的规范字符串主键查找与活动范围。更新比较将两端文本转换到同一编码后按字节核对，保留尾空格、大小写及 null 区别。两次发送的对照先取得预期文本，再以参数执行更新和读回。

- 8 个 SQL 用例覆盖大小写及尾空格、显式空值、软删目标、非规范外键、软删来源、无变化及缺失来源。非严格模式下实际截断仍能由预期值与物理值的差异识别。
- 独立连接先建立旧快照，再更新目标。可重复读的候选仍取得最新目标，目标保留共享锁，来源保留排他锁。另持有两张表的相关排他行锁，错库查询无命中、无写入、无锁等待，正确库对照等待超时。
- 可重复读下，缺失目标在锁读后不能被另一事务插入。读已提交下，同一竞争会使更新看到锁读时尚不存在的目标。接入需要可靠证明当前事务的隔离级别和已发布结构，无法证明时保留原路径。
- 实际驱动验证三个结果集、0／1 行更新、空结果和截断读回。两段读取间没有共享会话变量。列、表、主键和条件在正式接入时必须来自同一个已发布编译计划，写回前后仍须校验实际库身份、行数和物理值。

四个连接争用同一个父记录，每笔事务插入并核对 8 行。两种路径共 8 个预热事务和 192 个计时事务，三组交错运行。每笔数据命令由 25 次降至 17 次，事务提交单列于驱动命令计数之外，所有事务的提交时间均计入下表。
