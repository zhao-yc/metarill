# V633 恢复快照中的 Web 与 OAuth 会话处置

2026-11-08。固定产品 `5c8fcb823491e2e25029ffa40cb2cfdc851c0abb`，沿用 [V632](current-cross-instance-backup-restore-v632.md) 的 51 份 Windows Production 宿主和两个 MySQL 8.4.11 实例。源及目标实例 UUID 不同，各使用自己的专属库、账号、Redis 和回环转发。全部会话由原 Web 表单和 OAuth 设备流签发。

| 环节 | 实测结果 |
| --- | --- |
| 活动快照 | 源保留两条有效 Web 会话、一条已退出的 Web 会话、一条有效 Agent 访问会话、已批准刷新授权和一条待批准设备授权。停机后恢复 24／13 张表及两份本地附件，目标原业务读回一致。 |
| 隔离目标复用 | 两条未注销的 Web 会话分别读取客户详情和受保护附件，Agent 原访问令牌可读取身份，原刷新令牌成功轮转并签发新访问令牌。已退出的源 Web 会话仍被拒绝。 |
| 目标离线撤销 | 确认目标停机后，事务撤销两条 Web 会话、一条当前 Agent 访问会话及已批准、待批准两条授权，并清空旧刷新摘要。第二次影响行数为 0／0。已有注销时间及已消费刷新重放记录保持。独立源连接复核源会话及授权不变。 |
| 恢复后重新访问 | 旧 Web 会话按原 R500 拒绝，旧 Agent 访问为 401，旧和已轮转刷新令牌返回 `invalid_grant`，旧待批准设备码返回 `access_denied`。新 Web 登录和新设备流可用。原公开及受保护文件权限和字节正常，新会话按原入口退出。 |

两端共 50 个原 HTTP 请求符合预期。最终目标无活动 Web 或 Agent 访问会话、待批准或已批准授权，旧重放记录保留。独立确认两个 MySQL 和 Redis 容器、专属目录、端口、SSH 转发、本机临时配置及附件副本均已清理。

本轮覆盖隔离恢复目标的离线处置流程。原产品的日常会话策略保持按既有入口执行，实际发行环境的身份库清单需按其部署组合核对。处置命令见 [安装与恢复](../mysql-first-release-install.md#恢复快照中的会话与授权)。
