# MySQL 全新空库验收

固定测试库上的表复用只能证明兼容性，不能证明首次安装。此工具为每一轮创建4个全新随机库（平台、平台业务、独立应用、非冗余独立应用）和一个仅拥有这4库权限的临时账号。执行前及每条 Docker 命令前均核对 `Server-200 / 192.168.31.200`，Docker 固定远端 Unix socket，不使用本机 Docker。

## 执行

需要现有 `server-200` SSH 开发授权，以及容器 `yinzon-mysql` 内可用的管理员环境凭据；管理员密码只在容器内读取。没有该权限时工具失败，不能改用既有库来伪造首次安装。

```powershell
pwsh -NoProfile -File scripts/acceptance/fresh-mysql.ps1 `
  -SourceSettings E:/git/metarill/.local/test.settings.json `
  -DotnetPath E:/git/metarill/.tools/dotnet/dotnet.exe
```

`SourceSettings` 只提供既有开发连接的网络/TLS选项，工具用新随机数据库和受限账号替换数据库及认证字段。凭据通过 SSH 标准输入或子进程配置传递，不放入命令行、版本库或输出；临时配置在数据库清理成功后删除。本轮 TRX 与构建/测试日志保留在 `.local/fresh-install/<随机编号>`。工具另核对TRX必须3项全部执行且通过、0跳过，完成远端清理后写入不含凭据的 `result.json`。

离线清理保护回归不需要服务器或数据库：

```powershell
python -m unittest discover -s tools/acceptance -p test_server200_fresh_mysql.py
```

## 验收断言

- 独立应用：全库0表；普通宿主启动和 `--schema-preview` 后仍0表；当前Full实际包的 `--schema-apply` 从元数据创建业务表、三张文件基础表及六张安全基础表（本单业务表夹具共10表），再单独执行 `--initialize-security`；再次预览无差异，重复apply/初始化无额外对象或密码重置；实际HTTP认证、上传、生成业务页保存文件引用及下载成功。
- 平台：两个目标库全空；普通启动不执行DDL；显式 `--initialize` 创建平台元数据结构、种子元数据、管理员及示例业务结构；重复执行不重复种子、不重置密码；通过真实网页登录、管理员权限和菜单回读。
- 非冗余独立应用：从单独全新空库构建实际完整包，显式结构安装及安全初始化后，以 Production/Web 持久身份验证生成 CRUD、精确范围、原导入导出及受保护文件链路；与冗余独立应用分别计一项。
- 所有产品表均来自当前元数据和产品结构同步器，工具只创建数据库和授权，不手写产品表结构。

## 清理边界

远端仅记录本轮实际成功创建的随机库/账号，不保存密码。任何既有同名对象均拒绝复用。清理必须匹配本轮编号和所有权清单；创建中断只清理已经证明成功创建的对象。未知库名、账号或清单状态均停止，不能扩大DROP范围。

正常或测试失败均执行 finally 清理，且只清理本轮临时账号和4个随机库。若连接中断导致清理失败，保留私有临时配置和远端所有权清单供恢复，不宣称验收完整成功；恢复后仍须精确按清单清理。该工具不操作现有 `metarill_test`、`metarill_business_test` 或生产数据库，也不进行应用部署。
