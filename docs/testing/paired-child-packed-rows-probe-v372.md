# V370–V372 同父明细导入多行命令对照

2026-11-06，基线 `66eb8c9`。使用同一隔离 MySQL 8.4.11、MySqlConnector 2.6.1、可重复读、父排他锁、表结构与八行批次。逐行组使用 V365 同包 SQL。多行组先执行同一首行，再在一个命令中逐行发送后七行。两组均保留父候选重验、明细排他锁读、目标共享锁读、单条插入、原缓存更新表达式和物理读回。仅写入命令由 8 次降至 2 次，另有事务开始、父锁和提交。

V370 首轮在更新计数判定 SQL 的语法校验失败，未进入计时，测试资源已独立清理。V371 修正后实测四连接交替执行三对，每组每轮 24 批，共 144 批正式、8 批预热，最终 1,216 行核对父键、缓存、金额和活动状态。另有四组完整字段对照，包括超出 JavaScript 安全整数范围的 ID、空值、空串、四字节字符和尾空格。

V371 在回滚前就验证候选拒绝、缓存截断、重复主键和 CHECK 失败均阻止后续物理写入。候选拒绝后也未读取被其他事务锁住的后续行。错误库名阻止写入，SQL 异常后同一连接开始新事务可正常执行，全部负例回滚后零残留。

V372 在独占表安装实际触发器并使用同一个固定父键。首行改变父候选后，第二行拒绝，第三行未写入。第二行触发父名称变更、缓存发生截断时，第三行同样未写入。另补齐原活动范围语义：若触发器让新插入的明细立即成为软删除记录，原逐行命令与合并命令都接受插入、不更新该行缓存，下一条活动行仍成功。每个事务回滚后，独立连接核对明细零残留和父记录恢复原值。V370、V371、V372 的独占资源均已独立核零。

多行命令具备进入完整应用候选的性能信号。计时来自 V371 驱动对照，未对 V372 追加的活动范围分支重测；当前产品和首版结论仍以 [V366 双端正式回放](paired-child-parent-write-batch-timing-v366.md) 为准。

生成应用默认注册文件写入观察者，它即使遇到无文件字段的表，也先检查页面与表归属。完整应用接入必须保留这些校验和原逐行失败优先级，并为自定义观察者与守卫回退。另需核验报文预算、连接重置和触发器写会话变量时的边界，再以原 HTTP 工作簿及 Java／C# 同条件回放复验。
