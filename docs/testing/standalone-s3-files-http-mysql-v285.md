# V285 独立应用 S3 附件、权限与 MySQL 验收

2026-11-05，从固定产品源码 `250aab9` 使用公开 CLI 重新生成五表合成模型的 730 文件完整应用，严格发布 69 文件 Production 宿主。两轮使用相同的前端、宿主和 202 字节合成 ZIP。Server-200 运行独占 MySQL、Redis 和同存储镜像的 SeaweedFS，应用以固定配置经回环转发访问新桶。

| 场景 | 实测结果 |
|---|---|
| 真实身份及上传 | 原表单登录建立普通账号会话，核对页面权限与非超级角色。上传计划返回 S3 和 `SERVER_MULTIPART`，实际 multipart 上传及完成通过。公开响应未暴露存储键。 |
| 引用及读取权限 | 匿名下载返回 401，普通账号在绑定前解析返回 403。通过原页面更新路由绑定后，详情和解析回读同一文件，下载原字节一致。HEAD 返回 202 字节长度与空正文，`bytes=1-4` 返回 206 及正确的四字节。 |
| 写入拒绝与回滚 | 删除仍被引用的文件返回原 HTTP 200、业务码 500 及明确提示，原对象保持可读。用未完成上传的文件替换附件并同时改名，返回 401。独立 MySQL 核对原名称、两项级联及独立国家 ID、原附件字段与有效引用全部保持，独立 SDK 读回同一 S3 对象、核对长度与 SHA-256。 |
| 解绑、删除与撤销 | 原接口显式清空附件并删除文件，SQL 核对文件与引用的逻辑删除、附件字段为 NULL、未上传计划仍为 planned。独立 SDK 确认桶中已无对象，删除空桶后用新客户端核对 404。原退出撤销会话，原令牌访问列表返回 401。 |

复验共 21 次应用 HTTP 请求。初次预检因本机端口无法绑定停止，尚未创建任何资源。首轮已通过上传、绑定、授权读和 206 Range，随后测试错误期待引用删除应返回 HTTP 500，正式结果保留为失败。复验根据当前产品明确区分 HTTP 200 与业务码 500，保留业务拒绝和对象不变断言，产品及页面未变。

两轮正式资源均通过新连接核对。独占 MySQL 库、临时账号与所有权记录、隔离 Redis、SeaweedFS 容器、IAM 配置及 SSH 转发已清理。脱敏的请求时序、应用回执和物理读回保留在 `E:\git\metarill\.local\s3-application-v285`。

本轮覆盖生成独立应用的真实 S3 附件 HTTP 链及 MySQL 引用和回滚。平台库与业务库分离时的 S3 文件链、原浏览器、真机、直传、其他存储品牌和同条件性能分别验收。
