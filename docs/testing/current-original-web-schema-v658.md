# V658 原 Web 表结构同步

2026-11-08。在核验过的 Server-200 使用 V643 的 Linux x64 候选 `31cf5321`、原 H5 和实际 Caddy 同源网关。311 份文件逐项匹配固定清单。平台分库、同库和独立 Full 均显式初始化。结构操作只走分库平台的原管理页面，数据与凭据为独占合成样本。

| 检查 | 实测结果 |
| --- | --- |
| 原页面入口 | 桌面 Chromium 1280×840。通过真实账号登录，从 Metarill 工作区的「表」列表筛选 `config_page`，打开原详情并点击「在数据库创建表」。跳转到该表的预览，显示本轮平台库及一条新增索引的 SQL。 |
| 预览和取消 | 取消原确认框，浏览器没有发出执行请求。随后用新 SSH 和新 MySQL 连接核对目标索引仍缺失，平台宿主审计为空。 |
| 显式执行 | 再次确认只发送一次执行请求。响应与宿主 JSONL 共用原计划 ID，成功记录一条语句。页面自动反查显示「剩余差异：0 项」。手动再预览仍为零，执行按钮禁用。 |
| 物理结构 | 新 SSH 和新连接读取 `information_schema.STATISTICS`。目标 `ix_page_table` 恢复为 `config_table_id ASC, delete_no ASC`，为可见、非唯一、完整 BTREE。共库对照仍有原索引，业务及 Full 库无该平台索引。目标表的 21 条配置和 ID 合计前后一致。 |
| 核零 | 原账号退出后无活动会话。独立核验本轮容器、网络、MySQL 库、账号、凭据与转发已回收，浏览器只清理本轮回环来源。 |

浏览器脚本在识别预览文案和手动重新预览时曾超时。读取同一页面后继续，保留了原登录和原计划，执行请求未重发。

缺失索引由验收夹具在核验归属后的独占平台库预置。结论覆盖当前 MySQL 候选的原入口与一次成功的增量结构同步，实际发行环境按 [安装与恢复说明](../mysql-first-release-install.md) 单独验收。
