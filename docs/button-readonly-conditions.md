# 原业务按钮只读条件（C21）

本项补接 `VisibleWhenWritable` 业务按钮的服务端只读条件。产品解释器与精确数值比较均在C#中执行，Java用于开发期离线对照。原页面、样式、按钮和请求 JSON 保持；Web 中央入口与 Agent 从实际生成 Service 读取原记录后，共用同一固定条件判断。当前只完成执行前检查的本地验证，不代表全部页面只读、普通 Agent CRUD 或生产身份/数据库矩阵已完成。

## 发布与执行

- `AgentHostCatalog` 从已验证元数据冻结 `readOnlyCondition`，发布时编译为有界语法树，绑定本表已声明的物理字段及现有命名别名。未知字段、歧义、赋值或方法调用不发布该业务按钮；不会把失败解释为空规则。
- 普通 `Normal`／`AlwaysVisible` 按钮保持自身按钮权限，不统一附加页面修改权限或只读条件。`VisibleWhenWritable` 继续要求真实页面 update 权限及发布的 CanUpdate。
- `AgentActionBinding.RequireRecordAsync` 先证明原记录范围，再由 `AgentButtonVisibility` 读取所需的生成属性。不能使用客户端 entity、visibleScheme、visibleRuleJson、新值或元数据后改覆盖发布快照。
- 条件为真时在执行租约和业务回调之前抛出对象规则错误；不可可靠转换、缺属性或未装载派生字段也明确拒绝。规则不读取未声明 getter，不把数据库 JSON 字符串重新解析为对象。
- 原无记录函数表保持原 Java 路径，不新增记录读取和条件判断。本项未对其真实业务作新验收。

规则只是执行前预检。业务事务中的当前状态、锁、权限、文件和对象规则仍须由已有事务入口核验；本项未证明状态在预检与业务锁定之间变化时的完整矩阵，不把条件判断当作事务约束。

## 原受限语义

实现对照原 `YzpAgentReadOnlyGuard`，不执行 JavaScript。支持字段、`entity.`／`this.entity.` 前缀、null/布尔/字符串/普通十进制字面量，`!`、括号、`==/===/!=/!==/>/>=/</<=`、`&&/||`。非空条件语法长度4096、512令牌、32层嵌套；只读条件单次数值文本上限65536，超限拒绝。

与或两侧均完整解析和求值，缺字段不能藏在未命中的分支中。与或保留原操作数供外层比较，不能提前全转为 bool。两个字符串按 UTF-16 文字序比较；严格比较不把字符串/布尔隐式转成数字；宽松比较及数值序比较沿原 BigDecimal 标量规则。空对象/数组为真，空白字符串本身仍为真。

指数形式只允许出现在可转换的数值字符串中；原词法不支持 `1e3` 数值字面量。函数、方法、赋值、原型/反射字段、未知路径与不可靠对象转换仍拒绝。JSON/Map 路径的核心对照不等于所有生成实体嵌套对象均已装载。

## 共用精确数值修复

`JavaDecimalNumber` 为显示规则和只读条件共用数值比较，保留各自不同的字符串、空白及失败策略。按符号、有效数字和数量级比较，不经 double/decimal，不分配巨大指数数组。

原 Java 对照发现旧显示规则仍按 int32 指数和 ASCII 数字判断，实际出现4个差异。现按最终 BigDecimal scale 判断合法性，允许 `1e2147483648` 及小数位抵消后的 `1.0e2147483649`，超出最终 scale 的值继续原显示规则的文字回退；Unicode十进制数字按原数值处理。新增5个公开相邻反例，原显示规则共66组原 Java 对照通过，只读条件64组通过。

## 证据与接入

公开向量及调用器分别在 `tools/acceptance/read-only-condition` 与 `tools/acceptance/button-visibility`。调用器直接反射执行冻结原 Java 方法，不复制解析器。原源码去除换行/BOM差异后与冻结 V8 模板一致；执行的三份只读守卫类及显示规则类逐字匹配原样板 JAR。实际运行环境为 JBR25.0.2，调用器以 Java21 release 编译；不据此声明所有 JDK 已验。

真实完整包先将 `amount` 只读字段和可写按钮写入元数据，再正规生成、安装原手写样板并严格构建。使用包内真实 Controller／Service／Business／DTO 验证 Web 与 Agent 拒绝、当前记录改为可写后的允许，以及原中央路由的 HTTP200/R500 和 R200；身份、ORM传输和租约决策仍为明确离线夹具，不代表 Production 登录、OAuth、MySQL或并发已验。

完整包受管更新必须成套带齐 `ReadOnlyConditionRule.cs`、`JavaDecimalNumber.cs` 与 Agent 模块；同时裁源码及包清单也应拒绝，目标保持不动。旧目标可预览成套运行时升级。无表/字段变化，无DDL、回填或手写partial迁移；客户端资源无需因本项单独替换。
