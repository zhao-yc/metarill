# 原 V8 页面首批 C# 接口兼容

本切片仅调整后端生成源、Core 合同和既有权限/文件更新开关，不修改原页面或前端生成模板。原页面 PC/移动端布局、组件及整实体回传继续保留；菜单单表树是已经明确的结构调整，不在本合同恢复旧双菜单表。

## 完整实体回传

原详情 `getEntity` 把整个 VO 赋给 `entity`，保存和删除直接提交该对象；新增初始 `id` 为空字符串，子页保存前回填父外键。生成 Controller 在真实页权限及 Actor 验证后，使用编译为常量的 `LegacyPageWriteContract` 把旧请求转成原严格 DTO，再调用原 Service。

- 只有固定页可写字段进入 Create/Update DTO；删除仅保留 `id`。
- 当前页已声明可读字段、常量 `*Show` 和已知只读辅助名称只作回显并丢弃，不能覆盖服务器保存值。Multi 名称继续由源事务派生，省略 IDs 不刷新历史名称。
- 新增 `id` 只允许 null/空白，不能指定主键。实际主键仍由服务器分配。
- 父实体键只能等于本页真实 `parentId` 上下文，项目键只能等于真实 Actor 项目；未知字段、重复字段、伪项目和跨父均拒绝。客户端不能提交白名单、表名或 SQL 改变合同。
- DTO 的 `Optional` 仍记录省略与显式 null；HTTP 适配使用宿主相同 JSON 转换器。原 DTO 自身仍拒未知字段，手写 Service/MCP 不依赖这个 HTTP 归一器。

生成写 Action 使用固定 `LegacyPageWriteRequestAttribute(typeof(严格DTO))`。现有 Agent/MCP 能力目录从此标注生成原 DTO schema，保留 `additionalProperties:false` 与可选字段/null，不把 Controller 的原始 JSON 输入公开成任意对象。项目当前没有 OpenAPI/Swagger 入口；未来加入时也应复用同一标注。

## 候选与排序

原选项 `findNameId<来源字段去Id或Ids后缀><列ID>` 路由保留，已有按目标表名派生的路由作为同 Action 别名继续可用；分页和已选端点同样保留两种固定命名。目标表、列、页、控件范围由元数据编译，不能来自请求。

本轮仅覆盖已安全编译的 List 关系，未把 MultiCheckBoxDatabase、Cascade 或未实现表达式泛化成通用候选接口。旧数组端点接受空 POST、`{formParameters}` 和只读字段的 `{id,formParameters}`。明确 `id` 走已有同范围已选回读；显式空 id 返回空数组，不退回全量候选。外项目、软删或范围外 id 整体拒绝。返回仍是 `id/name/value/text`，64 位 ID 保持字符串。有父范围的旧请求仍需明确传页面已有 `parentId`（不改变 UI），不能因空 POST 丢失父限制。原 `formParameters` 仅作为已知请求键接收，本轮不解释未实现的动态表达式；无法安全编译的条件继续明确拒绝。

来源页和目标页仍使用现有权限校验，本轮没有通过放宽查询权限补偿未完成的授权继承。数组超过 5000 条仍明确要求分页，不截断。原 `uni-th` 取消排序发送 `order:null` 或空字符串时回到固定默认排序；未知非空方向仍拒绝。

## 更新与不分页开关

`PageUpdatePolicy.CanUpdate` 集中解释原 `isUpdate` 和 C# `isSave`。原显式 `isUpdate` 优先，因为 DTO 默认 `IsSave=1` 且再序列化会输出它，不能把该默认值误认为用户显式配置冲突。非法值拒绝。后端方法生成、子页能力、角色动作资源和文件上传统一使用该规则；前端生成器由完整恢复切片使用同一规则。

仅服务器已发布元数据 `PageSize=0` 的页面允许 `pageSize=0`，且请求页码必须为 1；在数据库查询前检查。该分支不添加 LIMIT，完整返回所有满足原页面范围及筛选的记录，不静默截断；`size=0`、`pages=0` 保留旧不分页响应。普通页面传 0、负数或超限分页请求继续拒绝。大型不分页页面的资源使用由明确配置负责人承担，不把客户端 0 当作任意页面绕过限额的方法。

## C115 Agent 新增必填描述

新增能力通过真实生成 Controller 的严格 DTO 获取属性集合。页面固定必填按生成 JSON 名与实际属性匹配，并与 DTO 自带的必填声明合并。例如物理列 owner_ID 的新增参数是 ownerID。主键、当前项目等由服务端提供的字段排除在调用方必填清单之外。带默认值、初始值及条件必填的字段继续由原生成流程处理。

基线 c7fa61d9 的真实新增 DTO 已接受 ownerID 并保持长整数精度，能力描述却要求 owner_ID、id 和 yzProjectId。另一 MVC 夹具复现页面必填写入时覆盖了 DTO 自带的 JsonRequired。修复后两项同夹具回归通过。15 项生成及原页面写合同和 114 项 Agent 回归通过。API、CLI 严格编译，717 个受管文件再生成一致。正式 Web 验收按进度表跟踪。

## C116 Agent 新增父级与归属

生成动作从新增服务使用的固定物理父级和账号归属提取实际 DTO 字段。能力描述据此允许省略请求体中的父键与账号归属。例如子页仍须传查询参数 parentId，门店页从认证快照取得 storeId。显式提交的归属继续经过原校验。普通固定必填和 DTO 自带的必填继续从各自来源合并。

基线 c6096ad2 的真实生成 MVC 合同曾同时要求请求体内的 parentId 和 storeId。修复后实际生成 DTO 可省略两字段，父级查询参数仍由能力目录列为必填，普通业务字段仍必填。生成与原页面合同 53 项及 Agent 114 项定向回归通过。API、CLI 严格编译，717 个受管文件再生成一致。正式 Web 验收按进度表跟踪。

## C117 Agent 子页请求体父级

Agent 能力目录根据已发布页面范围与 MVC 请求体属性，在子页列表、计数、原 Excel 导入及导出的请求体上将 parentId 标记为必填。导入的 requestJson 仍独立必填。新增与详情的实际父级仍走原查询参数。普通页的固定条件仅含父变量字样时继续按普通页描述。

基线 1007e784 的生成 MVC 列表动作接受 parentId 请求体属性，但生成子页的 Agent 能力未在必填清单声明它。修复后编译并从 MVC 发现普通页和子页，逐一核对四个请求体动作和新增查询参数。实际生成和原页面 44 项、Agent 114 项通过。API、CLI 严格编译，717 个受管文件再生成一致。正式 Web 验收按进度表跟踪。

## C118 Agent 列表和导出排序

Agent 列表及导出根据生成控制器的固定描述公开实际排序列。生成服务和描述使用同一组开放字段。请求仍通过原 orderBy.column 或兼容 orderBy.field 传实际 JSON 名，方向为 ascending 或 descending。例如物理列 owner_ID 的排序字段是 ownerID。省略排序时使用页面原默认顺序。页面没有开放显式排序时，Agent 描述只公开其余输入。

起点 7848f507 的生成列表和导出只公布通用排序对象。修复后三个实际 MVC 生成模型覆盖冗余、非冗余、无显式排序及未发布字段排除。79 项生成与固定查询、114 项 Agent 回归通过。重新生成平台和演示共 717 个受管文件，两轮结果一致，21 个控制器排序标注和两份归属清单的对应摘要进入提交。API 和 CLI 严格编译。已有业务应用按同版生成器再生成后可使用新描述，正式 Web 验收按进度表跟踪。

## C119 Agent 实际页面筛选

生成列表、计数和导出公开本页固定筛选键及其值形状。标量按实际 JSON 字段名描述，长整数可用十进制字符串，日期区间为两个端点，原布尔复选保留 0/1，关联数组使用对应 ID 类型，级联节点只开放已发布层级键。名称筛选使用生成查询实际识别的辅助键，冲突缺口不进入能力描述。当前账号、项目和父级条件仍由既有入口和服务处理。

基线 bd6b24fe 的两个存储模式及普通页三个生成模型均只公开通用字典。更新后从真实 MVC 读取三个动作的字段与布尔、日期、大整数形状。84 项生成及相邻筛选、114 项 Agent 回归通过。最终复验实际跨表节点、歧义名称排除、复选和两独立完整包。API、CLI 严格编译。21 个控制器标注和两份清单摘要随 717 个受管文件两轮再生成一致。正式 Web 验收按进度表跟踪。
