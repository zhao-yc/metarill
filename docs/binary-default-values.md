## 固定合同

明确 logical binary 的非空默认文字沿公开请求合同填写 Base64，例如 AP8Afw== 对应 00 FF 00 7F。默认框留空仍表示无默认值，与既有 string 等类型一致；不是新增SQL表达式输入入口。不接受 UNHEX、十六进制SQL片段、JSON数值数组、无效Base64或超过配置字节长度的默认值。

Core 的 DefaultBytes 统一生成器和结构适配器的解码与长度检查。生成器在输出前拒绝无效默认；普通创建时缺省字段取得默认，显式 null 和零字节不被默认覆盖。每次创建重新分配数组，修改一次创建的返回字节不能污染下一次默认；部分更新省略继续保持旧值。

MySQL适配器把固定字节编译为 X'00FF007F'；longblob 使用 (X'00FF007F')，varbinary 使用字面量。SQL只由已验证字节编码产生，不经过字符集、反斜杠或任意函数。BLOB表达式括号的规则见 [MySQL 8.4 默认值文档](https://dev.mysql.com/doc/refman/8.4/en/data-type-defaults.html)。

## 反查和保护

- 只归一明确 0x 偶数十六进制或 X'偶数十六进制'，大小写与一层表达式括号不造成重复差异；指纹比较按真实字节区分。
- 只对明确可变长二进制类型、精确 EXTRA=DEFAULT_GENERATED 且确认为上述常量时解除默认值保护；函数、混合EXTRA、未知字符表达式及生成列不放行。
- 结构草案把明确字节还原为Base64默认，再正向编译验证零差异。不把SQL片段误当业务默认文字。
- X'' 是零字节物理默认，不能丢成“没有默认值”。现有元数据没有独立“存在默认值”标志，此类源结构明确报告不能无损表达，未增加新输入规则或控件。固定长BINARY的填零、任意函数默认及其它数据库并未由本任务开放。
- 新 MySqlBinaryDefault 源文件纳入当前完整候选必需清单；旧目标可按原按钮同步运行时并再生成，手写 partial 保护不变。候选删除源码与清单条目不能绕过完整性门禁。
