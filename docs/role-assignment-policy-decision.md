# 角色管理权限的待确认边界

平台需要沿用原页面和权限流程。原V8的静态调用链按页面新增/修改权限授权；账号写守卫验证全部角色属于合并后的目标后台，但未另设“仅超级角色才能绑定超级角色”的检查。已核对资源模式拦截器、管理员Controller、页面写执行器和写守卫；尚未实际通过普通账号HTTP授予超级角色，不能把静态证据写成已复现越权。

当前C#仍保留平台配置页仅平台管理员的门禁。普通账号管理功能不会因接通复选控件自动开放。下面是开放前的两个明确选项，须按用户“操作变化先确认”的要求确认后实施。

| 操作 | 建议收紧方案 | 原V8页面权限方案 |
| --- | --- | --- |
| 普通账号已有账号新增/修改权限 | 同真实后台普通账号，只分配或撤销普通角色 | 继续按页面权限与同目标后台角色校验 |
| 绑定/撤销超级角色或修改超级账号 | 需要对该后台有管理权的超级管理员 | 不另增加超级身份门槛 |
| 普通账号修改角色超级标志 | 拒绝 | 继续按角色页修改权限校验 |
| 业务后台超级角色管理平台或批准Agent | 拒绝 | 也不因接通角色控件授予平台权限 |

“收紧”会影响原先依赖账号/角色页修改权完成超级角色分配的普通账号；原页面、按钮位置、复选和全选方式保持。确认不会自动给任何账号新增页面权限。角色不得直接搬后台、有引用不删等原有规则继续保留。跨后台迁移须另外证明来源及目标管理权，不能把“本后台超级”当成任意后台权限。

独立于本决策的工作继续推进：真实身份后台与开发工作区分开、工作台目录归属、事务锁序、锁后当前读撤权、已发布目录版本冲突，以及固定控件/VO/旧协议适配。角色能力缺口仍未关闭。
