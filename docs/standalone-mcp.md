# 独立应用MCP接线与验收

## 目标与当前边界

平台及完整应用共用 `Metarill.Mcp` 的固定强类型页面执行器。该工程只引用Core、Security、ASP.NET Core与已固定版本的MCP SDK，不引用平台Runtime、API、生成器、设计器或Agent实现。平台原元数据/结构工具仍由平台提供；原 `call_generated_page` 工具名、六操作、parent参数、强DTO字段存在性和确认要求继续。普通应用不获得平台设计器或任意SQL入口。

完整应用新增同路径 `/api/mcp` 的Stateless Streamable HTTP，使用同一已核编译目录、实际生成程序集与原Web/Agent认证管线。显式Development身份不发布该MCP，缺配置/匿名请求在工具及数据库服务构造前拒绝。BackendOnly仍不包含该正式宿主和MCP。

## 工具合同

| 工具 | 行为 | 权限与边界 |
| --- | --- | --- |
| `list_generated_pages` | 当前允许的固定项目/页面标识、名称、表名及动作 | 每次重新按当前身份页权过滤；不返回连接、SQL或隐藏默认值，Agent仅列出读取动作 |
| `call_generated_page` | list/detail/create/update/delete/copy，调用原生成Service | 先验证真实持久身份及页权；写入必须明确confirmed=true；DTO拒绝未知字段，保留省略/null；原parent、取消令牌及对象规则继续 |

服务类型、命名空间、程序集和方法只来自宿主注册的可信目录。客户端不能提供类型名、源码路径或自报项目权限；源元数据对象在建立目录后变化也不能扩充该快照。当前工具返回对象使用公共JSON合同，长整数以字符串输出；原字符串结果保持字符串。

Agent的授权项目必须与页面项目一致，MCP写入一律拒绝，即使confirmed=true；写入仍使用已有带UUID、明确确认及任务账本的HTTP能力入口。工具的ReadOnly标记只是协议提示，不能替代服务端逐次检查。菜单可见性也不能替代页面动作授权。

## 更新方式

旧完整应用通过原运行时更新预览/应用流程，配套同步Mcp基础工程、中央NuGet版本/依赖、宿主引用、McpIntegration与Program；不直接修改已生成业务Service或原页面。平台需同步新公共工程及原工具适配后重编译。没有新增数据库表、元数据或DDL，不改变原界面、样式、交互及手写partial；现有Agent基础结构仍按其独立安装要求审查。
