# R1跨表名称缓存传播与维护（B60）

本批补齐固定R1跨表链的物理字符串名称传播与原维护后端回填。原uni-app页面、样式、交互、接口、模板和平台元数据保持原样。R1重复来源写入、物理联接名称、全局目标、R1跨表Full及其余复杂组合继续保留门禁，不能据此宣布整个复杂关系或MySQL首版完成。

## 固定编译与执行

各级缓存由同一个跨表写入计划登记，绑定稳定控制列ID、层key、真实ID列、目标表／名称字段和来源缓存字段，不按表名或后缀猜测角色。支持已证明的固定普通同项目R1链、字符串／int64来源ID和父键，以及默认name或自定义物理字符串caption。自定义目标仍写原prefix_name辅助列。

Data独立校验完整固定链、层标识、前缀、项目、物理列、父键关联、标量类型和唯一缓存归属；拒绝重复JSON键、额外SQL范围、全局／派生／凭据／数组终点及不匹配绑定。普通RelationCacheDefinition保留原六参数构造，未设置的级联属性不进入原JSON，旧普通关系不能借自定义名称别名绕过证明。R0实时名称不登记物理缓存。

传播在目标新增、名称修改、置null、软删或物理删除的原Service事务内完成，仍在尾部观察者之前。按实际外键反查当前项目活动来源，分批最多128行当前锁读，只写缓存、不改关系ID、业务和审计字段，不调用消费者Service／业务钩子，也不借消费者页面写权限。各层同ID属于不同表的角色分别取名；缺失／删除目标产生null名称，原ID保留。字符串ID使用规范精确匹配，不把尾空格历史值当成同一引用。

每批缓存写回后统一核对实际存储值，核验成功才进入下游队列；非严格MySQL静默截断或实际值不符会使目标、前批缓存和下游副本一起回滚。自动传播每批回读一次；维护单行写回沿同一核验器处理。直接标量缓存由普通传播唯一处理，明确联接下游仍沿原混合传播队列执行。

原维护入口继续根据每条记录已经存储的各级ID独立重算名称，不修补ID或把错误父路径改成另一条路径；坏／空外键按原读取规则得到null。标量计划不使用多值数组预算或把叶子控件伪装为List。跨批失败整笔回滚，重复回填无变化返回0，不在启动自动回填。

## 省略字段与来源图

关联ID省略时，原归一化仍保留关联输入及缓存；如果同时修改的字段本身就是目标名称，新反向传播会在同一事务刷新引用它的缓存，包括该实体自身。来源图原用例因此由“保留旧缓存”改为核对实际新名；关系ID和路径选择规则不变。这是本批新增的一致性行为，不是请求省略字段等同显式null。
