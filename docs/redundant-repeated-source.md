# R1重复来源跨表写入与缓存（B61）

本批接通固定冗余（R1）来源在跨表根／中、根／末、中／末及三层同时出现的后端组合。原uni-app页面、样式、交互、模板和接口保持。各层ID及名称仍物理存储；不将R0的单槽稀疏存储或实时祖先投影搬到R1。

## 角色与真实存储

生成时分别证明每个层key、字段前缀、真实父键与名称终点。来源与目标均为普通同项目R1，支持物理字符串name，以及来源不同角色使用各自物理名称字段。名称和真实父键必须与受管ID／名称槽位分离；页级角色覆盖、全局／非冗余目标、受管槽位兼任来源条件或父范围仍有独立门禁，不静默覆盖业务意图。共享辅助字段与其他组合仍待继续补齐。

同一表、同一数值ID或同一实体不代表同一层角色。固定层数的路径可在多个角色引用同一既有实体；角色分别解释名称字段及父字段，不按自树循环误拒绝。新建自身仍拒绝。缓存绑定沿B60控制列ID／层key证明，不按表名合并；发布能力清单明确标识重复来源，R1跨表Full仍未放开。

来源更新先以受信待存实体协同名称／真实父键，再以正常DML后的SQL范围和真实路径复核。R1单来源与重复来源现在都会比较本次提交的真实父键存储值；非严格MySQL截断为另一条有效路径也必须整笔回滚。没有补写修复DML。修改父键却省略关联、使原缓存ID与实际路径不一致时仍拒绝；明确一起提交选择才能协调保存，这延续原R1单来源合同。

省略关联而修改目标物理名称时，B60反向传播会按各消费者已存ID刷新相应缓存，包括自身多个角色，不改其他消费者的外键。原候选／路径使用真实层key，中文key与字段前缀独立；分页、总数和空页筛选按已存物理ID，不把其他消费者的祖先ID自动改为最新路径。

各级名称传播、目标软删／恢复及维护回填加入原事务；133个固定消费者跨批核验，消费者业务钩子／通知不重入。R1部分选择保留各级ID与名称，只清后段；复制按原生成流程。原维护按各级已存ID重算缓存，保留其他业务／审计值及ID；重复执行0。测试不赋予新观测权限或改变服务器全局模式。
