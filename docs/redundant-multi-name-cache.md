## 存储与写入合同

- 沿原存储政策：冗余表中的 `isJoinColumn=1` 名称列仍是物理缓存；非冗余同类名称才是只读投影。不能因为有联接标记就忽略物理列，也不能因此放行任意派生写入。
- `MultiSelectPage` 和普通 `MultiCheckBoxDatabase` 共用固定缓存证明：必须是同一来源 `_ids` 的名称辅助列、非虚拟物理字符串，且未另声明独立关联；原路径只接受 `来源前缀.目标字段` 或 `来源完整_ids.目标字段`。空路径、其他来源、跨层路径、虚拟列或独立关联继续拒绝。
- 目标名称继续受原控件的固定类型、可读范围及权限约束；本批没有打开非字符串、全局或复杂派生名称的额外组合。
- 缓存只由生成 Service 重算，DTO 不开放名称写入，原整 entity 回传仅剥离已声明只读回显。新增、复制、已选 ID 或相关依赖变化复用原事务；缓存的 JSON 数组 VO 和元素筛选保持。
- 手写规则修改缓存名称、所选 ID 或真实父依赖时必须登记提交字段。未登记变化拒绝；已登记缓存变化也从已验证目标重新计算，不能保存规则自行拼出的名称。
- 隐藏来源字段不能取消内部证明；Full 包在写文件前拒绝没有可执行读写规则的冗余多选。未知物理联接仍由原保护拒绝，不开放通用任意路径写入。

原页面、布局、组件、样式、弹层／复选／全选、候选权限和接口字段均未改。原普通缓存、非冗余和账号角色专用路径继续保持各自边界。
