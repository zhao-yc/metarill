# 非冗余共享跨表生成 CRUD 与原完整包（B76）

2026-10-27，起点为 B75 提交 `57b98e3`。本批把已证明的整组稀疏存储接入生成 Service、原详情页和独立源码包；仅支持下述固定组合，整体复杂关系和发布验收继续。

## 固定接线

`SharedCrossTableSparseMutation` 是单笔请求、单个共享组的状态，分别保存原始物理 ID、按需恢复的旧逻辑路径和本次规范化后的预期路径。它不跨请求缓存目标，不把非冗余原始祖先空位当成真实业务上级。

- 创建、更新、复制先保存原始快照。部分更新在 DTO 合并前恢复实际独立末端对应的原逻辑路径，手写 `BeforeSave` 只执行一次；钩子即使未登记组内字段，也识别实际变化。
- 钩子后整组协调，再校验依赖共同上级的普通 List。只更新这种 List 时，按需恢复旧逻辑上级供校验，并在持久化前恢复原始物理位；不重打包或重复存储省略的组。
- 改变共同上级自动清空受影响的其它下级；同父的独立城市、仓库可以共存。两个主动选择产生冲突时整笔拒绝。
- 每组只打包一次，保留不能从其它分支推导的末端 ID。共同祖先和名称不重复存储；来源物理表没有名称缓存列。
- 正常 DML 后、通知之前，先核对实际物理 ID 与身份范围，再在当前事务内恢复实际路径并与写入前预期比较。失败直接回滚，不通过补写掩盖差异。
- 复制先验证原始稀疏集合无歧义，随后使用同一组协议；文件／业务观察者加入原事务，尾部失败回滚整笔来源写入。

旧值／最终核验的目标读取不要求候选 list 动作，主动新选择保留原候选授权与固定范围。无关业务字段的更新不额外读取整组目标；明确全清不要求坏旧目标仍可恢复。整数／字符串 ID 保持精确类型和原字符串 JSON 协议，null、空字符串与省略分别处理。

## 保留原前端与生成归属

页面、布局、组件、样式和整 entity 请求沿用原工程。共用上级的事件清理复用用户确认的规则。短控件的主字段本身也是另一个控件的祖先时，仍显示为原可操作控件，不能被非冗余派生字段判断隐藏。

生成 `.g.cs` 及详情事件来自元数据和生成器，手写 partial 再生成时保护；不修改平台和示例既有生成文件。不含共享组的原生成输出应逐字稳定。完整包使用同一 Core／Data／Runtime 接线，本地更新器必须能预览、应用、重复不变并保留手写内容。

## 当前范围与剩余边界

普通 R0 来源，两个具有一致共享前缀的固定跨表控件；四种所选键／父键交叉、两种短主叶以及固定派生目标为本批模型。独立物理或固定派生目标按已有证明使用，不宣布所有混合目标组合均已验收。

共享 R0 来源父范围、精确数据权限、页级改变存储定义的覆盖仍明确拒绝；全局、来源直接／间接自参与、其它拓扑与下游复杂派生／维护用途继续沿用已有门槛。单控件旧稀疏编码器继续拒绝共享，不能逐控件覆盖整组物理位。

已有无共享组项目无需 DDL。新共享模型仍须按元数据预览结构差异、执行并核验；不启动自动改表，不把历史全路径数据自动转换为稀疏集合。同步运行时并再生成配套后端与原页面，手写 partial 保留。
