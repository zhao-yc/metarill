# 原时间控件的数据绑定与浏览器验收

日期：2026-10-29；进度编号 C40；起始源码 ae3c19d。按用户确认修复时间输入异常并保持界面，改动位于 C# 原详情生成模板，不手改可覆盖页面。C38 固定包及其待批单库范围保持，真实 TIME 持久化仍待正式验收。

## 问题与结果

原时间模板给 uni-easyinput 传入 model-value，但没有接收其 update:modelValue 事件。使用 HBuilderX 实际构建、在 ego lite 打开原 H5 详情后复现：微秒值 11:22:33.123456 可正常显示；不改值保存、打开 picker 后取消再保存均保留原值。点击原清空图标后输入框已空，原保存请求却仍含旧时间，造成视觉清空与整 entity 提交不一致。该失败来自受控 API 的真实浏览器请求载荷，没有连接数据库。

模板现将输入/清空事件与原 picker 的选择事件交给同一字段方法；该方法只在页面仍有效且字段可写时赋值。不解析、截断、补零或过滤文本，明确空字符串交给既有 C# 清空合同，无效非空文本交给既有后端校验。picker、原输入组件、清空图标、显示属性、必填/只读元数据、布局及样式全部保留；未增加按钮或操作步骤。

真实 SFC 解析对照原三字段：只剔除时间字段的事件绑定差异后，整个 template 结构和其他属性一致，全部 style 内容一致。同一份50列/6索引元数据正规 CLI 再生成的8份前端文件中，只有合同详情的内容变化；隔离工程使用该真实归属产物，不作生成后补丁。
