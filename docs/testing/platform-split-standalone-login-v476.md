# V476 分库独立应用登录与账号初始化并发验收

2026-11-07。以 `5a28de19` 为基线，沿用上一轮的 Production 平台宿主。用同一示例项目元数据生成完整独立应用包，发布独立 ASP.NET Core 宿主。平台连接平台库，独立业务宿主只连接业务库。使用 Server-200 本轮独占 MySQL 和隔离 Redis。

## 场景

- 平台的原中央按钮完成首次重置和缺失业务归属的补齐。独立业务宿主普通启动，使用该账号真实表单登录并读取原菜单和角色权限。平台入口拒绝从业务宿主取得的令牌。
- 平台再次更新已保存口令，通过原按钮重置。第三连接持有独立应用的旧会话行锁，先观察平台等待业务库会话，再观察独立业务旧密码登录等待业务项目行锁。释放锁后，旧密码请求收到独立应用原 401 回执，未签发令牌，先前业务会话也失效。
- 用新密码重新登录。第三连接锁定会话主键末尾的插入区间，让另一个独立登录先持有项目和账号锁。在观察到平台直调重置等待同一个业务项目行锁后放行。刚签发的业务会话由随后提交的重置撤销。独立读回验证业务账号 ID、档案和角色保持，平台库无同名业务账号。
- 共库继续复验 V475 两种顺序。两种拓扑保留原末段 CHECK 的故障与重试覆盖。浏览器交互和 Agent 刷新授权规则在 C07 单独跟踪。
