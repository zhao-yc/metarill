# V470 JDBC 语句默认库证据

2026-11-07，在固定 Connector/J 9.7.0 下补齐 Java SQL 采集的逐命令默认库证据。Connector/J 的语句可以在执行时临时切换到语句创建时绑定的库，再恢复连接原库。用连接 URL 或执行前的当前连接库，无法分辨这一情况。

新版在调用原驱动前读取 Connector/J 语句的 `getCurrentDatabase()`。从池代理取得底层语句时仍由驱动原样执行，采集器不发送附加查询。新 Java 索引与请求记录使用 v2。独立预期提供 `source.databases` 时，审阅器要求新版证据，逐条匹配预期库。采集入口同样按本轮独占库校验新版记录。历史 v1 仍可按原预期审阅，其 Java 命令没有逐条库证明。

| 验证 | 结果 |
| --- | --- |
| Server-200 直连 `11f9941f23c14209` | 普通 Statement、客户端预处理和服务端预处理各验证一次。语句在 A 库创建，执行前连接切到 B 库。采集库名和实际 `SELECT DATABASE()` 均为 A，执行结束后连接仍为 B。 |
| Server-200 Druid 1.2.28 `c050a53b5750460f` | 使用项目同版本连接池，实际通过代理验证相同三种执行方式和库切换。 |
| 归档审阅 | Spring 宿主生成的实际合成产物经独立读取器核对 3 条命令和 5 个事务事件。缺少库名、越界库名、错配或降级的 Java 格式均被测试拒绝。 |
| 本机回归 | Spring JDBC、事务及 MyBatis 25 项通过。Java 驱动离线自检 50 项通过，包含无法获得语句库名时保留业务执行并将证据标记不完整。 |

首轮本机严格编译发现一个异常路径的测试替身缺少新增接口方法，补齐后复验通过。首次全组工具回归的三个 cgroup 夹具因 Windows 临时路径过长无法创建。改用短临时目录后，全组 405 项通过，5 项按环境条件跳过。两轮实库资源分别用新连接确认数据库、临时账号、所有权记录及本机恢复凭据已清理。

默认库证据用于约束普通未限定 SQL 的执行环境。显式跨库表引用、触发器等服务端间接访问仍需独立审阅。当前双端完整宿主的正式 SQL 采集、跨语言 SQL 语义、性能与首版发布继续在 [实施进度表](../project-progress.md) 跟踪。
