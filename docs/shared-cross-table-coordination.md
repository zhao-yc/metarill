2026-10-27，提交基线 `371aba1`。用户已确认：多个级联共用上级字段时，修改上级后**自动清空受影响的其他下级**。本批落实普通冗余来源的固定共享组，页面、样式和原控件保持；固定后端／源码包验收已完成；正式身份、非冗余共享存储与整个模块继续。

## 行为与固定范围

例如“国家→地区→城市”和“国家→地区→仓库”共用 `country_id/name` 与 `area_id/name`。改国家或地区会清理另一分支旧的下级；同一国家、地区内更换城市保留有效仓库。短控件“国家→地区”也可与长控件共享其主字段。省略整组不会刷新或写入这组；仅清独立末级保留另一分支；清共享上级会清理受影响的后续字段。整数关联使用 null，字符串关联保留原 null／空字符串形状，所有真实 ID 精确解析，不经过浮点数。

后端以当前事务锁定行捕获原共享字段，DTO 和手写 `partial BeforeSave` 执行后比较实际变化。多个主动新选择分别验证真实路径，再原子合并；冲突时整笔拒绝，不能用最后一个控件覆盖前一个选择。整 entity 中未变化的旧末级不会把新上级改回原值。缓存名称只接受真实目标读取结果。

当前要求普通 R1 来源、固定同范围公共前缀，目标可为独立 R1 物理名称、独立 R0 物理名称或已证明固定派生名称。非冗余 R0 来源的共享稀疏存储／读取、全局目标、直接或间接来源自参与及复杂父范围继续保留门槛；没有简单删除旧拒绝条件来冒充支持。

## 生成、原前端与事务

协调规则由发布元数据编译为固定组，Core 只执行已冻结的槽位和目标读取委托；请求不提供目录、表名、SQL、权限或范围。相同共享槽必须具有相同目标、候选页、名字、父关系、祖先和类型；坏同伴使整组失败，完整包不会单独放过另一个控件。

生成器在原详情事件方法中添加已确认的跨控件清理，原 `yzp-cascade-tree`、DOM、样式、页面模板和整 entity 负载沿用；只读事件仍拒绝修改。后端独立执行同一协调规则，不能只靠前端清理。无共享组时输出原处理方法，普通单控件、独立组不新增运行期协调。

共享组必须在普通关联校验前完成归一化。其他 List／多选等依赖国家或地区的条件据此检查最终父值，不允许先按旧父范围通过再修改父值。正常 DML、已有路径写后核验、缓存传播、下游与通知仍加入同一事务；不重入消费者 Service。

公共名称缓存只登记一次，短控件自己的主字段优先作为该缓存的规范控制列，保持原维护计划完整。目标改名及派生终点变化继续向来源和下游传播；原维护执行器只回填名称，不改关系 ID，重复执行无变化返回 0。
