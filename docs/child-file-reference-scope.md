# 子页面文件引用的父范围证明

文件模块现在支持发布元数据中可证明的父等值范围，例如 `yz_project_id=@current_yz_project_id AND parent_id=@parent_id`。语法沿用生成器的严格子集：仅声明的物理列、`AND`、项目变量及 `@parent_id`/`@parentId`；未知变量、复杂 SQL、虚拟列、父定义缺失或不支持的身份类型继续拒绝。没有修改 Core、生成器、HTTP 参数或 RecordMutationContext。

## 实际记录与发布定义

FileReferenceScope 只读取 FileMetadataContext 的发布快照。父目标优先使用明确 LinkConfigTableId；没有此声明时，仅接受与生成器一致且唯一的 `table_name + "_id"` 对应。父必须为已发布实体表，具有64位整数主键及明确项目字段；逻辑删除字段若存在必须有效。父键来自同一事务锁定的实际源记录，客户端 parentId 不参与授权。多条父条件必须对应同一个实际父 ID，与生成页单一 parentId 语义一致。字符串/整数身份使用明确参数类型，长 ID 不经浮点转换。

观察器先核验当前身份、来源页操作权限、源表归属及原事务，再锁定实际源记录并对父记录执行同事务的锁定当前读，验证存在、未删除及同项目；源文件字段随后仍须与通知一致；任一失败令业务行和文件引用一起回滚。源记录软删后的删除通知仍可以解绑全部注册文件字段，前提是其声明父记录仍有效。未提交文件字段保持引用不变。

## 新增隐藏空字段

生成器的新增通知可含全表文件列，即使来源页未开放其中某列。只有新增通知和实际记录都为 null/空数组、且该字段没有有效引用时，才将它作为无效果同步跳过。隐藏非空值、实际值不一致、已有引用及更新通知中的隐藏字段仍拒绝；没有放宽 DTO 或页面写权限。删除继续解绑全表已登记的文件列。

## 事务与锁顺序

观察器的顺序为：已锁源记录 → 按父表名/ID排序的父行 → 原文件ID升序 → 原引用。文件与引用仍通过原 DatabaseSession 加入同一实际连接和事务；没有引入独立事务或自动重试。生成 create 已先锁父再插入新子记录，观察器仅在同事务重入已有父锁；普通 update/delete 则先锁实际源记录，再取得父锁。

这不是任意 Business 编排的无死锁承诺。先持父再锁既有子记录的 Business 可能与先锁子再锁父的并发修改形成反序，须由该 Business 明确协调聚合锁序；数据库死锁失败仍回滚整笔事务，不能只重试文件同步。此次没有扩展生成器准备上下文或跨模块锁抽象。

父锁保证本次提交时的父记录证明，不能代替父删除业务的永久关系约束。父在子事务提交后另行删除时，下一次文件提交会重新核验并拒绝。两方向的双连接测试分别证明：父软删先持锁时子保存等待后拒绝；子文件保存先持父锁时父软删等待子提交。
