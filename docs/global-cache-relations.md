## 已实现范围

- 普通 R1 消费者可以引用明确发布的全局 R1 物理字典。List、原 type=1 SelectPage、原 type=2 MultiSelectPage、数据库复选共用完整的表、页、主键和物理标量证明；全局终点不能是凭据、虚拟字段、联接缓存、文件或数组。
- 全局仅改变目标数据范围。来源与普通中间表仍按真实项目、来源父范围及活动状态限制；全局记录的可选项目字段即使属于另一个项目，也不能成为消费者写回范围。生成的全局目标通知使用真实 `actor.ProjectId`。
- 名称和标量副本在目标原 Service 事务中传播；普通 R0 中间节点及 R1 下游使用同一队列、当前锁读和物理预检。只写已证明缓存，不修补 ID、业务值或审计字段，不进入消费者 Service／业务钩子；后批或文件引用失败则整笔回滚。
- 原维护 POST 和配置表选择方式保留，按已存 ID 回填当前宿主项目；没有启动回填、启动 DDL 或请求可提供的项目、字段、SQL／连接覆盖。相同数据重复维护为零变化。
- 复制保留关系 ID，已证明缓存不再从旧实体作为新输入复制，随后在同事务内重算；未知派生写入仍拒绝。该修复位于生成器，不能逐页修补生成产物。
- 修复回填把 MySQL TEXT 默认值的 `DEFAULT_GENERATED` 误判为计算列。反查同时核对真实生成表达式及生成标记；真实 STORED 计算列仍拒绝，结构不一致包含固定表／列诊断，不回显业务数据。
- 原 uni-app 页面、控件、布局、样式与交互保持。List／SelectPage、Multi 的原查询授权继承、复选来源动作、导入 `is_all` 等合同保留；原 R1 复选 Excel 仍为 ID 数组，单值与多选保留名称反查格式。

## 跟进与回退

1. 已有正确物理列不需要 DDL。先审查元数据：普通 R1 来源有真实主键／项目归属，目标明确全局且为同发布项目 R1 实体；目标固定页及名称一致，不能通过表名相似或空归属推断发布权限。
2. 同步同版 Core、Data、生成器及完整包 Foundation，再正规生成相关实体、Service、注册和冻结维护目录；保护手写 partial。需要新增物理缓存的工程仍须独立走结构预览、执行与核验，不能让 ORM 启动改库。
3. 历史值只由用户使用原维护入口审查后回填；本批不在存量业务库自动执行维护。核对本项目、外项目、缺失名称、重复零变化和文件引用；传播失败保持原事务回滚，不自动重试业务副作用。
4. 回退时恢复同一兼容版本的 Core／Data／生成器、生成产物和目录快照；本批无数据类型转换或 ID 重写，不自动逆向回填或回滚其它任务的数据。

全局来源、全局 R0／派生目标、全局 crossTable 缓存级联、共享辅助列、其它复杂依赖、原浏览器和跨端矩阵仍保持独立门禁。平台全局目录管理权限不变，独立应用正式 Web 结果不代表平台全部身份已验收。不合 main、不部署生产；新提交 CI 按具体 SHA 另核。
