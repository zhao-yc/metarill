# V876 当前候选同父合同明细尾延迟诊断

2026-11-10。固定产品 `ffcd80d3`。沿用 V875 的 Java、C#、Redis 镜像、原八行 XLSX、普通身份、最小权限和共同关系索引。诊断使用 Server-200 同一存储设备上的独占 MySQL 8.4.11。提交和 binlog 同步均保持每次持久化。只在隔离实例采集 MySQL 语句、阶段及等待，应用侧逐语句观察保持关闭。

每窗按数据库阶段总时长取最慢五笔事务。C# 父锁读占这些事务所观察时间的 73.6% 至 74.9%。按四并发整窗合计，父锁读时间中 81.9% 至 84.4% 与更早事务的提交时段重叠。三轮提交差异主要落在 `waiting for handler commit`，已采到的 binlog 同步差值随轮次波动。SQL 样本按事务分组，HTTP 与 SQL 只在窗口层比较。

锁内每批八行，两端各执行八条 INSERT。Java 将名称缓存随 INSERT 写入，C# 每批还执行八条缓存 UPDATE 和八次缓存来源读取。本轮账号无直接 TRIGGER 授权，宿主没有配置共享追加证明。源码要求其中一种有效证据才把缓存并入 INSERT。现有证据覆盖服务器语句次数，驱动命令边界未采集。后续优化重点为缩短默认权限下父锁内的缓存写入和核验，并保留触发器、写后物理读回、逐行错误及整批回滚行为。

独占实例的诊断计时中，四并发三轮均触线。MySQL 首版正式门槛仍按 [V875 九类同条件性能](current-mysql-performance-v875.md) 判定。独占 MySQL、两业务库、测试账号、容器、网络、源凭据和私有数据目录已由新 SSH 核验回收。
