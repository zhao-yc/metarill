## 已实现范围

例：原始共享字典 `global_target.name` → 全局R1中间表 `global_source.global_target_name` → 普通项目消费记录。

- 来源仍是有真实项目字段的普通R0或R1实体；List支持既有string/int64外键，type=1单选保持既有int64物理外键和字符串JSON ID合同。
- 中间名称必须是已发布、没有项目列的全局R1实体中真实存储的字符串缓存，声明原物理List及精确联接路径。所有上游目标继续显式global、属于同一发布目录、具有真实主键和目标页面，最终落到非凭据物理字符串。
- 任意join标记不足以取得资格：缺路径/表/页、私有终点、凭据、文件、数组/JSON、虚拟名称、冲突声明、动态全局页条件、循环和超过16层目标缓存依赖均拒绝。证明栈显式传递，不使用静态或线程可变状态。
- 原 `GlobalPhysicalRelationValue.IsScalar` 完全保持严格物理语义；新增受管值证明只接入普通单值名称、非冗余全局别名读取和普通单值冗余传播。全局多值、跨表级联和全局R0实时派生目标未由此开放。
- R0消费记录只保存ID，读取中间表已有物理名称缓存，不为本次读取额外联接最终字典；来源项目、目标软删及字符串外键的二进制精确比较保留。候选/已选/保存继续原页面和控件条件、权限与事务合同。
- R1消费记录的名称副本进入既有普通/混合传播及原维护闭包。实际生成模型同时登记原始字典、全局中间缓存和R1消费者；R0消费者不会因此增加物理名称存储。

这里读的是受管缓存，并非每次查询实时重算终点。静态图及离线代码验证不能证明实库改名已传播；采用前必须验证并回填实际存量缓存。

## 使用、升级与回退

1. 同版更新Core、Data及依赖它们的生成器。目标缓存必须原本就有真实、已声明的R1物理存储及完整全局List维护定义，不能把任意旧字符串列加一个标记后直接发布。
2. 通过元数据入口选择同一已发布目标页和名称缓存；来源保留真实项目，不删除项目字段来绕过范围。单选继续type=1/int64；候选字段和只读名称按原生成链处理。
3. 若目标或R1消费者缺少所需物理名称列，先配置字段，按原“预览差异/SQL→执行→核验”流程同步；R0来源不增加该物理副本。此次仅更新代码不要求对未采用新模型的项目执行DDL。
4. 正规再生成受影响的Service/DTO/VO/Controller和页面，并同步同版运行时/完整包；手写partial保护。模板和控件仍沿原版，不手补生成文件。
5. 经原维护入口核验/回填上游全局缓存，并核验R1下游传播；再验候选/已选、保存/导入、改名/删除、权限与晚期文件失败整笔回滚。未经这些实库用例，不宣布该组合正式支持。
6. 回退需配套回退Core/Data和生成产物，恢复此前不支持的门槛；不自动删除列或数据，不把新缓存数据当旧物理原始名称使用。
