# R0 List 的固定派生名称

本项接续复杂联接 B20：订单通过客户ID关联 R0 客户，客户再通过公司ID关联公司，使用 company_name 作为原 List 的名称。保留原接口、字段名、uni-app 页面、样式和交互，不把派生名称落成物理缓存。

## 修正的执行路径

旧生成器对 R0 来源直接拒绝派生名称候选；简单解除该门禁会让原候选／导入查询对 Entity 的 IsIgnore 名称属性执行物理 SQL。因此本批接通完整的固定名称用途，而非仅删除拒绝：

- 生成校验和宿主静态装载分别编译目标 ID／名称及必要条件依赖，普通请求只绑定真实 Actor、父ID和明确表单标量。
- 三个候选入口沿用原来源／目标页面授权和真实父检查。名称的搜索、排序、COUNT、分页均在固定SQL内完成；旧数组端点超过5000明确拒绝，已选最多200项，导出按200个ID分批读取。
- 页面条件和控件条件作为AND同时保留。新增 FixedConditionSqlPlan.BindVariables／And，只绑定固定槽和组合已有类型计划，不在请求中重新解析元数据；缺变量、类型错误和同字段矛盾类型在执行SQL前拒绝。
- 原中文表头导入按同一范围唯一匹配，数值ID也核对；目标名称使用同事务当前读，第二行失败撤销整批。普通导入不借用新增、编辑或目标列表授权。
- 原导出仍使用实际来源记录的父键／表单依赖隔离名称缓存，通过原票据下载XLSX；未匹配名称保留原ID回退合同。
- 隐藏有效关系只生成内部最终值校验，不额外生成公开候选路由；隐藏默认FK也不能跳过候选范围。非派生普通关系的生成路径保持。

名称属于已授权来源行的逻辑投影。上游外项目／软删除节点的名称保持空值，不以另一项目的名称补齐；目标ID本身的可选性仍按目标行及候选范围判断。不存在的、已删除的或不在当前范围的已选ID整体拒绝。

## 直接验证的模型

验收使用四张独占随机表：订单R0、客户R0、组、公司R1。客户的 company_name 明确为只读联接 company.name；订单可选的 customer_company_name 为只读联接 customer.company_name。客户物理 name 故意使用另一个名称，避免测试误读旧实体列。

两种场景分别是不带目标父／表单条件，以及来源父与目标父同定义、附带 segment 表单条件。每组预置5103个正常候选、上游外项目名称、目标状态失效／软删除／外项目等反例；正常默认范围总数为5104，包含一个名称为空但目标行仍有效的记录。候选ID、所选ID和父ID超过JS安全整数范围，沿原字符串合同。

实际生成HTTP覆盖分页、非首屏已选、百分号／下划线／单引号字面搜索与注入形态无结果、来源及目标撤权、整entity只读名称回传、混合条件重验及回滚。公司通过真实生成更新接口改名后，订单逻辑名称立即变化，物理订单不重写。另验证中文名称导入、重名第二行失败整体回滚、实际原票据XLSX下载，以及在已建立旧RR快照后由另一HTTP请求改名，再直接调用同版生成导入服务成功解析新名。

固定测试宿主建立明确 Actor，仅允许测试头减权；这是实际MySQL与生成接口，不是正式Web认证。完整包实际编译并保护手写partial，原远程关系组件与运行时资源按真实路径逐字比较；没有使用“文件不存在就跳过”的组件核对。

## 验证与原始失败

最终冻结源码`09a1d1dac202d1af03140b43ad111942d06c9e890d86817db909749277d31086`、1239文件：数据层全量330/330、相关生成／实库／包更新138/138、API全量83/83，分别零失败零跳过，不相加为整个生成工程全量。两个完整包真实构建并保护手写partial；正式189输出＋2清单＋24手写共215文件两轮正规生成逐字稳定，CLI／API Release构建通过。原前端488、模板49和元数据9文件按上批冻结逐字核对不变。

本批9组四表样本（含3轮原失败、6轮成功）共36表，完成本批独立只读实例核验并确认全部不存在，没有补发DROP／DELETE。私有证据在.local/derived-relation-names/，包含原始TRX、阶段、失败、随机对象意图、脱敏异常和清理回执。以上实际HTTP使用固定测试Actor；没有新增正式Web／Fresh、原Vue挂载或浏览器／设备／性能结论。

旧派生名称门禁的两个复现保留。新验收中的异步声明编译错误、错误读取字符串分页总数、缺少PageImportException封装，以及误把导出票据当URL的失败均保留，修正的是夹具而非产品响应。有效模型的目标父页继续使用原显式linkConfigPageId，不修改默认页面选择规则。

## 跟进方式与边界

已有应用先同步同版 Core／Data 运行时，再从元数据正规生成受影响Service、DTO/VO、Controller及原页面；通过原三动作的预览和依赖检查应用，保护手写partial、AppID与私有配置。新增方法是运行时依赖，不能只复制生成页而沿用旧Data源码。逻辑名称沿用现有ID和联接定义，不新增DDL、物理名称列或历史回填；配置本身变更仍先改元数据再预览结构。

本批只接通 R0 来源 List、普通R0目标和固定单值字符串名称，目标身份／父及附加条件须为物理标量。全局目标、精确数据权限、逻辑跨表父、平台固定归属、R1来源的派生缓存、SelectPage／多值派生名称及未编译表达式继续明确拒绝或保留既有门禁，不扩称全部复杂联接完成。

尚未完成本模型的正式Web／专属空库、原页面浏览器、跨端与同条件性能；名称缓存反向传播和维护回填仍按B21／B22分别推进。浏览器空间重建确认仍待答复，不以构建或HTTP代替。整个MySQL首版和后续数据库目标均保持，不合main，不部署生产。
