# V490 二进制默认、持久化与原 XLSX 验收

2026-11-07，以 `f3eaca64` 为基线。当前 CLI 为独占合成元数据生成完整应用，三个字段分别使用可空 VARBINARY、可空 BLOB 和非空 VARBINARY，均带非空 Base64 默认值。通过包内源码严格发布的 Production 宿主，在 Server-200 的新建独占 MySQL 和 Redis 上验证真实普通账号。

## 修复的两个问题

- MySQL 的 `COLUMN_DEFAULT` 将实际 `00FF007F` 的 VARBINARY 默认值返回为 `0x`。原快照因此把它当成零字节，建表后的核验失败，阻断空库安装。新空表独立探针复现同一表示差异，`SHOW CREATE TABLE` 保留完整十六进制常量。结构反查现在用同一次反查的建表文本核对明确常量，未知表达式和其它 EXTRA 继续保护。
- 合法 Base64 解码后超过字段字节上限，原导入直到 Service 校验时才失败，返回内部错误。生成器现在在本列解析时检查字节上限，返回 HTTP／业务码 400，并给出行号、中文列名和长度提示。Service 对手写钩子处理后结果的校验继续执行。

## 实际验证

| 检查 | 结果 |
| --- | --- |
| 空库安装与反查 | 显式安装成功，重复预览零差异，实际快照包含完整二进制默认。独立 SQL 确认两种物理类型，省略列直接插入取得完整默认字节。 |
| 真实普通身份 | 原登录和本页普通授权通过，非超级账号。原增改查、相等及 IN 筛选、错误输入拒绝、撤权和退出通过。 |
| 字节与字段存在性 | 原 HTTP 区分省略、null、零字节及非空 Base64，独立 SQL 按 HEX 逐行核对。省略更新保持原字节，显式 null 清空，零字节不触发默认。 |
| 原 XLSX | 原导出入口实际下载工作簿，由原 SheetJS 参数解析。非空及零字节回导落库一致。null 单元格被原解析器省略，重建记录时沿原省略语义使用默认，已逐值记录。 |
| 整批回滚与重启 | 两行导入的末行超长时返回本列输入错误，独立 SQL 确认首行插入也已回滚。重启后原会话和字节读回一致。最终核对八条合成业务记录。 |
| 生成与构建 | 656 文件完整包两轮摘要一致，从包内源码严格发布 69 份宿主文件。平台与示例 215 份既有文件两轮逐字保持。 |
| 回归 | 结构及相邻合同 186 项通过、2 项缺外部配置跳过。真实生成二进制用例 6 项通过，无跳过，包含独立包与手写保护。 |

原版第一轮在安装后的结构核验失败。修复结构后第二轮走到原 Excel 导入，暴露长度错误分类。最终轮次同时包含两项修复并通过完整用例。三轮独占库、账号、所有权记录、Redis 和转发均从新连接独立核清，临时凭据及导出缓存清除。用于确认默认表示的独占空表也已独立核验删除。

本轮覆盖上述 VARBINARY／BLOB 和原 HTTP／SheetJS 链路。零字节默认仍无法由现有空配置框无损表达，反向导入明确拒绝该类默认。原浏览器操作、非冗余关系组合、其它 SQL 模式和同条件性能继续分别验收。
