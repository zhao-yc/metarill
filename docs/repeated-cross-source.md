# 非冗余重复来源角色（B58）

状态：本固定 MySQL 后端／完整包范围已完成（2026-10-24）。冻结源码 `6ce6ad68112bf0307173480a049a7da7f832e02450ee8c78faa6f28b90c9889b`，共 1234 个源码／测试／模板／元数据／前端文件。整个复杂关系模块仍部分完成。

## 对应原语义

原 YZP 的 `CascadeTreeBusiness.validateCrossTableDefinition` 按层 key／前缀区分角色，未禁止来源表重复参与跨表链。本批补同一个非冗余 R0 来源在根＋中、根＋末、中＋末、全部三层出现；名称分别是物理 `name`、固定单值 `company.name` 派生 `display_label`，或首个来源角色使用业务名称而其余来源角色使用派生名称。不同角色不能因为同表、同 ID 就合并 SQL 别名或名称。

真实父字段 `<prefix>_country_id`／`<prefix>_area_id` 始终与稀疏选择位 `country_id`／`area_id`／`place_id` 分开。数据库只保存当前选择最深一层的 ID；SQL 按角色还原祖先与实时名称。原页面、样式、组件、生成模板和整 entity 提交协议保持。

## 实现边界

生成器移除 R0 重复来源的计数门禁，保留 R1 冗余来源重复写入门禁。数据层独立证明各层项目、目标页、物理父外键、固定名称及条件，并明确拒绝用稀疏选择位冒充来源角色的真实父键。能力清单仅在实际固定计划包含重复来源角色时声明 `repeatedSourceRolesSupported`。

写入沿 B57 的受信来源待存覆盖、独立来源名称依赖、存储后实际父键／稀疏位及完整路径复核；不新增补救 UPDATE 或名称缓存。省略关系 ID 而只改业务名称、名称 FK 或真实父键时仍复核当前图。当前名称锁、结构锁及通知都在原事务内；坏范围、存储截断和通知故障整笔回滚。

## 失败证据与计数

最初 32 项因旧门禁无写计划失败；改动后原生成编译通过。数据夹具首轮 49 项失败：重复表默认以表名为 key，夹具未声明独立角色 key，被原结构校验正确拒绝。只补各角色唯一 key 后 55 项通过，未放松结构规则。本批实库样本按真实执行结果记录；编译检查不能记为实库成功。

首轮 48 编译及早期高风险实库、12 Full、后续补强回归独立保留。最终冻结后串行执行 Data、相关 Generation、Files、API、两轮正规生成与构建；每阶段核验摘要。最终 81 个新测试逐项核验，48 个新实库模型的角色／名称／键四维集合恰好完整，不能把早期 16 组算入最终 48 组。私有原始 TRX、冻结摘要、逐组意图／验证／清理和独立只读后验存于 `.local/repeated-cross-source/`，不提交凭据、环境配置、日志或测试数据。
