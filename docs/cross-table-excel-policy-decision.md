# 跨表路径 Excel 的兼容决定

状态：待用户选择，仅说明差异；不据此修改原页面或启用未确认的导入语义。

## 已核实的原行为

本机只读参考为YZP的CascadeTreeBusiness。resolveLeafIdByDisplayText约248—292行：完整层数按名称逐级查找；不是完整层数时，只取最后一段到末级表按名称匹配。queryByName约722行：按配置排序取第一条（limit1），找不到返回空。normalizeEntity会把没有有效选择的各级ID/名称清空。buildDisplayText约351行却会导出根或中间级的已存名称。因此以下是从原源码直接推导的冲突，不是已执行生产数据操作：

- 三层“国家/地区/城市”只选择根“同名”时，导出单元格是“同名”。若城市也叫“同名”，旧导入会选中该城市，不能判断这是根选择。
- 导出部分路径“国甲/区甲”时，旧导入按最后一段“区甲”找城市；找不到会清空整条选择，而不是恢复地区选择。
- 同级重名旧代码按排序选第一条；完整路径中的一段未命中也会得到空值。保留它与严格拒绝/完整往返是不同的数据语义。

当前C#导入仍受未完成门禁，没有用上述旧规则接通真实用户写入。

## 两种可实施的路线

| 路线 | 导出/导入行为 | 对使用者的影响 |
|---|---|---|
| 无损还原（建议） | 完整路径外观保持；部分路径补空层，如“国甲//”“国甲/区甲/”，让导入明确恢复根/中间级。未命中或无法唯一还原时整批报错，不静默清空；旧简写仅在唯一无歧义时兼容。名称含分隔符等无法无损表达的值明确拒绝，后续再扩展转义。 | 页面、按钮和列不变；部分单元格文本和容错规则改变，需要明确确认。 |
| 完全沿用原语义 | 保留原已存名称文本；非完整路径按末级名回退，按排序第一条；未命中返回空并清空各级。 | 与旧算法一致，但部分路径不保证往返，可能选择到末级或丢失原选择。 |

该决定影响的是Excel单元格语义，不是C#分层或页面布局。用户此前要求“其他需要改变接口或操作方式的问题，先提供证据、建议和影响，由你确认”，因此在启用这些差异前请求选择；不把未回答当作授权。

## 不依赖本决定的修复

当前ImportRenderer.Columns直接使用page.Writable，而CrossTableWriteCompilation为原表单把隐式各级ID加入Writable。只读反射已实际确认：页面显式列为amount/name/place_id，当前导入列却额外出现area_id/country_id。修复应让Excel模板继续只含原显式页面字段，保留普通表单DTO的隐式ID支持。

空单元格的内部准备还需按原清空整条选择处理，不能只清叶子后误保留旧祖先；普通表单部分更新的省略/null合同继续保持。来源import动作、数据范围、原事务/钩子/文件同步和当前读锁不能绕过。上述模板与内部准备工作可先继续，完整路径Excel验收须包含最终选定语义。
