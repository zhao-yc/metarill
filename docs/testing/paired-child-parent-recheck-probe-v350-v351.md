# V350／V351 同父导入逐行重验的合并 SQL 专项

2026-11-06，基线 `11a6ded`，MySqlConnector 2.6.1，Server-200 独占 MySQL。V350（`e206f71cd1b635b7`）的探针重复建立子表，整轮未通过。V351（`08c005d149178211`）修正夹具，并将候选继续写成标量查询，以保留物理父键重复时的原错误。两轮均用新 SSH 独立核验库、账号和所有权记录已清除。

V351 首行沿用原顺序取得排他父锁和读取原候选。随后用独立事务修改另一行，验证首行原候选已经建立并固定可重复读快照。在同一事务已持有精确父锁、快照已建立的前提下，后续七行各发一次合并查询。

| 验证 | 实际结果 |
| --- | --- |
| 父记录当前活动、原快照可见、当前固定候选允许 | 合并状态允许，七行均与原候选一致。 |
| 当前父记录软删除或物理删除 | 合并明确判为当前父记录失效。 |
| 当前父记录存在，但旧快照中不存在 | 合并明确判为快照缺父。 |
| 旧快照有父记录，当前候选排除 | 合并明确判为当前候选排除。 |
| 物理表中有重复父键 | 原查询与合并查询均报 MySQL 1242。 |
| 排他锁与回滚 | 竞争连接的 NOWAIT 被拒；回滚恢复父记录、撤销已插入子行，独立连接可重新取父锁。 |

原首行快照不应提前到批级父锁入口。探针也证明，在同一事务执行手写规则可能使原本合格的父记录离开固定候选，前置计算的候选结果不能跨该规则复用。接入生成器时需保留首行原顺序，仅对已证明无中间变更的后续行合并，并在原校验位置处理快照和候选拒绝。宿主自定义 ORM、全局过滤、动态候选和其他父范围仍需原校验路径。

严格构建零警告、零错误。本轮验证数据库片段和接入边界，尚未将它接入生成器，未测完整应用吞吐。首版性能仍按 [V348](paired-child-transaction-start-timing-v348.md) 判定。
