# binary 逻辑字段：生成与离线验收

日期：2026-10-30；起点 1a8f4a5，本任务同提交。对应进度 C42。仅接通明确声明为 binary 的字段；既有 string、文件库、图片控件和原前端不改变。

## 合同与实现

- Entity／DTO／VO 使用 byte[]?，HTTP／Agent／MCP 的字段文本采用 System.Text.Json 原生 Base64。请求 schema 表示为字符串及 Base64 编码，不再错误描述为整数数组。
- 部分更新继续使用 Optional：省略保持原值，显式 null 清空，空字符串表示零字节。禁止用 JSON 整数数组、无效编码或任意对象绕过输入合同。
- Service 在手写 BeforeSave 后按实际字节数校验；超过配置长度即回滚，不依赖驱动截断，也不按 Base64 字符数计算。数据库 NOT NULL 与页面必填保持独立：前者拒绝 null，后者另拒绝零字节。
- 普通生成筛选保留原空筛选处理，非空单值／IN 使用字节参数；非冗余读取同样按已发布 logical binary 接收 byte[]，不得使用文本 LIKE；冻结时复制可变字节数组，调用方后续改写不能影响 COUNT／明细绑定。基础设施 SqlRowStore 也保留 null、空字节与原生 byte[]。
- 原已存在的 MySQL 结构规则不改变：未填长度是 longblob，明确长度是 varbinary(n)，空白长度沿既有 255 回退；结构反查草案保持逻辑 binary。物理长度范围仍由 MySQL 适配器负责，不在 Service 判断数据库品牌。
- 原 C# Excel 写出器已经将 byte[] 输出为 Base64 文本；本任务接通生成字段和导入解析。导入错误采用固定中文分类，不回显原值或底层异常。没有把二进制值改为图片。
- 当前候选包必须包含 BinaryFieldValue 源码；旧目标允许预览升级，但须显式同步运行时，保护手写 partial，不能删掉文件及清单条目绕过完整性检查。

原 Java 生成类型映射没有明确的 binary 分支，落入 String；其通用 Excel 写出器的 byte[] 图片分支不能证明普通 binary 字段已经完整往返。本任务没有自动迁移旧项目、改变原字符串字段或宣称所有旧二进制输入均等价。

## 已知边界

- 基础批次 e11ee13 曾在生成前拒绝非空数据库默认值；C44 已接通 [非空 Base64 默认的离线双向合同](binary-default-values.md)。零字节默认仍无法由现有空框无损表示，真实 DDL／反查与 HTTP 持久化未验，不计完整支持。
- JSON 省略／null／零字节已经分离。原 XLSX 空单元格及原前端解析可能不能区分 null 和空字节，未引入新标记或改变列／交互，整文件空值往返仍待原链路实测。
- 非空参数的离线 SQL／绑定不代表真实 MySQL 持久化、排序规则、BLOB/VARBINARY 不同长度和 SQL mode 已通过。
- 派生二进制关系名称、级联、维护回填等原有限制不解除。本轮不增加二进制编辑器、不改变原控件、不修改平台配置或数据库。
- B102 跨表 Excel 待批固定包和 C38 TIME 待批固定包未修改，不消费其授权，也不以本轮回归替代其正式验收。
