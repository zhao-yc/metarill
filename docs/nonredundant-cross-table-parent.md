## 为什么不能直接比较物理列

非冗余来源只存所选层位。例如选择城市后，来源的 `country_id`、`area_id` 为空，只有 `place_id` 有值。主子页面的国家父范围必须沿当前城市、地区、国家链定位，不能用 `country_id=parentId` 判断，也不能将页面传来的祖先 ID 当作真实物理外键送入守卫。

列表对失效关系保留所选原始 ID，方便原页面回显。这不构成写入归属证明。写范围额外要求整条已选路径的目标均存在、未删除、属于当前项目且满足固定目标条件；直接选中的失效根／末层也不能仅凭原始 ID 匹配。

## 固定执行计划

- `NonRedundantCrossTableScopeSql.Apply` 只接收已编译跨表 ID 字段及其准确类型的规范正整数；字符串前导零、溢出、浮点、注入文本及非规范项目 ID 在连接数据库前拒绝。
- 相关 `EXISTS` 同时绑定固定来源主键、来源项目／软删除范围、逻辑父 ID、稀疏存储有效性及所选路径可见性。双控件使用不同参数前缀，可组合为交集。
- 来源、目标条件中的私有文本和身份值均通过参数绑定。已编译计划不读取后改的元数据，辅助依赖不加入公开输出。
- 写用途必须在原事务内使用 `locking:true`，并将外层来源查询设为 `ForUpdate()`。适配器对内部路径使用当前锁读；即使查询在事务开始前已创建，也会重新加入当前事务。来源映射、外层锁、动作授权及独立参数前缀仍是调用方职责。
- 仅编译 `id` 与实际需要的父层位，避免因无关展示字段联接而扩大锁范围。无关目标路径是否可并发操作，以实库竞争结果为准。

原列表读取、VO、表头、前端组件及生成模板没有因本次适配器改变。ORM 启动自动改表保持关闭。
