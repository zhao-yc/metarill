# V362／V363 同父追加的候选重验与写入同包实库对照

2026-11-06，开发基线 b1a10c4，Server-200 MySQL 8.4.11，MySqlConnector 2.6.1。V362 独占轮次 61a41f8ba9133393，V363 独占轮次 0bd75a7538843225。驱动专项复用 V355 的标量缓存写回、按字节比较、物理读回与提交。两条路径都在同一可重复读事务内重验父候选，分别对比独立发送候选与一次发送候选及写入。每个命令使用绑定参数。

V362 使用 SET 从带子查询的 CASE 计算会话候选值。负例先建立看不到新父记录的一致性快照，再由另一连接插入并提交。当前读能看到父记录，原独立 SELECT 返回状态 1，合并结果不同，拒绝采用该 SQL。MySQL 手册区分普通一致性读取、锁读和某些组合语句的读取规则，具体差异以本轮实库复现为准。[MySQL 一致性读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html)

V363 把同一 CASE 放进独立 SELECT INTO，在同一驱动命令内由服务器先确定候选状态。只有状态 2 且连接库名匹配，才执行实际插入、缓存锁读、缓存更新和物理回读。两段 ROW_COUNT 独立检查插入和更新，命令末尾清空内部候选变量。实库逐项核对如下。

- 已删除或缺失父记录、快照缺父、候选不匹配及当前事务内改变父候选，合并路径与原独立候选返回一致。拒绝时插入及缓存更新为零，缓存读回均为空。
- 无效候选使用已有子行的同一主键。独立事务锁住该子行，合并拒绝在一秒锁等待限制内完成。切换到错误库时同时锁住父子行，仍无来源读写。
- 三组合法样本核对大金额 decimal、中文、引号、尾空格、null 和空字符串。重复键阻止后续更新，末行约束失败整批回滚，非严格模式的缓存截断被物理读回识别并回滚。

四连接争用同一父记录，每事务八行。各四次预热后交错比较三组，每种路径每组 24 批。计时包含提交，144 批计时和八批预热共 1,216 条实际写入逐行核对。每行由两次驱动发送减为一次。
