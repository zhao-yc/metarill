目标是让完整生成应用沿原授权页面，使用本应用真实Web账号批准设备，CLI发现实际生成接口并以原任务协议调用、查询与撤权。不得从平台CLI已有测试推断生成应用支持，也不得把本应用超级角色变成平台管理员。

## 已具备的必要基础

- `Metarill.Agent` 仅引用 Core、Data、Security 与 ASP.NET Core。原OAuth、能力、任务控制器及中间件复用同一份源码，平台明确注册其MVC应用部件，保留原路由及协议。
- 宿主通过 `IAgentHostResources` 提供安全资源与固定Agent发布快照；能力目录只匹配真实注册控制器，沿用原必填/默认值/父上下文规则。快照不暴露可变元数据，重复页面ID拒绝。
- 平台保留平台管理员批准及平台身份续签规则。独立快照限定本应用项目及已发布后台，当前超级角色才可批准；认证和后续操作仍须真实Web会话、当前角色和生成接口检查。这里是代码合同，不是新独立宿主已通过正式身份验收。
- 普通grant绑定证明、当前事务锁读证明提取到共享Agent；平台原适配类型保留为同规则委托。账号/项目/client/状态/实时有效期以及同一Session/事务要求保留，不把原grant字典或令牌摘要交给安全基础层。
- 原JSON选项进入Core，保留转换器与命名空间。旧公共类型从原程序集转发，原构造依赖变更须源码配套重编译；不宣称旧二进制插件无需更新。
