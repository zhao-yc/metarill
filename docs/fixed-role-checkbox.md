# 原账号角色复选的固定编译合同

本切片仅为原账号页 `6031906822946816` 的 `yz_role_ids` 字段补齐读取、数组边界与原候选协议。控件仍为 `MultiCheckBoxDatabase`，保留原全选、逐项复选、只读名称、完整实体保存及原 POST。没有增加后台切换清空/重载、弹窗或页面脚本。

## 元数据与读取边界

- 原声明为字段 `1692528723801219073`、物理字符串长度 500、`control_detail=yz_role`。编译器核对来源表/页、角色表/页、角色后台、后台项目等稳定字段 ID 与物理类型。
- 来源/页覆盖冲突、未知 SQL、关联目标冲突、计算别名冲突、虚拟或联接字段继续返回能力缺口。未知数据库复选控件不随该固定实例放行。
- 原 `findNameIdYzRole1692528723801219073` 返回 `{id,name,value,text}`，两个 ID 为字符串。候选最多 5000 项，超限明确报错；不会只返回第一页后让全选冒充全量。
- 原Java候选未规定 `ORDER BY`。C#仅按ID稳定排序，不添加名称排序；这不宣称与原数据库自然返回顺序完全相同。
- 来源页查询、新增、修改动作任一通过才可读候选；新增/修改须在本页实际开放。该合同来自原 `PowerInterceptor` 对关系候选的动作规则，仅捕获无权限异常尝试下一动作，不吞其他异常。
- 真实 `actor.ProjectId` 由宿主认证建立。候选依据 `role.yz_admin_type_id → yz_admin_type.id → yz_admin_type.yz_project_id` 限定当前服务器工作区，并排除已删除角色/后台。角色自身的兼容项目列不是授权事实：兼容列等于当前项目也不能放进外项目后台；兼容列为旧值也不把真实当前项目后台的角色误判为外项目。
- `formParameters` 保留原空槽/对象/旧文本请求，但不解释其项目、后台、SQL或目录。当前没有新增表单后台提示，也不会因缺提示查全库。
- 不按 `is_super` 隐藏普通超级角色；选项可见不等于可保存到任意账号。

## 数组与名称

省略由 `Optional` 保留，更新不覆盖；显式 JSON null 清空；`[]` 存空数组文本；HTTP 数组及旧已编码 JSON 数组文本均可输入，最终存储文本最长 500 字符。数字 ID 使用精确 `Int64` 读取，字符串 ID 使用规范正整数文本；拒绝浮点、指数、溢出、布尔、对象及字符串 `"null"`。旧数组文本不经浮点转换，保留提交顺序和重复位置。

`yzRoleNames` 是固定计算的数组/JSON null，按原角色 ID 顺序输出，缺失或当前项目范围之外的名称保留 null 位置。名称只从受限 ID/name 查询获得，不增加物理名称列，不持久化客户端名称。原完整实体回传只剥离精确 `yzRoleNames` 回显别名，严格 DTO 不接收该别名，其他未知键照常拒绝。

列表先读本页源记录，再整页去重角色ID，每200个唯一ID串行查询一次，仅选择ID和名称，不逐行/逐角色查询、不在同一事务并行SQL。每次最多5000个唯一ID，超量在补名SQL前明确拒绝，不取前5000个冒充完整名称。生成服务正常列表查询预算为 `2 + ceil(唯一ID数/200)`（数量、源页、补名）；详情为 `1 + ceil(唯一ID数/200)`，空角色不发补名SQL；不包含宿主既有认证/撤权读取。5000上限时补名最多25条；单账号仍受500字符存储上限。

## 尚未完成的授权与发布门禁

本切片不修改 Runtime Security、身份认证、角色资源工作台或手写 Service。生成的普通关联检查只证明角色仍在当前工作区真实后台项目范围；最终账号合并后的后台与全部角色必须一致、后台修改但省略角色仍重验、锁内当前读和撤权协调继续由 Runtime A 完成。

因此用途读取 IR 可以证明这个固定角色实例，但能力清单仍明确保留 Runtime A 缺口，FullApplication 继续拒绝。不能仅凭本切片编译通过关闭整体角色 Gap。

原账号页导出和复制开关均为0，未更改。新增、更新及以后显式开启复制的生成回执已走名称投影；导出目前直接读取物理列，尚未补角色名称。能力审计复用导出渲染器真实的开启与列选择规则：仅当已开启导出且实际导出列包含角色字段时，另记 `usage=export` 缺口；未导出角色列的页面不会被该缺口误拦。将来Runtime A验收完成后，该导出缺口仍须单独解决，不能随Runtime缺口一起取消。

页级隐藏角色ID时，已证明的内部固定引用校验和真实授权DI仍按表级服务依赖生成；DTO/VO、名称投影和公开候选只按该页实际可读字段生成。隐藏字段不导致缺方法编译失败，也不借此开放隐藏数据。

Runtime A待验收门禁独立绑定固定账号表的稳定ID和表名，覆盖原固定账号页及同表所有实际开放新增、更新、删除、复制或导入的页面。即使角色字段隐藏、声明变为未知配置/其他控件或被移除，安全服务仍不能借读取证明消失而提前导出Full；该发布检查不会生成新的DTO字段、候选或读取投影。

`type=2`选择页的已选行回读目前使用统一页VO，尚未补角色名称投影。因此仅当实际已选回读包含已证明的可读固定角色字段时，另记 `usage=selection` 缺口；角色仅从网格隐藏但仍可读时也受该门禁约束。原`type=0`账号页不新增选择用途缺口，完全隐藏角色读取的选择页也不误加该缺口。将来Runtime A通过后仍须单独完成选择回执，不能连带解除这一用途门禁；本切片未实现或改造选择页。
