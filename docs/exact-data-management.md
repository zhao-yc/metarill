# 精确数据管理对齐

目标是保留原 V8 的记录范围能力，覆盖平台、生成项目、文件真实引用及原操作。前端页面、样式、交互和接口不因这一实现改变。直接页及可信父子/选择引用的物理标量执行链，以及已登记非冗余单值派生列的匹配已经接通；复杂条件及完整控件/并发组合仍须完成，不能将本阶段视作完整功能验收。

## 逐动作决策和可信匹配值

原规则来自 PowerInterceptor.applyExactDataManageFlag、YzpPermissionService 和原文件 PagePermissionBusiness：当前操作所有有效授权都来自 is_scope 角色时才限制。普通角色必须通过有效直接或继承来源授予当前目标的当前动作，才能解除该动作的限制；is_all 是该动作的另一条有效来源。后台 super 保持原规则。

共享 PrincipalRolePolicy 对已支持的直接页及可信继承来源聚合 ExactDataManagePermissions，同时核对已发布资源及当前有效资源。外后台、软删除、损坏授权、其它页或仅菜单授权不能影响当前动作。AuthenticationService 与事务内 SecurityRealmCurrentReader 使用同一规则重读，不修改旧身份快照。

后台的 exactDataManageMatchField 来自已发布元数据，完整应用使用已验证摘要的私有目录，平台使用自己的固定目录。认证仅捕获该真实账号字段的一份值快照，不保存整个账号。字段名统一 snake/camel，不能使用 SQL 或属性路径，也不能用凭据字段匹配。未配置、空值或空数组在需要限制时不匹配记录；损坏 JSON、嵌套对象和不可表示类型明确拒绝。长整数不经过 double。新增身份属性均标记 JsonIgnore，不加入原接口和会话内容。

## 已接通的物理标量执行链

- 生成期固定页记录匹配列和后台账号字段。真实物理标量沿原执行链；已登记的非冗余单值派生列经固定计划证明后参与范围。数组、未知列、虚拟表达式及无法证明的路径在生成时拒绝，不能忽略条件继续生成。
- 标准强类型查询在分页、数量、导出和写前锁定之前追加 AND 条件。非冗余固定读取计划使用同样的逻辑类型和集合；隐藏匹配列只成为读取依赖，不进入 VO。SQL 名称来自固定计划，值通过驱动参数绑定。空集合固定为不匹配。
- 导出使用 export，修改、删除、复制分别使用自己的动作；覆盖导入使用 import，不能借普通 update 授权取消限制。范围内未找到覆盖对象时保留原追加规则。
- 新增沿用原新增或导入权限，不额外要求查询权。非冗余写后回显使用私有入口，限定已写对象主键、真实项目/父和当前写事务；HTTP 无切换参数。关系写入继续按原候选范围校验，不擅自增加目标页查询权限。
- 文件真实引用读取追加来源页查询精确范围，继续核对实际文件值、项目/父、软删除和真实引用。记录读取复用当前连接及事务，保持同批未提交数据可见。空值、坏值或无法证明的声明不能使他人文件变为可读。

旧授权器没有实现 ResolveExactDataManage 时明确拒绝已声明范围的操作。没有配置范围的页面维持原生成签名和调用，不增加新的授权依赖。公共 Service 接口保持，新增动作参数仅用于生成的私有方法。

## 验证与真实反例

专项验证分别执行值转换/身份快照、实际生成程序集与 ORM SQL、完整包 Production/Web 和真实 MySQL。它们不能替代浏览器、真机或性能验收，具体当批结果记录在验收台账。

实现过程中保留了两个真实反例：ORM 的 Contains 将集合值内联，之后改用固定 SQL 参数；Where 对象重载不能接收 DbParameter 数组作为参数集合，虽可输出占位符，实际执行缺少绑定，之后改用受支持的命名参数字典。正式验证必须同时检查范围内写入成功和范围外写入拒绝，不能把驱动异常造成的 HTTP 500 算作范围正确。

完整包还验证仅有新增权限的文件首次绑定：写后回显不能误用详情权限拒绝原操作。详情不可读仍沿原 HTTP 200/R500 语义，未改产品接口去迁就测试。

## 继承来源与文件用途

C# 的独立资源目录对照原资源权限分支，合并真正命中的直接、真实父子及选择引用来源。旧菜单权限分支的直接优先顺序不套用到此目录。

PagePermissionInheritance 在固定目录加载时编译同项目、同后台的窄关系。真实父子边来自 ConfigChildren；选择边来自 SelectPage/MultiSelectPage 列与页面字段的有效配置，页面非空覆盖优先，再使用明确的页面关联。重复、软删除、跨归属或无法解释的配置不产生授权。普通认证不重复解析固定控件 JSON；平台事务内当前读取得必要配置，并与已发布边、页面归属及动作开关取交集，新增或重绑不能借未发布关系扩权。

子页从真实直接父页继承同类动作，来源和目标都必须开放该动作；选择页只继承查询。聚合只使用直接角色授权，不做递归传递。继承的 is_all 单独保存在内部集合中供复制/导入检查，不能作为绕过父页已关闭修改动作的通用 is_all。

文件来源只聚合直接页面和真实父子查询，排除选择引用。普通页面查询与文件查询分别保存授权和精确范围集合，均标记 JsonIgnore，不改变原身份构造和 HTTP 响应。即便普通查询因选择页普通角色而不限制，文件仍可按直接来源的范围角色过滤，账号窄值也会为此捕获。文件真实引用、当前字段值、项目/父、软删除及同事务读取继续核验。

真实包验证使用同表的独立选择视图和普通子视图。引用由原 Service 写入，最后写入视图决定真实文件来源；没有手造引用。仅选择查询时普通页可读、文件拒绝；直接范围查询只读取匹配记录文件；真实父子普通查询使相应真实引用可读；错误动作、撤权和账号值变化逐请求生效。关闭父页修改时，父 is_all 不能修改子记录。

以上结果不代表所有主子列表类型、派生属性或锁并发组合已完成验收。选择列表直接作为内嵌编辑子表仍受既有生成边界约束，不能用独立视图场景冒充该组合已支持。

## 已有工程跟进

本阶段不新增数据库列或调整物理表，也不手工修改在线配置。升级先保留现有手写 partial、私有配置和 AppID，再用同一版本工具生成完整候选，通过本机助手原按钮或既有更新流程预览并同步运行时、项目配置和页面生成结果，审查后应用及编译。范围声明同时依赖编译后的 Service 和宿主已发布目录，不能仅复制一个运行时文件后宣称旧生成代码已具备过滤能力。

后台匹配字段及继承关系变化需要重新发布已验证的目录和生成计划，再构建并按原流程重启固定包；账号值和角色变化由下一次真实认证重读。完整包更新仍保护手写内容、拒绝归属不明文件，不执行 SQL 或生产部署。未配置范围的现有项目无需元数据回填或 SQL 迁移。

## 非冗余单值派生匹配（2026-10-21）

生成期与宿主静态初始化共同编译固定匹配路径。只接受真实项目列和统一 int64 单值关联键；最终字段的真实逻辑类型必须与已登记匹配列一致，凭据、文件数组、JSON、虚拟来源和循环路径不能借普通别名参与匹配。发布脱敏与路径校验复用同一凭据字段名规则。原没有范围声明的接口和页级字段边界保持。

读取将派生匹配作为固定 AND 依赖，在 count、分页、统计、导出之前执行；隐藏依赖不加入 VO。修改、删除、复制及覆盖导入继续从原私有 Scope 进入，由同一真实写事务执行相关子查询锁读。外层主记录与内层匹配路径分别 FOR UPDATE，固定计划只带匹配需要的关联，不连带锁定其它显示关系。MySQL 对嵌套查询需要单独锁定，见[官方锁读说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)。方言及参数命名留在数据适配层，Service 不判断数据库品牌。

真实双连接验证了单级关联锁、无关目标可写、两级路径各级均锁定、提交释放，以及 REPEATABLE READ 先建立旧快照后目标变化时，写前锁读拒绝旧匹配并接受新值。该用例不代表安全目录七表锁集合、所有死锁组合或性能已经验收，也没有新增观测权限。FreeSql 在已有 lambda 后更换别名不会改写旧条件，首轮实库错误保留；最终与生成 Mapper 保持同一固定别名。

保护文件在启动时另编译每页/每文件列的窄投影，只读取实际文件值、主键、项目及父键，匹配依赖保持隐藏。读取复用原连接和事务，再核对真实引用、实际文件值和父对象；缺少可执行证明不能回退为无限制。正式 Production/Web 包验证了派生范围内文件流、resolve、原文件列表，以及目标值变化、目标软删/跨项目和撤权后的拒绝。

本阶段不改前端、接口、平台元数据或物理表。已有工程需要同版再生成并同步 Data/Files 运行时后构建固定包；不能只复制新运行时就认为旧 Service 已具备范围。SQL 迁移和元数据回填均无需执行，新增匹配配置仍走原元数据发布流程。复杂 Where、多值、其它控件和完整并发边界继续验收。
