# V287 平台同库 S3 项目隔离对照

2026-11-05，沿用 [V286 分库验收](platform-split-s3-http-mysql-v286.md) 的 `250aab9` 固定产品、两字段合成元数据和 69 文件 Production 宿主。平台和业务连接同时指向本轮独占物理库，另建一座未接入宿主的空库作对照。复用相同的 29 次原 HTTP 请求、两种不同 ZIP 及真实 SeaweedFS，独立 SQL 改按项目归属检查共享库。

| 检查 | 实际结果 |
|---|---|
| 共享库中的项目边界 | 平台、业务表均在共享库。业务文件与两条引用归业务项目，平台项目下对应文件与引用均为零。未配置的对照库始终零表。业务普通角色在平台身份表中存在。 |
| 原接口及公开项目提示 | 原表单登录、上传计划和 multipart、受保护授权读及 206 Range 通过。平台管理员和匿名用户均无法读取业务受保护附件。公开文件只接受正确业务项目提示，读回原字节一致。 |
| 回滚、删除及撤销 | 未完成附件导致整笔保存拒绝，原备注及两份附件引用保持。仍有引用时文件删除被拒绝，逻辑删除业务记录后清除两条引用，再删除两个对象。SQL 核对记录、引用和文件删除标记，活动会话为零。 |
| 独立 S3 与清理 | 两对象实际长度及 SHA-256 独立匹配。删除后独立列举确认为空，空桶删除后新客户端 HEAD 返回 404。双库、临时账号、所有权记录、Redis、SeaweedFS、IAM 配置和转发均独立核清。 |

固定产品及原页面未修改。私有脱敏回执保存在 `E:\git\metarill\.local\s3-platform-v287`。本轮与 V286 合并证明固定原 HTTP 用例在同库和分库两种拓扑通过。S3 原浏览器、设备、其他对象存储品牌与同条件性能继续单独验收。
