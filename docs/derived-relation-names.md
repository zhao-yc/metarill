# R0 List 的固定派生名称

本项接续复杂联接 B20：订单通过客户ID关联 R0 客户，客户再通过公司ID关联公司，使用 company_name 作为原 List 的名称。保留原接口、字段名、uni-app 页面、样式和交互，不把派生名称落成物理缓存。

## 修正的执行路径

旧生成器对 R0 来源直接拒绝派生名称候选；简单解除该门禁会让原候选／导入查询对 Entity 的 IsIgnore 名称属性执行物理 SQL。因此本批接通完整的固定名称用途，而非仅删除拒绝：

- 生成校验和宿主静态装载分别编译目标 ID／名称及必要条件依赖，普通请求只绑定真实 Actor、父ID和明确表单标量。
- 三个候选入口沿用原来源／目标页面授权和真实父检查。名称的搜索、排序、COUNT、分页均在固定SQL内完成；旧数组端点超过5000明确拒绝，已选最多200项，导出按200个ID分批读取。
- 页面条件和控件条件作为AND同时保留。新增 FixedConditionSqlPlan.BindVariables／And，只绑定固定槽和组合已有类型计划，不在请求中重新解析元数据；缺变量、类型错误和同字段矛盾类型在执行SQL前拒绝。
- 原中文表头导入按同一范围唯一匹配，数值ID也核对；目标名称使用同事务当前读，第二行失败撤销整批。普通导入不借用新增、编辑或目标列表授权。
- 原导出仍使用实际来源记录的父键／表单依赖隔离名称缓存，通过原票据下载XLSX；未匹配名称保留原ID回退合同。
- 隐藏有效关系只生成内部最终值校验，不额外生成公开候选路由；隐藏默认FK也不能跳过候选范围。非派生普通关系的生成路径保持。

名称属于已授权来源行的逻辑投影。上游外项目／软删除节点的名称保持空值，不以另一项目的名称补齐；目标ID本身的可选性仍按目标行及候选范围判断。不存在的、已删除的或不在当前范围的已选ID整体拒绝。

## 直接验证的模型

验收使用四张独占随机表：订单R0、客户R0、组、公司R1。客户的 company_name 明确为只读联接 company.name；订单可选的 customer_company_name 为只读联接 customer.company_name。客户物理 name 故意使用另一个名称，避免测试误读旧实体列。

两种场景分别是不带目标父／表单条件，以及来源父与目标父同定义、附带 segment 表单条件。每组预置5103个正常候选、上游外项目名称、目标状态失效／软删除／外项目等反例；正常默认范围总数为5104，包含一个名称为空但目标行仍有效的记录。候选ID、所选ID和父ID超过JS安全整数范围，沿原字符串合同。

实际生成HTTP覆盖分页、非首屏已选、百分号／下划线／单引号字面搜索与注入形态无结果、来源及目标撤权、整entity只读名称回传、混合条件重验及回滚。公司通过真实生成更新接口改名后，订单逻辑名称立即变化，物理订单不重写。另验证中文名称导入、重名第二行失败整体回滚、实际原票据XLSX下载，以及在已建立旧RR快照后由另一HTTP请求改名，再直接调用同版生成导入服务成功解析新名。

固定测试宿主建立明确 Actor，仅允许测试头减权；这是实际MySQL与生成接口，不是正式Web认证。完整包实际编译并保护手写partial，原远程关系组件与运行时资源按真实路径逐字比较；没有使用“文件不存在就跳过”的组件核对。

## B189 普通 List 使用派生整数名称

普通非冗余来源通过 List 选择同项目非冗余目标时，`nameField` 可绑定到目标已开放读取的 int32 或 int64 联接字段。例如订单选择客户，显示客户关联公司的整数编号。来源外键和整数名称来自同一声明的候选目标。候选和已选回读沿用原下拉文本协议，保留整数的完整十进制表示，列表和详情的联接投影仍为原整数类型。

搜索在固定整数表达式上按字面关键词匹配，候选按原配置的物理标量或该整数名称排序，并以主键稳定同值次序。原 Excel 的数字或文本单元格均作为配置的业务编号反查，同一范围内缺失、重名或溢出按原关联错误处理。导出以文本写入整数名称，缺失名称留空。64 位编号的工作簿源数据也应用文本单元格保存原精度。

适用范围为普通 R0 来源及目标上的 List 固定标量联接。已有生成项目先同步 Data 运行时，再重新生成受影响页面。验证覆盖负 int32、超过 JavaScript 安全整数范围的 int64、带父及表单的目标范围、声明排序和现有字符串关系。专项 MySQL、正式 Web 交互和性能按首版计划后续验收。

## B193 项目内物理整数名称

普通 R0 来源的 List 和 SelectPage 可以用同项目 R0 或 R1 目标页已开放的 int32 或 int64 物理业务编号作为显示名称。候选、分页、回显和工作簿反查沿用原目标页的项目、软删除、父记录和已配置条件。工作簿将编号作为文本保存，导入使用真实整数类型匹配。已有应用更新 Data 运行时后，再生成受影响的服务和页面。

35 项生成及 110 项数据层定向回归通过。四种实际生成模型覆盖两种目标存储、两种整数及两种控件。数据层核对了项目与软删除谓词，并验证全局目标和缺少真实项目列的声明会被拒绝。专项 MySQL 与正式浏览器验收后续执行。

## B194 R1 整数名称缓存

普通 R1 来源的 List 和 SelectPage 支持同项目或全局目标的 int32、int64 名称。来源必须声明与外键路径、目标字段和类型一致的只读物理缓存。发布时核对现有保存、目标值变更传播与维护回填计划。保存和复制由现有事务重算缓存，Excel 使用候选范围按真实整数查找，导出按文本保留精度。

原 SelectPage 名称搜索使用缓存列的十进制表示，关键字沿字面匹配绑定参数。54 项生成和 123 项数据层定向回归通过，覆盖四种物理目标、两种全局派生目标、缓存声明拒绝、SQL 参数与已有字符串路径。专项实库、正式浏览器和性能验收后续执行。

## B195 全局 R1 来源的整数名称缓存

明确全局且没有行项目列的 R1 表，其原 List 可以选用全局目标页上的 int32 或 int64 业务编号。支持 R0、R1 目标的物理编号，以及 R0 目标沿已发布关系派生的编号。缓存必须是真实物理列，与外键路径和目标编号类型一致。辅助值沿原页面回显，保存、复制、目标值变更传播和维护回填共用现有缓存计划。候选按原范围搜索分页，Excel 按真实整数反查并以文本导出以保留精度。

已有应用同步 Core 和 Data 运行时后重新生成。专项 MySQL、正式浏览器及性能按首版安排后续验收。

## B197 全局 R0 来源的整数名称

显式全局的 R0 来源，原 List 和 SelectPage 可以使用全局目标页中的物理整数编号，或 R0 目标沿已发布路径计算的整数编号。来源页有项目列时，读写按记录归属和当前发布身份过滤。没有项目列时，按同一发布目录的身份及固定页面范围执行。

列表和详情即时读取 int32 或 int64 名称。目标名称经多个 R0 联接时，沿同一证明栈追到同类型的真实字段。原选择页支持名称关键词和已选回显，Excel 使用候选范围精确反查并以文本导出。已有应用同步 Core 与 Data 后重新生成，正式实库与浏览器验收按首版计划后置。

## B198 全局 R1 整数缓存作为单值目标

原下拉和选择页可以使用全局 R1 目标表中已发布的 int32、int64 名称副本。发布时逐层校验该副本的外键、目标、字段和类型。候选按原目标页范围搜索、分页和回读，Excel 按原候选范围精确匹配，并按文本保存完整整数。

R0 下游即时读取上游副本。R1 下游在保存、复制、变更传播和维护回填时沿已发布的依赖更新自己的物理副本。全局无项目列的 R1 来源沿用原 List 控件；普通来源和全局 R0 来源支持原 List 和 SelectPage。已有应用同步 Core 和 Data 后重新生成。专项实库验收依首版计划后置。

## 跟进方式与边界

已有应用先同步同版 Core／Data 运行时，再从元数据正规生成受影响Service、DTO/VO、Controller及原页面；通过原三动作的预览和依赖检查应用，保护手写partial、AppID与私有配置。新增方法是运行时依赖，不能只复制生成页而沿用旧Data源码。逻辑名称沿用现有ID和联接定义，不新增DDL、物理名称列或历史回填；配置本身变更仍先改元数据再预览结构。

B43 当时接通 R0 来源 List、普通 R0 目标和固定单值字符串名称，目标身份／父及附加条件须为物理标量。全局目标、精确数据权限、逻辑跨表父、平台固定归属、R1来源的派生缓存、SelectPage／多值派生名称及未编译表达式继续明确拒绝或保留既有门禁，不扩称全部复杂联接完成。

尚未完成本模型的正式Web／专属空库、原页面浏览器、跨端与同条件性能；名称缓存反向传播和维护回填仍按B21／B22分别推进。浏览器空间重建确认仍待答复，不以构建或HTTP代替。整个MySQL首版和后续数据库目标均保持，不合main，不部署生产。
