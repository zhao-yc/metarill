## 原协议与存储定位

原 `yzp-file-library` 已支持 `SERVER_MULTIPART`，本轮继续使用原上传计划、`local-upload/{id}`、完成、公开/受保护内容与删除接口。页面、样式、选择/上传/预览/下载交互、字符串ID和原文件引用事务保持。路由中的local名称作为原协议保留，实际对象供应商由服务端计划决定，不由请求选择。

文件表的 `storage_key` 当前逻辑长度100；元数据及物理结构未改。旧 `32位随机值.blob` 永远按原本地根读取，切换默认供应商不会重解释旧文件。S3新键为：

```text
s3:部署别名:32位位置摘要:32位随机值.blob
```

别名最多16字符，总长度不超过90。位置摘要由规范化端点、区域、桶、前缀及寻址方式生成，不包含可轮换凭据。未知别名、篡改定位或重新指向另一个桶/端点明确拒绝，不回退到新桶或本地路径。更换对象位置须保留旧别名并发布新别名；同位置轮换密钥不改变定位。

客户端与数据库中的对象定位不能提供URL、桶、区域、凭据或任意对象路径。公开URL仍为原受控内容入口，不向浏览器暴露云端密钥或临时签名。

## 对象与事务

- 平台和普通/管理完整应用共用 `FileObjectStorage`；连接单例、按已发布配置懒创建，普通启动不连接云端或创建桶。平台/业务库仍选择原文件会话与项目槽。
- 上传在原文件行锁/事务内完成有界临时流与SHA-256核验，再调用固定S3对象。写入使用 `IfNoneMatch=*` 与明确SHA-256校验值；同键已存在时只在真实GET大小/字节摘要相同后接受重试，不以远端元数据或单个ETag证明一致。
- 未确认数据库提交结果时保留固定随机对象供核验，不能清理可能已经提交的文件。上传状态、所有权、过期、项目和引用校验仍由原Service/观察器处理。
- 完成会重新验证对象。云端读取先按文件记录有界下载并核对实际大小/摘要，再以可寻址只读临时流交给原ASP.NET内容响应，保留Range/HEAD合同。只在流关闭时清理本次缓存，不能无限读入内存或让调用方写入缓存。
- 物理删除仍先在原事务内确认无引用并使数据库记录失效，固定定位先校验；云端删除失败明确回报，不能恢复数据库行或扩大到目录/桶。版本桶的历史版本、回收与完整故障矩阵仍待专门验收。

此实现只覆盖服务器中转的S3对象能力；原云端直传、阿里OSS及其它供应商/访问模式组合继续单列。兼容端点必须实际证明条件写和内容校验，不能因SDK能连接就声称该品牌正式支持。

## 私有配置

平台使用 `Metarill:Files:Storage`，独立应用使用 `Files:Storage`。默认仍为local。以下只是结构示例，不会自动写入现有开发或服务器配置：

```json
{
  "Files": {
    "Storage": {
      "DefaultProfile": "storage200",
      "S3Profiles": {
        "storage200": {
          "Endpoint": "http://192.168.31.200:8333",
          "Region": "us-east-1",
          "Bucket": "<该项目明确授权的桶>",
          "Prefix": "metarill",
          "AccessKey": "<私有配置>",
          "SecretKey": "<私有配置>",
          "ForcePathStyle": true,
          "AllowHttp": true
        }
      }
    }
  }
}
```

HTTP只在部署方明确开启时允许；TLS、桶、前缀、凭据及策略由部署方固定。凭据字符串不进入配置对象的默认日志格式，不提交仓库；后续实际新增需按项目约定备份到重要文件目录。当前没有生成真实云端密钥。

采用官方 [AWSSDK.S3固定版本](https://www.nuget.org/packages/AWSSDK.S3/4.0.104.8)；[条件写与SHA-256合同](https://docs.aws.amazon.com/sdkfornet/v4/apidocs/items/S3/TPutObjectRequest.html)按官方SDK实现。实际完整包曾复现旧打包器只允许三段固定版本而误拒绝四段SDK版本，本轮扩大为明确三/四段数值，仍拒绝浮动/区间，输出使用完整版本精确锁定。
