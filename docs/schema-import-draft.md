# 数据库反向逻辑草案与配置保存：A11

当前已接通“明确选择源表→只读草案→服务端审核计划→明确确认→平台配置事务保存”。**A11仍为部分完成**：A13已补固定同库双项目活动/墓碑、并发认领与真实Web排队撤权；导入后原页面配置/生成CRUD及其余归属/身份/库名规则矩阵仍需补齐。原只读预览合同保持 `executable:false`、`canImport:false`，不发放保存计划；其中的 `draft_*` 仍是符号标识。实际保存使用下面单独的prepare/apply协议，不把预览输出直接传给旧新增表入口。

## 使用入口

- HTTP：`POST /api/admin/sys/database/import/preview`，请求 `{"tableNames":["source_record"]}`。
- MCP：`preview_database_metadata_import`，`data` 使用同样对象，工具只读。
- CLI：`dotnet run --project backend/src/Metarill.Cli -- schema import-preview --server https://平台域名/api --project-id 项目ID --tables source_record,other_record`。

CLI仍从 `METARILL_LOGIN_STATE_ID` 或指定 `--token-env` 读取原网页登录会话，不接受命令行令牌、SQL、连接串。远程HTTPS、重定向拒绝、8 MiB响应及30秒总期限沿用[A10合同](schema-inspection.md)。草案和准备命令要求 `--tables`，不能与 `--table-id` 混用。客户端也验证不可导入和符号ID标记，避免把草案响应解释为保存许可。

服务端逐请求要求真实网页登录平台管理员；普通账号、Agent或匿名拒绝。项目由原认证上下文选择，连接仅来自服务端配置。仅接收1至16个明确、合法且不重复的单段物理表名，不接受跨库名、未知/重复属性或省略/null列表。已在当前项目登记的表（含派生文件基础表）应使用原受管反查，不能以此覆盖。只读草案不构成导入许可；准备和保存另需实际目标、包含墓碑的归属当前读及服务端计划确认。

## 快照、锁与预算

适配器先核对实际数据库与预期，校验能读取MySQL实例标识；当前结构指纹不绑定该实例身份，不能当保存授权。实体类型预检后，以显式事务中的固定 `SELECT 1 FROM 规范表名 LIMIT 0` 持有MDL；查询不返回业务行。随后在同一事务读取列、默认值、索引、SHOW CREATE及未建模特征，回调结束或异常时释放。

实库已否定仅使用SHOW CREATE持锁的假设：其锁在语句后释放，首轮ALTER确实成功。修正后，源检查期间另一连接的ALTER实际1205超时；成功返回和回调故障回滚后均可ALTER，后续结构指纹发生变化。没有放宽断言，也不以客户端等待时间充当真实锁证据。

每表最多512列，一轮最多4096列，DDL快照合计最多2 MiB，超过预算明确拒绝，不截断模型。普通视图和非InnoDB实体不能生成该实体草案。多表按名称排序申请锁，但本轮没有证明所有多表DDL死锁组合或其它MySQL名称大小写配置的完整矩阵。

## 逻辑模型的边界

草案只包含源中确实存在且当前逻辑模型能够无损表示的表、列和索引，不分配真实ID，不创建页面、菜单或补8个默认系统列。项目名称和主色来自当前项目，字段显示名暂用物理名称；这不是原页面已生成或已接通的声明。

映射后逐列用原正向编译器核对类型、可空性、主键和安全默认值，再两向比较列/索引，防止遗漏。普通索引保留原名、唯一性和列序，不自动改成托管前缀。`columnsAndIndexesRepresentable:true` 仅说明当前模型内的列和索引能够往返，不说明可保存、源库可完整重建或其业务数据、权限和生成页面已验收。

支持当前正向逻辑模型可表达的有符号int/bigint、varchar/text/longtext、decimal（完整数值范围限28位精度）、tinyint(1)、date、datetime(6)、time(6)、json、varbinary/longblob及已证明的常量。具体可否往返以逐项缺口为准，未知类型不回退成string。明确缺口包括：

- 没有唯一非空有符号bigint主键id、复合主键、auto_increment、生成列及未证明的EXTRA。
- 当前模型无法表达的物理类型/时间精度、超过C# decimal范围的精度、函数默认、空字符串默认与无默认的区别。
- 前缀、DESC、隐藏、非BTREE或表达式索引，外键/CHECK等未建模约束；这些特征不伪装成普通ASC索引。

字符集、排序规则、注释等保留在原始DDL快照中，不表示都已进入逻辑模型；触发器可见性及运行副作用仍待专门复核。预览不自动修改现有表来迎合逻辑类型，也不执行原生SQL默认表达式。元数据指纹只是本次读取的诊断值，后续保存仍须原事务内当前读和版本复核。

## 明确确认的配置保存

原界面及首页按钮未改变；新增在线入口共用同一Business：

| 操作 | HTTP POST 后缀（`/api/admin/sys/database/import/`） | MCP | CLI `schema` 子命令 |
| --- | --- | --- | --- |
| 审核 | `prepare`，`{"tableNames":["source_record"]}` | `prepare_database_metadata_import` | `import-prepare --tables source_record` |
| 保存 | `apply`，`{"planId":"…","confirmSha256":"…"}` | `apply_database_metadata_import`，另外要求 `confirmed:true` | `import-apply --plan-id 计划ID --confirm 摘要` |
| 回执 | `status`，同一计划ID及摘要 | `get_database_metadata_import_status` | `import-status --plan-id 计划ID --confirm 摘要` |

CLI还须传原 `--server` 和 `--project-id`，使用现有网页登录会话环境变量。审核应检查完整逻辑模型和提示后再显式运行保存命令；客户端不能上传待写模型、连接串、项目归属或SQL。准备不写配置；保存仅登记源中已有的表/字段/索引及真实ID引用，**不执行DDL、不写源业务行、不补8个系统列、不创建页面或菜单、不自动生成/发布**。

服务端计划绑定当前账户、会话、主身份项目/后台、所选项目、实际MySQL实例/数据库/名称规则、源快照、当前配置版本和完整逻辑模型摘要。有效期5分钟、同会话最多8个待用计划，全局待用及回执合计最多512项；确认原子消费一次。错误身份/摘要不能消耗计划，合法消费后失败须重新审核；执行前及平台配置提交前再次检查期限。计划只缓存小型绑定，不缓存连接或凭据；重启后失效。结构快照指纹本身仍不充当实例身份。

准备及保存都持有目标源表MDL，在平台配置事务内按原项目/后台预锁协议当前读会话与角色。导入专用配置读取使用锁后当前读，避免安全发现阶段形成的旧RR快照漏掉排队期间的配置修改；版本或源结构漂移会拒绝。协调器必须拥有平台配置事务边界，不能加入未知外层事务提前记录保存成功。

归属比较使用实际目标身份与MySQL名称规则：当前活动配置、派生基础表、同物理对象的其他项目配置及墓碑均不能重复认领；同名但实际数据库不同可继续。保留安全基础表，固定平台基础表也不能以删除配置绕过；无法解析其他项目的可信服务端绑定时拒绝猜测。当前采用包括墓碑和空隙的 `config_table` 全范围锁，兼容未遵守项目预锁的旧写入口；这是低频管理操作，可能增加配置写入等待，未承诺并行吞吐或全部死锁组合。

表/列校验复用原对象规则，索引引用在事务内分配实际ID；保存后从数据库当前回读配置并用原正向编译器双向核对源物理结构。任一表晚批错误都回滚整批表、字段、索引和子项；不能以将要插入的字典代替真实回读，也不能通过补列或放宽类型使源结构“通过”。二进制物理词使用原配置可接受的 `blob`，逻辑类型和长度保持原varbinary/longblob；`*_id`必须int64、`sort_no`必须int32，不能隐式扩宽源列。

`configurationSaved:true` 只表示已确认平台配置提交。该回执在目标只读事务结束前记录，后续源连接异常不抹去已提交事实；不宣称跨库分布式写事务。回执保留30分钟，状态有 `prepared`、`processing`、`saved`、`unconfirmed`、`unknown`；只有saved返回true，其他返回null。响应丢失、超时、重启或回执过期不能说明未写入，应查询同一计划并核对实际配置，禁止自动重复保存。CLI核对回执项目及计划，拒绝把未知状态解释成false。
