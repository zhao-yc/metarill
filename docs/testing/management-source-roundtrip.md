# 管理准备包的原业务来源与跨进程重建

日期：2026-10-30；起点 `2a076b7009062ef70855bdb949e85f656bfc06ee`，对应 C05/C50。完整管理发布和更新仍需后续接线与正式验收；本批补它们共用的持久化来源，不新增前端操作、CLI或HTTP入口。

## 原缺口与当前实现

管理准备器原来只保留合并基础/安全管理图后的 `backend/metadata/project.json`，工厂原业务来源只存在当前进程的弱引用签发表。实际准备包回归首先确认 `application-source.json` 不存在，无法从磁盘独立恢复原业务输入；不能通过删除若干安全表来猜测原目录。

现在在普通完整包完成脱敏后，将其原业务元数据字节保存到固定路径 `backend/metadata/application-source.json`，同时登记实际字节SHA256和文件归属。随后继续生成原管理目录、三份安全partial与原工作台。不会复制调用者尚未脱敏的原对象，也不会改写原输入。

`PreparedSecurityManagementSource.Read` 只读取固定的来源、发布目录、生成归属和两份基础元数据路径。原业务快照再次脱敏必须幂等，再由当前内置工厂按包内后台重新签发；模块摘要、项目、命名空间、管理图规范摘要、实际发布目录摘要和生成归属必须一致。基础图继续经过C49完整表集合/字段/索引核对。即使重算文件及声明摘要，也不能用自报标志替换当前工厂固定模型。

准备器在最终发布前实际落盘回读并重新构造一次。返回的是新的工厂上下文，来源字节无需依赖先前进程的签发对象。该读取器只证明元数据来源和固定管理目录，不验证全部源码/宿主完整性，也不提供更新或数据库写入授权；未来受管更新仍须执行完整文件归属、计划、确认及恢复流程。

## 兼容与手写内容

- 来源读取不按初始手写文件摘要拒绝开发者扩展；重建后实际生成继续执行原partial首次创建规则。
- 模型字段、归属声明拒绝忽略大小写的重复别名；嵌套业务扩展JSON保留大小写敏感键。补充正例曾复现 `A`/`a` 业务字典被第一版校验误拒绝，已收窄并保留失败证据，不能借来源验证改变扩展值语义。
- 新准备包增加一个来源文件和 `applicationMetadataSha256`。旧内部准备包没有该来源时，新读取器明确要求重新准备；不在原目录上补写、不从合并后的表图反推、不修改已冻结的旧验收包。
- 普通FullApplication、普通更新器、原前端/模板/接口和数据库均不变。准备标识继续 `readyForPublication=false`，不会据此解除C05发布门槛。
