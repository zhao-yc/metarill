# MySQL 关联反查锁范围诊断

日期：2026-11-04。归属：V156，继续处理 V150 的并发四写入退化。此处是诊断结果，产品修复及完整同条件性能复测尚未完成。

## 实际入口与保留语义

V155 已从真实当前运行时收回完整业务 SQL。混合关系反查由 `MySqlMixedRelationMutationExecutor.ReverseIds` 执行：在当前业务事务内，保留活动范围、稳定主键游标、128 条分批及 `FOR UPDATE`，字符串 ID 按二进制精确匹配。原样本每表只有主键、唯一 ID 索引及逻辑删除索引，没有关联字段索引。

诊断不移除锁、不降低 RR 隔离、不跳过关联传播／权限／文件事务或结构验证，也不改变省略字段与显式 null 的规则。目标记录可缺失、部分保存刷新直接缓存等兼容行为保持。

## 实库变体

服务器身份、地址及 MySQL 实例在执行前核对。MySQL 8.4.11、`performance_schema=0`；首个要求该功能的预检在创建任何资源前拒绝。后续改用自有连接的完成标记验证锁查询已执行，再保持事务四秒；第二事务只设置自身 `innodb_lock_wait_timeout=1` 并独立执行。等待失败后，在首事务回滚后重试。没有开启全局观察、增加权限或修改全局模式。

贴近测量数据的四表样本 `38adca8e9da2448f9a4401e3e43d1d36`：每表 12 行，原外键值为较早的种子 ID，两个新目标为后生成 ID。查询、目标、数据与索引均预先固定。

| 变体 | 执行计划使用索引 | 首事务持锁时第二事务 | 用途 |
| --- | --- | --- | --- |
| 原二进制比较，无关联索引 | 主键 | 1205 超时 | 复现无关目标等待 |
| 原二进制比较，添加关联索引 | 主键 | 1205 超时 | 仅加索引不足 |
| 关联索引＋普通等值预筛选＋原二进制比较 | 关联字段索引 | 成功 | 候选修复方向 |
| 关联／删除标记／主键组合索引＋同一预筛选 | 关联组合索引 | 成功 | 候选修复方向 |

两种成功查询分别耗时约 106／79 ms，只用于确认第二事务在第一事务仍持锁时完成，不作为应用吞吐或性能得分。二进制比较仍决定最终匹配，普通等值条件只能作索引预筛选，不能替换精确条件。

此前另一组目标位于现有外键之前的样本中，带预筛选的单列及组合索引查询也出现等待，不能推断此方案消除所有锁竞争。最初参数变体、一次准备表达式错误和这些阴性结果均保留；不能只展示最终成功样本。
