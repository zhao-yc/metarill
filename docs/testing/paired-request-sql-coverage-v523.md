# V523 固定双端业务请求 SQL 覆盖复核

2026-11-07，独立复核 [V471](paired-current-full-sql-v471.md) 在 Server-200 的真实采集。原 C# 镜像来自 `7adb1728`，本轮在 `e2b84971` 开发基线审阅封存证据。逐一匹配 132 份归档摘要、双端 54 个原请求及旧清理回执。原环境和业务样本均沿用该归档。

| 补齐的场景 | 本轮证据 |
| --- | --- |
| 合同预览与过期摘要重放 | 双端 4 个请求、6 条合同 SELECT、11 个绑定值。预览均无业务写入。重放的授权范围读取和合同排他锁读位于同一事务，随后回滚。两端合计 45 条驱动命令全是 SELECT。原物理读回确认合同仍为已处理。 |
| 客户复制、更新复制件、改名、删除复制件 | 双端 8 个请求、11 条写命令、36 个绑定值。核对原客户与新主键、复制的空备注、复制件独立更新、客户改名后关联缓存写回和复制件软删除。两端各 4 笔事务提交。原物理读回覆盖正常值及墓碑。 |
| 请求覆盖 | 之前 52 个读取、18 个身份或拒权、16 个客户写入及 18 个合同写入的分类有 8 个重复请求。本轮补 12 个原来未覆盖的请求，按宿主及步骤去重后与固定 108 项请求清单完全一致。 |

Java 在写事务外读取复制来源，C# 在写事务内锁定来源。改名时，Java 通过活动合同的客户外键更新缓存，C# 先按相同客户范围锁定，再以合同主键更新同一事务中的缓存。复制件在本样本没有关联的合同，Java 仍发出带复制件客户键的缓存更新，C# 跳过无匹配写入。

过期摘要重放保留已记录的宿主响应差异。Java 返回 HTTP 200、业务码 500，C# 返回 HTTP 409、业务码 409。初次范围读取均含合同名称限制。排他锁读仍核对相同主键与活动状态，C# 也在锁读中复核名称限制。

审计使用原 JDBC 位置参数和 MySqlConnector 命名参数重算私有 HMAC，公开说明仅记录计数。四项篡改对照分别替换范围常量、复制目标 ID、回滚事件和请求覆盖，均被拒绝。本轮使用封存的真实实库记录。固定请求现均有独立业务 SQL 证据，触发器及存储程序等间接访问、全体命令语义、当前候选性能与首版签收仍按 [实施进度](../project-progress.md) 跟踪。
