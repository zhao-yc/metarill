# 原页面创建与字段默认规则

本片恢复原Java创建入口的区别，只维护元数据，不建表、不执行DDL，不修改页面DOM。普通页面新增只校验归属、派生缓存和既有字段，不自动把所属表全部列加入新页。表首次创建的默认页及原“创建页面”按钮显式调用同一内部初始化入口，所有活动列都建立映射并默认显示、编辑；该入口必须加入既有项目事务。

新增列只给本次源列建立映射，不补同表其它列的历史空洞。表有0个活动页面时不建映射；1或2页时各页显示/编辑为1；3页及以上仍给每页建立映射，但显示/编辑为0。活动页数在项目锁后的当前读中确认，软删页不参与计数。

固定`BuildPageField`工厂沿用`ConfigPageColumnServiceImpl.createForColumn`：只读仅由源列`is_join_column=1`确定；必填默认0、默认值为空串，`sort_no`例外为默认值字符串`99`且必填1；重要、筛选、自动聚焦、合计、打印和改变后自动保存默认0。源列自己的默认值、数据库非空或页面标志不自动成为页覆盖。名称/物理列名与排序缓存来自真实同表源列，排序null保持null。主键、审计字段名不再擅自改变这些页面标志，生成写入的ID和系统字段保护仍保留。

复制页面只复制源页活动字段、按钮和出向子页关系；字段默认值和显示/只读等原覆盖保持，派生缓存按真实源列核验。源页未配置或已软删的映射不会出现在新页；不新增授权，不修改源记录，也不调用全列初始化补历史洞。

原依据：`D:/svn/yzp/backend/yzp/src/main/java/com/yinzon/service/impl/ConfigTableServiceImpl.java:48`、`ConfigPageServiceImpl.java:27`、`ConfigPageColumnServiceImpl.java:40`及`controller/admin/custom/ConfigPageController.java:94`。Java页面的普通新增没有`afterAdd`补字段钩子。

本片明确保留C#的8条显式系统列、默认项目范围`yz_project_id=@current_yz_project_id`、页面直接后台归属，以及现有权限/项目锁/事务和派生字段边界。这些与原Java基类/DDL隐含系统列、空默认where和旧菜单归属存在架构差异，不能称完整等同原Java。没有迁移或批量回填历史配置，没有删除种子。
