# 跨表Excel原模板与空单元格

该批修复原模板字段与空单元格内部准备，不启用尚待确认的非空路径还原策略。页面、样式、按钮、请求路由与模板列不增加操作步骤。

## 原字段边界

只读实测确认，原页面只声明amount/name/place_id，普通表单扩张隐式级ID后，旧ImportRenderer.Columns却额外带入area_id/country_id。生成模型现在保留扩展前的DeclaredWritable快照，Excel字段取该集合与最终可写列的交集，再排除上下文父字段。

普通表单DTO仍接受控件所需隐式各级ID；Excel不会因此增加未配置标题。显式且可写的祖先字段仍可导入，只读或当前父范围字段保持排除。受管名称和废弃凭据继续使用原排除规则，不回写页面或元数据。

仅靠DetailColumns不足以排除只读祖先，因为跨表表单本来会为控件重新加入ID。新增回归实际发现这一点，随后改用原始可写快照；原失败保留，不把失败当成通过。

## 空值、缺省与同一行字段

省略级联列不改原选择或已存名称。明确空字符串/空白/null单元格在内部DTO准备中清空各级ID，防止只清叶子后误保留旧祖先。名称仍由正常Service归一化维护，不从Excel信任名称。

若同一行显式配置并提供祖先字段，保留其输入，规则不依赖JSON属性顺序；父范围仍由真实上下文绑定，不能清除当前父归属。普通表单的部分更新、缺省与显式null合同没有改动。

只要求真实来源import动作，普通create/update与目标list仍可以被撤销。后续走原默认值、手写规则、原事务、正常Mapper和存储核验，不另开写通道；第二行失败整批回滚，撤销来源import不写入。

## 非空路径与验收范围

非空跨表路径仍明确拒绝，等待[路径策略决定](cross-table-excel-policy-decision.md)；不会把原可能误选/清空的回退规则或新的单元格格式在未确认时启用。完整路径Excel、严格唯一/旧排序首条等策略、导出文本和无损往返不据此标完成。

两种来源键实际生成编译及MySQL/生成HTTP验证清空、缺省、新建空值、父范围、仅import权限、源撤权、隐藏标题拒绝与整批回滚。原测试宿主遗漏PageImportException导致预期失败正文不是JSON，修正测试宿主后重跑；初次编译Header私有可见性错误未入库，改同程序集复用既有标题规则。最终关联205/205、零失败零跳过，前序专项重叠不累计。独立BackendOnly包在移除仓库定位环境变量后实际构建成功，含空值准备与非空策略门禁；未完成用途Full原子拒绝。215正式产物两轮逐字相同，24手写partial不变，十组累计825个随机表名独立连接核零，最终源码摘要与回归一致。
