# 非冗余 crossTable 逻辑父范围的文件引用

本项延续[逻辑父范围](nonredundant-cross-table-parent.md)。保持原页面、样式、组件、文件控制器路由和交互，只补 C# 文件后端的父路径证明。这里的完成范围是固定 MySQL 后端与 BackendOnly 源码包，完整模块仍按[项目进度](project-progress.md)跟进。

## 存储与范围

来源只存实际选择层的 ID。选择末层时，物理祖先位仍为空；文件模块不能把空位解释为没有父记录，也不能把请求中的父 ID 填入来源记录。

发布时从元数据编译固定文件父计划：沿唯一 crossTable 链取得每层真实物理主键、父键、项目、软删除和固定目标条件，并复用数据层完整读取计划校验类型和链结构。目标页必须唯一、具有所需可读字段；页覆盖改链、逻辑 ID 常量条件、精确范围和未证明上下文继续拒绝。

保护文件先验证来源页权限与真实文件引用，再读实际来源稀疏值，沿所选层向根定位。无外部事务时，来源与父链使用同一读取快照；已有写事务时使用当前读及锁，避免旧 RR 快照提供父归属。多条逻辑父条件与普通物理父条件必须指向同一实际父 ID。

## 引用与删除事务

- 引用变更加入原业务连接与事务，锁定来源及真实父链后才处理文件与引用；没有请求祖先或临时归一化值参与授权。
- 物理删除前保存同一身份、项目、事务、真实来源及实际父 ID 的一次性证明。删除后确认来源确实不存在，再复核父路径；同事务中换父也必须拒绝并整体回滚。
- 软删除、复制、导入沿用原观察器和动作边界。文件首次绑定例外、已有文件再次引用的来源读取要求，以及写后离页规则保持原行为。
- 读写只投影必要 ID 与父键；SQL 标识符来自冻结元数据，项目、节点与条件常量参数化。启动不自动修改业务结构。

覆盖导入另修正一处生成前校验：页面排序与表排序不同时，数组门禁检查实际用于匹配的表级首列，避免输出字符串与 JSON 数组比较的无效 C#；正常标量匹配顺序不变。

## 已执行场景

| 范围 | 直接验证 |
| --- | --- |
| 稀疏文件 | 来源 string／int64 与目标父键 string／int64 四组合，直接选择根／中／末层；三表相同数值主键不混层 |
| 读取拒绝 | 隐藏目标、错误项目、多个物理层位同时有值、混合物理父不匹配；另一普通测试账号不能下载 |
| 事务与锁 | 旧 RR 快照后目标失效，记录与引用回滚；物理删除换父拒绝；独立 NOWAIT 证明来源和三层目标锁；尾部故障回滚 |
| 生成 HTTP | 两种来源类型分别走原上传计划、多段上传、完成、保护下载、生成新增／复制／更新、原导入及软删／物理删 |
| 发布与更新 | 带实际文件列的 BackendOnly 包包含完整文件父运行时并编译；运行时同步保留手写 partial，未知相邻 partial 仍拒绝 |

HTTP 测试采用固定测试身份，不能替代正式登录、设备授权或原浏览器验收。非空级联路径 Excel 仍按既有待确认策略拒绝，Full 仍保留未完成用途门禁。
