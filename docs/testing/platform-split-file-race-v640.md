# V640 平台分库文件绑定、删除与权限撤销

2026-11-08。当前开发提交 `c6096545`。沿用 V620 的 51 份固定 Windows Production 宿主与 11 份元数据，其中含独占示例的两个文件控件。当前提交与宿主基线 `5c8fcb82` 的运行时、生成文件、模板、元数据和构建输入逐路径一致。两轮均在 Server-200 上使用独占平台库、业务库、临时账号和 Redis。

| 场景 | 实测结果 |
| --- | --- |
| 绑定先进入等待 | 普通写者的客户更新先取得等待位置，随后同一写者从另一个 HTTP 请求删除该文件。放锁后绑定返回 HTTP 200／R200，删除返回 HTTP 200／R500。业务库有一条有效引用，普通读者从原路由下载，内容字节一致。 |
| 删除先进入等待 | 独立客户与文件样本中，删除先进入等待，随后绑定更新。放锁后删除成功，绑定返回 HTTP 200／R500。客户备注及空附件保持原值，文件已删除，活跃引用为零。 |
| 两次实际锁等待 | 每组先观察一条，再观察两条本轮业务库的 InnoDB 等待连接。独立会话对同一文件 ID 使用 `FOR UPDATE NOWAIT`，均得到 MySQL 3572，放锁前两请求都未返回。 |
| 源授权撤回 | 在平台库精确撤销合成普通读者的页面查询授权。同一登录会话的原详情及受保护下载均拒绝，普通写者仍可下载原附件。业务库客户、文件和引用快照保持一致。 |
| 数据归属与退出 | 两组文件与引用都没有写入平台库。四个真实会话已注销，合成文件对象为零。两轮测试资源由新连接独立核零。 |

正式复验共 58 个原 HTTP 请求，含 38 个业务成功、15 个预期拒绝和 5 个字节校验。首轮先观察到绑定成功、并发删除拒绝，随后夹具尝试重新绑定已经解绑的旧保护文件，收到 R500。按现有文件来源规则，有解绑历史的文件不能仅凭上传者身份重新取得首次绑定例外。复验改用独立客户样本，保留主客户的原附件供撤权测试。

本轮覆盖平台分库、普通角色和本地文件。浏览器、S3 同一竞态及性能按独立专项验收。
