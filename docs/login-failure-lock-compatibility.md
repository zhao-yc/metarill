# V62 原账号与IP登录失败锁恢复

日期：2026-11-03；起点f4daa5a。恢复原登录保护，不改变页面、Cap交互或业务接口，不新增表、字段或启动DDL。此项与V61 Cap、V57／V58审计配套；未把代码或Redis独占探针当作真实完整Web／MySQL正式验收。

## 原规则及次序

固定b6d64fb原九方法Controller定义：账号5次、IP20次，计数窗口均15分钟，达到阈值分别锁15／30分钟。计数窗口从首次失败开始，不随每次请求刷新。账号锁优先于IP锁，先检查锁再进行Cap；Cap拒绝不算口令失败。成功只删除失败计数，不删除锁键。提示保持原“该账号登录失败次数过多，请15分钟后再试”和“当前登录请求过于频繁，请30分钟后再试”。

共享Redis Lua一次处理账号／IP两个计数与期限，避免INCR成功但EXPIRE遗漏的窗口；已锁请求不再增加计数或延长期限。Cap期间可能被并发请求锁定，因此密码查询前再检查。原请求频率限制仍独立存在，不用它替代失败锁。

## 共享实现、审计及事务

Security提供ILoginAttemptStore／RedisLoginAttemptStore，平台与完整应用宿主都显式注册；不是在页面或生成CRUD中维护计数。StackExchange.Redis固定3.2.0，按官方共享ConnectionMultiplexer方式延迟复用；无配置或Redis故障明确提示“登录安全校验暂不可用，请稍后再试”，不降级为进程内计数或开发账号。连接断开时不排队重放旧操作，避免恢复后旧清理误删新的失败计数。连接与命令超时有界，私有地址／口令及内部异常链不回传。

仅真实用户名／口令失败在认证事务回滚后增加计数，再记录原yz_manager_log触锁标志；已锁请求记录原拒绝原因、无账号关联，但不计数。停用／后台归属拒绝继续记录审计，不伪装成原口令失败。审计持久化失败仍保持原拒绝与锁结果。平台成功在自身事务提交后清计数；独立宿主拥有外层项目／后台事务，由外层提交后清一次，内层不提前清理。会话插入失败整笔回滚，失败计数保持。

Redis与MySQL不做分布式事务：成功会话已提交后若Redis清理失败，本次不返回成功或令牌，但已提交的会话记录不会被伪称回滚；其令牌未交给客户端。跨应用进程复用同一Redis计数，Redis本身的数据持久化／高可用仍由部署负责，不能把应用重启保持等同于Redis丢失数据后的恢复保证。
