# 精确数据管理对齐

目标是完整保留原V8的记录范围能力，覆盖普通页面、生成项目、文件真实引用及原操作，不改变前端流程。下面区分已经实现的决策基础和仍待完成的执行链，不能把决策测试当作SQL过滤或完整功能验收。

## 已实现的直接页面动作决策

原规则来源为PowerInterceptor.applyExactDataManageFlag、YzpPermissionService和原文件PagePermissionBusiness：当前操作所有有效授权都来自is_scope角色时才需要精确数据管理。账号同时具有普通角色不代表全部动作不受限制，普通角色必须实际授予当前页面当前动作；is_all作为当前动作的另一条有效授权来源。后台super不受精确限制。

共享PrincipalRolePolicy现对已经支持的直接页面授权聚合ExactDataManagePermissions，保留页面及启用动作的发布/当前目录交集。外后台、软删角色/授权、损坏授权JSON、未知动作、其它页或仅菜单授权不影响当前动作。集合包含经过is_all展开后的有效动作范围决策，不额外授予动作本身；执行入口仍需原页面权限检查。

普通AuthenticationService与事务内SecurityRealmCurrentReader都将最新决策放入本次AuthenticatedIdentity。每次重新认证重读角色和权限，已有身份快照不被原地修改。Realm和Identity的既有位置构造参数保持，新增集合标记JsonIgnore，不加入HTTP响应、会话存储或原权限接口。

当前代码仅保留授权来源决策，尚未消费这些决策构造业务SQL；不能声称范围角色已经安全开放使用，不能以此宣告精确数据管理完成。没有新增发布支持声明或变更原页面。

## 仍须完成的完整链路

- 对齐原直接/父子继承来源的组合决策，选择弹窗不能借来源页授权获得独立文件读取权限。当前直接页决策不替代继承规则。
- 按已发布后台账号匹配字段及页面记录匹配字段编译固定计划；snake/camel名称、真实物理/派生属性和类型要与生成模型一致，不能执行客户端字段名或动态SQL。
- 账号单值执行等值，JSON数组执行IN。原配置启用而账号值为空、空数组或缺失时不匹配任何记录；损坏JSON、不可表示类型和未证明表达式不得退化成不加范围。
- 列表、明细、数量、统计、导出、分页前过滤、写前锁定、复制/导入及关系候选按各自原动作使用同一固定范围。导出不能借查询动作的普通角色授权取消自己的精确限制；写操作不能误用详情动作决策。
- 文件读取、浏览计数、可读他人文件整理及后续绑定复用来源页查询范围，事务内读取继续使用当前连接/事务，保持同批未提交记录可见。
- 通过正式完整包Production/Web及真实MySQL分别验证范围/普通/混合角色、单值/数组/空值/损坏值、跨项目/父、撤权及记录变化、导出/写入回滚。离线授权类、SQL计划或HTTP TestServer不能代替这些验证。
- 同步平台、完整包、本机助手更新策略及已有工程升级文档，重复生成保护手写partial；不直接手改原页面或物理表来掩盖缺口。

原文件库还要求真实引用、当前记录实际文件值、项目/父范围与未删除状态，精确过滤是附加条件，不能替代这些核验。MySQL首版整体验收、浏览器、真机、性能及后续数据库目标继续保留。
