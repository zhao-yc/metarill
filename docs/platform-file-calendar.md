# 平台手写审计与上传期限分离

日期：2026-10-29；修改前基线3536e02。本批接续C30的生成日历合同，将平台手写审计和文件上传期限分别解释，保持原页面、按钮、上传协议、字符串ID及文件权限/事务路径。真实MySQL变更和上传验收尚未执行。

## 权威来源与范围

先通过YZP MCP只读列项目，确认其仍指向旧Java的YZP/美业等项目，不向其中写入C#配置。Metarill固定文件基础设施的单一事实来源为backend/metadata/files.json，平台ProjectFileRuntimes与独立包均从该目录合成物理模型；它不属于原Java项目的在线可编辑字段。本批先改此源，再由公共MySqlSchemaPlanner编译、比较，不手工建列或直接补实体/Mapper。

文件库表ID2200000000000000364新增字段ID2300000000000000401：upload_expires_at，逻辑datetime、物理datetime(6)、可空、无默认和索引，不增加页面或页面字段。新增/更新/软删的展示审计继续使用BusinessCalendar.Now；截止值明确代表UTC，不从展示日历推断。服务端生成计划时保存同一个六位精度截止值并返回既有ExpiresAt，仍为三十分钟。

普通元数据工作台、关联/批量字段、索引/菜单聚合、配置联动删除、反向导入、开发种子及手写角色权限审计均接入原宿主日历。初始化账号的角色/账号审计改用日历，但sys_session注销仍用UTC；该准备入口原有行为待确认状态不因本批改动变为已发布。开发备份文件名仍用UTC，认证会话、OAuth/令牌/授权TTL不变。

## 新旧上传计划

新计划只按upload_expires_at比较实际UTC瞬时，insert_time不再参与过期计算；等于截止仍允许，大于截止才拒绝，保留旧边界。显式非空期限损坏立即拒绝，不降级到insert_time或不限期。只有字段为空/旧记录缺字段时，才按原UTC创建时间加三十分钟，兼容本次结构升级前已经存在的计划。

文件、文件夹和引用的审计改用日历；本批不重写旧行，也不将旧UTC审计整体加减八小时。上传状态、所有者/项目校验、流大小/摘要、存储路径和事务步骤不变。校验仍发生在持锁读取当前计划之后、创建临时文件之前。

## 发布与结构顺序

当前打包器、独立宿主启动及平台项目文件运行时要求固定目录声明可空六位UTC期限；候选更新同时检查元数据和FileUploadLifetime.cs，不能重算包摘要后绕过缺列/错误类型/精度/默认约束。旧目标目录不要求预先包含新列，可通过原同步运行时操作接收新目录；文件模型和运行时代码同属sync-runtime范围。

上线前须分别核对平台库与每个已发布业务库的实际结构，沿原SchemaService预览→审查SQL→显式执行→核验→记录结果完成新增可空列，再切换运行时。普通启动不改表。不得只更新FileLibraryService，也不能把本地新增列计划当作实库DDL已执行。没有更改已有业务列的时间精度或自动回填。

不支持新旧文件服务混合处理新计划：旧二进制仍会将新的日历insert_time当UTC。回退前需停止新计划流量、处置在途计划并确认不存在需要旧服务处理的新日历计划；不自动删除记录或回滚DDL。既有已完成文件和引用不因本批改动重写。
