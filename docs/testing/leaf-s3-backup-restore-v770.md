# V770 当前候选平台分库与 S3 对象恢复

2026-11-09。使用产品 `4ef3ca76561e3e3b5e8a6915312ecfff78f1b3a3` 的 51 个 Windows x64 Production 宿主文件和 V758 合成附件元数据。Server-200 上同一 MySQL 实例内使用四个独占库，源与目标分别使用专属库级账号、Redis 和 SeaweedFS S3 兼容服务。独立探针使用与宿主逐字一致的 AWS SDK，库存门禁 8 项通过。

| 环节 | 实测结果 |
| --- | --- |
| 停写与恢复 | 源宿主停机后，将平台库 24 张表和业务库 13 张表导入目标空库。六类结构目录、数据语句及源复导出核对一致。 |
| 对象及文件引用 | 独立 SDK 验证目标空桶后按原键复制两个对象，目标新客户端复核键集合、大小和 SHA-256。源 S3 容器在目标下载前已回收。 |
| 逻辑地址及权限 | 目标逻辑地址变更时，两份文件均被拒绝。恢复原逻辑地址并使用目标凭据后，无需改写文件引用，公开文件 35 字节、受保护文件 38 字节均与原摘要一致。匿名受保护下载、无页权限、旧注销会话和只读写入均被拒绝。 |
| 独立核对及回收 | 25 个原 HTTP 请求、13 项实际 SDK 操作通过。客户、文件和引用仍归业务库，三条 Web 会话已注销，源数据未变。两端空桶删除后，从新连接确认本轮四库、账号、Redis、S3 和本机回环转发均已回收。 |

本轮覆盖同一 MySQL 实例内的平台分库、S3 兼容服务及逻辑位置保留。跨 MySQL 实例的本地附件恢复见 [V769](integrated-cross-instance-recovery-v769.md)。实际供应商、版本桶历史及主动改变逻辑位置的迁移分别核验。恢复操作见 [安装与恢复](../mysql-first-release-install.md#更新与失败恢复)。
