# 原单选页的固定派生名称

## 已接通行为

R0来源SelectPage可以使用普通R0目标的单值字符串联接名称。例如订单customer_id选择客户，客户company_name来自公司name；来源的customer_company_name保持只读逻辑值。保留原type=1列表选择页、弹层、清除、回执和父上下文，不另写页面或样式。

此前NonRedundantSelectionCompilation只接受物理名称，派生名称的共享计划又只允许List。现新增独立目标证明后复用既有固定目标读取：目标页自身按逻辑名称在SQL内筛选／分页，辅助候选、已选、原名称导入与票据导出沿同一范围；名称终点使用固定单值匹配证明，凭据／文件数组／错误路径继续拒绝。普通请求不重新解释元数据或接受SQL。

目标页面必须是真实type=1、名称已开放读取、普通同项目R0实体；项目／软删、真实父与附加条件按原目标页执行。SelectPage的附加条件只能是目标页已执行的固定条件；来源表单动态条件、未证明排序、全局／逻辑父／精确权限等组合继续保留门禁，不能借宽目标页代替窄条件。

原List的证明与生成路径保持；能力声明按实际控件写SelectPage，未把所有派生名称都标为List。无目标父、同父以及由来源实体物理FK推导的独立目标父分别验证；隐藏关系仍执行默认值与最终FK校验，不增加公开候选入口。

## 跟进与边界

本批没有新增数据层API或业务DDL。已有同版正确逻辑名称模型更新生成器后，正规再生成受影响Service、DTO/VO、Controller与原页面；沿原三动作预览／应用保护手写partial、AppID和私有配置。元数据变更仍先维护定义并预览结构，不建立新的物理名称缓存或自动回填。

本批仅完成固定R0单选字符串派生模型；没有新增正式Web／专属空库、原浏览器、跨端或同条件性能结果。其它复杂联接、全局／多值／级联、R1派生缓存及维护传播、MySQL首版和后续数据库继续，不合main、不部署生产，新提交CI另核。
