# V319 保留父关联的 Java 子页导入对照包

V318 在原 Java 镜像观察到实际漏写父 ID 与缓存名称。本轮把原镜像保留作历史行为证据，另从其冻结样板构建 Java 对照夹具。它在原子页入口校验规范正整数父 ID，以样板父表的逻辑删除条件锁定活动记录，在同一事务中向原 Service 传递父 ID。名称缓存仍由原生成 Service 计算。保存失败继续抛出异常，使批次事务可以回滚。该补丁只用于独占性能样板。

Java 21 离线打包执行了 3 项对照夹具、9 项原登录、1 项原类路径测试，共 13 项通过。夹具覆盖父 ID 绑定、无效和不存在父 ID 拒绝、末行保存失败向事务边界传播。初次全样板测试还触发依赖真实 MySQL 和 Redis 的用例，离线环境缺少连接配置。实库事务与接口仍需另验。

本机与 Server-200 独立重组 JAR，摘要一致。只有 `SampleContractLine81003ImportSupport.class` 内容变更，154 个嵌套依赖、其他类、配置和归档条目次序均保持。禁网探针核对了镜像内 JAR、Java 21 和原用户／启动配置。首次镜像检查因 Docker 省略空 `Cmd` 字段中止，随后沿用已构建的同一镜像补做检查。通过新 SSH 核验两容器和临时构建目录均已回收。该轮未启动业务宿主，也未连接数据库。

正式回放前仍须用固定原工作簿验证双端父 ID、缓存及子页可见性，覆盖无效父记录和末行失败回滚，再审阅实际 SQL 与参数。V318 的原 Java 结果继续有效，V08 子页同条件性能保持待验。
