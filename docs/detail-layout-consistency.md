# 原详情布局跨入口一致性

日期：2026-10-30；起点 `b9d913f54ada0ef9c0232084c66d1049eb277b7a`。本轮修复平台配置与生成规则，不修改原页面、组件、样式、交互、元数据或数据库结构。

## 原合同与已复现差异

原YZP的 `DetailLayoutDefinition.Group` 限定机器标识以字母开头、仅含字母/数字/下划线/短横线，最多64字符；`PageDetailLayoutRules` 对普通页面和页面字段保存也检查分组引用，关闭tabs仍保留定义与归属；`PageDetailLayoutBusiness.Snapshot.Field` 同时返回pageColumnId与columnId。

C#原实现存在以下差异：

1. 工作台允许最多100字符key，生成器最多64字符，产生“保存成功、不能生成”。
2. 普通配置观察器未检查布局和字段归属，可删除仍有活动字段引用的组，或直接写入不存在的组。
3. 生成器把未知组静默当常显；隐藏字段及关闭布局同样可能留下错误引用。
4. 快照缺失原columnId；只返回页面字段ID，无法保持原字段识别合同。
5. 聚合保存未检查每条更新的实际命中数，后笔零命中可能被当作成功。

实际红灯：元数据相关20项中8失败、10通过、2实库跳过；生成拒绝组中1失败/5通过/零跳过；原columnId合同另有2失败/零跳过。失败日志与TRX保留，不改写为通过。

## 修复边界

- 新共享 `Metarill.Core.Metadata.DetailLayoutConfiguration` 固定version=1、none/tabs、唯一64字符key、有效名称及明确字段结构；拒绝重复/未知成员。旧空存储仍为常显，非空坏JSON不降级。工作台保存、原复制所用规则、普通观察器和生成器共用它。
- 普通页面保存对锁定的全部活动字段检查引用；字段保存使用同项目的已锁页面检查。原项目锁、身份、表/页归属及事务仍保留。字段墓碑不阻止活动页面移组，也不会被清空或复活。
- 明确提交布局才归一JSON；普通改名保留已有布局字节。明确提交字段归属null沿原规则保存为空字符串，省略该字段不清空。
- 原工作台完整提交定义与全部字段归属，在原同一事务内完成迁组和删除旧组；不是逐笔调用普通入口造成中间态悬空。逐笔检查更新命中，第二字段或末笔页面失败时全部回滚。
- 快照补回字符串columnId，保留原pageColumnId及已有字段。一次建立ID索引，未引入逐字段查询，超过2^53的ID不经浮点数。
- 生成期只解析一次布局，验证全部页面字段（包括隐藏字段及关闭模式），错误发生于原生成器完整计划阶段；合法页面的原模板文本保持。新Core源码进入真实独立包并由自身源码构建，不依赖开发机DLL。

原聚合路由仍为 `/api/admin/custom/page_detail_layout/snapshot` 与 `/save`，工作台与按钮没有变化。专用MCP聚合入口另外跟进，不将本轮固定子集等同于B12全部完成。
