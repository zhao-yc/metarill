# V413–V416 默认配置同父导入的语句级诊断

2026-11-06，使用 V412 产品 2856e6aa 的固定源码和原生成导入接口，在 Server-200 MySQL 8.4.11 的本轮合成库上运行私有 C# 探针。仅为每个请求的专用连接开启会话计时，在七行合并命令前及提交后读取历史并按编号去重。每个请求完整保留连续的 98 条分类计时，SQL 正文及值只在内存中分类。探针不连接其他数据库，不修改实例级参数。 [MySQL 会话计时](https://dev.mysql.com/doc/refman/8.4/en/show-profile.html)

V413 未能按被截断的语句末尾识别父候选，原 HTTP 已走七行合并。V414 改用语句开头识别，20 次原 HTTP 和 160 条物理明细通过。V415 细分两次父锁读、七次合并父候选、八次缓存写入与八次物理读回，20 次原 HTTP 和 160 条明细通过。V416 交错执行同父与分父四并发，各 16 次，另有 4 次单并发。36 次原 HTTP、3,528 条分类计时及 288 条物理明细独立复算通过，逐父行数和缓存值匹配。四轮各自的库、账号和所有权记录已用新 SSH 独立核清。

下表为每个成功请求各类别合计耗时的中位数，单位毫秒。

| 类别 | 单并发 | 同父四并发 | 分父四并发 |
| --- | ---: | ---: | ---: |
| 父记录锁读 | 1.1 | 302.2 | 0.6 |
| 合并行父候选重验 | 3.2 | 4.7 | 2.7 |
| 物理结构检查 | 5.5 | 9.2 | 6.1 |
| 明细插入 | 3.1 | 4.2 | 2.6 |
| 缓存写入 | 5.7 | 8.4 | 5.2 |
| 缓存比较读取 | 3.4 | 5.2 | 3.1 |

| 排除父锁读和提交的语句总计 | 32.2 | 46.5 | 29.5 |

四个同父批次的最后一个锁读累计达 500.2–613.5 ms，四个分父批次各请求均低于 0.8 ms。分父组提交时间更长，因此父锁读和提交需单独看。语句分类未区分每条锁读的纯锁等待和 SQL 自身执行，也未测锁释放的准确时刻。探针在 Windows 发起原请求，并增加了历史读取和应用观察。这轮用于定位 C# 事务，无法归因 Java／C# 之间的全部差距。发布门槛仍以无探针的 V412 判定。 [V412 正式对照](paired-child-default-single-command-timing-v412.md)
