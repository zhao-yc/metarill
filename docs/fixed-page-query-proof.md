# 固定页面查询与单选范围证明

`FixedPageQueryCompilation` 把实际强制行范围与有效默认排序集中为编译期计划。Mapper、页面 Scope 和默认 Order 消费同一事实，单选名称筛选及读取依赖 IR 也以此证明配置是否已经由目标页面约束。此计划只来自已发布表/页元数据，不接受客户端表、页面、SQL、参数绑定或原始排序表达式。

## 实际查询计划

- 物理表存在 `delete_no` 时，Mapper 查询起点仍为 `delete_no IS NULL`；没有该列时保持原行为。
- 非 global 表存在 `yz_project_id` 时，即使页面 WhereSql 为空，也按真实 Actor.ProjectId 自动约束。global 表只有页面明确声明项目条件时才添加此约束，不能把“有项目列”直接当成“已限制项目”。
- 页面明确的父等值条件独立绑定 `parentId`。项目身份与父上下文不能因为值相同就互换；现有真实父记录校验、页面权限及事务入口均不由此计划替代。
- 默认排序先编译页面原 OrderBy；原序列没有主键时追加 `id desc`，原已含主键时保持原序列。既有请求结构化排序白名单、取消排序、ID 补位规则不变。

页面 WhereSql 现可将已发布物理标量的固定常量 AND 条件与原项目/父等值范围共同编译，完整范围见[页面固定条件](fixed-page-conditions.md)。选择控件附加条件逐项证明：身份项按稳定字段 ID 与绑定来源比较，常量项必须与目标页实际执行的规范条件项一致。重复项可去重，不能以来源更窄的条件替代较宽目标页，也不自动证明数学等价表达式。OR、函数、其它变量和任意 SQL 继续拒绝。软删除虽属于实际查询计划，附加 `delete_no IS NULL` 仍须由目标页显式声明相同条件，不能据此开放其它配置语法。

附加 OrderBy 非空时采用相同的主键补位规则，要求与目标有效默认序列逐项相同；空配置继承目标默认序列。例如目标未写 OrderBy 时，配置 `id desc` 与实际默认相同；目标 `name asc` 与配置 `name asc,id desc` 等价。`id asc`、交换列顺序或未知函数不能通过证明。原配置及未知合法 JSON 键完整保留，不把附加 SQL 送到 HTTP 请求。

单选与已支持的冗余 MultiSelectPage 共用附加范围证明；多选原有显式排序比较、非冗余、名称及父映射门禁继续保留。未证明的来源额外条件在生成落盘前拒绝。IR 原有联接、非冗余和未知父缺口继续保留。

## 平台两个原配置

`config_child` 页 `1679390851298631682` 的 `parent_config_page_id` / `child_config_page_id` 页配置均指向目标页 `1869016706289577986`，保留 `whereSql=yz_project_id=@current_yz_project_id` 与 `orderBy=id desc`。目标 config_page 表为非 global，实际查询含未删除、真实 Actor 项目约束，没有父范围，并默认 `id desc`。因此这两项是已有范围与排序的重复声明，可以安全接通原名称筛选。

保留原列表输入及辅助键 `parentConfigPageName`、`childConfigPageName`，名称谓词仍在共享 Query 的分页前执行，page/count/export 继续复用。该查询证明独立验收时，角色权限引用修正后的 6 项能力缺口只减少这两个筛选项，剩余 4 个详情关系保持明确 Gap；后续[固定源父归属](fixed-parent-column-relations.md)单独接通其中两项。Full 包门禁继续拒绝剩余未完成能力。

## 验证与升级边界

验证包括真实生成 C# 编译、离线 FreeSql ToSql 的未删除/自动项目/global/显式项目/父条件及参数边界、取消与默认排序、AND 子集及排序序列正反例，以及真实原 Vue 模板挂载后的两个请求键。ORM 仅创建和解析表达式，不打开数据库连接；不把离线 SQL 或 Vue 探针称为真实 MySQL、浏览器或设备验收。

没有表结构、HTTP DTO 或元数据变更，无需 DDL、回填或覆盖既有库。已有项目仅需更新生成器并预览、重新生成，保护手写 partial。既有任意 SQL 或非等价范围/排序继续拒绝，不能为消除 Gap 删除用户配置。正式平台产物由集成阶段统一生成。
