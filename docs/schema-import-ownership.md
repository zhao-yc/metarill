# 反向导入的同库归属与当前身份验收

本阶段验证既有配置保存实现，不修改产品代码、原前端、生成模板或权限规则。A11整体仍未完成；本页只证明同一实际业务库中两个真实项目的固定归属和Web撤权场景。

## 原接口及实际目标

通过原项目、后台类型及表配置接口建立独占项目，主平台库为Server-200的`metarill_test`，源业务库为既有`metarill_business_test`。新项目在测试宿主中使用可信服务端`ProjectDatabases`绑定到同一业务库，先反查实际实例/数据库指纹相等；项目表中原必填连接描述仅为无凭据显示文本，不作为实际连接来源。

测试只创建随机源表、应用项目/后台/配置，以及一套独占应用角色/账号/会话；不创建数据库、MySQL账号、权限、触发器或调整全局变量，不调用“初始化账号”。所有HTTP宿主使用独占临时端口；真实登录和原JSON接口运行于Kestrel，未伪造HttpContext身份。

## 同库活动配置、墓碑及未知绑定

原接口为另一个真实项目登记源物理表，导入当前项目时应明确拒绝；通过原表配置删除接口逻辑删除后，墓碑仍阻止认领。当前项目不能出现同名新配置，外项目归属和墓碑字段不被改写，源SHOW CREATE快照及业务行保持。

没有外项目可信连接的宿主单独验证拒绝，不能从项目显示连接描述推断归属或静默退回平台库。配置完整的宿主再验证真实同库冲突；二者不是同一断言。

## 真实并发认领

两个项目先分别完成审核，再通过真实并发HTTP确认同一物理源表：恰好一个保存成功，另一个因物理归属冲突拒绝。只允许一套真实表、三列及一个索引，不创建页面；所有引用归于获胜项目。失败方的表/字段/索引/索引列/页面/页面字段，包含删除墓碑的完整配置摘要，必须与执行前相同，不能只以“没有表记录”代替整批完整性。

同一会话的两个项目计划分别查询回执，成功方为saved，失败方为unconfirmed且configurationSaved为null；源结构和业务行不变。

## 真实登录、另一会话及排队撤权

使用原角色/账号接口创建独占应用身份，普通角色拒绝建立计划；仅为该角色授予原平台超级标志后，可以审核。相同账号的另一次真实登录不能消费或查询原会话的计划，合法会话计划仍为prepared。

随后通过原角色HTTP更新撤销本轮角色的超级标志，在既有角色事务的提交前暂停。旧已提交角色仍允许导入请求通过初始认证；导入持有源MDL后等待平台项目预锁。探针反复设置本轮源表原有的空注释，直到实际ALTER出现1205，证明请求已通过认证且持有MDL，不靠固定延时推测时点；探针不改列和业务行，前后源快照相等。

释放角色事务并确认提交后，排队导入必须按锁后当前角色拒绝，返回原统一公开权限错误“无权执行此操作。”，不回显内部身份诊断。源配置保持不存在。只重新授权本轮角色，原会话重新审核后保存成功，作为受控对照，排除结构/参数错误造成的偶然拒绝。原管理员及其角色保持不变。

## 失败记录与测试宿主纠偏

首轮漏传原角色接口必填排序号，下一轮错误期待内部权限消息，分别保留失败及清理记录，没有放宽原必填或权限合同。切至真实TCP时又发现派生WebApplicationFactory首个客户端继承父地址，实际打到无外项目绑定的父宿主；服务端按未知绑定拒绝，未发生导入写入。修正测试客户端为本宿主实际监听地址，并断言两个子客户端一致且不同于父宿主；另将未知绑定拒绝纳入独立断言。最终结果以固定来源及全量回归为准。
