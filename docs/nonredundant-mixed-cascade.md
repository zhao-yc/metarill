# 同表非冗余自树与跨表级联

本项接续 B33、B40：同一个 R0 来源表在原详情中同时使用 selfTree、crossTable 和 MultiSelectPage。保留元数据、原 uni-app 页面／样式／交互及完整应用生成方式，只修正 C# 完整包的组合证明。整个复杂关系模块仍按[项目进度](project-progress.md)继续。

## 修正的问题

底层固定读取与写入已经分别编译两类级联，但完整包的两个检查器把表内全部 CascadeTree 当成自己的模式处理：跨表检查器把有效自树视作坏链，自树检查器也会把有效跨表视作坏链。四种来源 ID／目标父键的有效混合模型都被完整包拒绝，失败发生在写入 stage 前。

现在按实际模式分类，并共同证明全部同伴：

- 自树仍要求完整的自树写入计划，以及独立、同项目、普通 R1 目标；单目标证明不递归调用另一模式的完整包检查。
- 跨表仍逐层验证固定读写链、属性解释及已配置的导入导出用途。另一类自树使用真实自树计划检查，不以跨表解析失败拒绝。
- 隐藏有效控件仍参与最终写入／复制；隐藏坏链、未知模式、全局目标和未发布目标仍拒绝整个包。目标项目／后台发布检查继续执行。
- 能力清单的“多个自树／多个跨表”按各自实际写入计划计数；一个自树加一个跨表不会被写成“两棵自树”和“两个跨表”。另用 mixedCascadeModesSupported 表达两类控件共存。

共享运行时、Service 事务、数据库方言、原页面及平台元数据均未因此重写。没有为了打包而关闭实际项目按钮；验收合成模型未配置路径 Excel，用途限制沿用 B14。

## 直接验证的组合

本批来源包含一个三层跨表、一个独立自树、同目标多选、普通非空字段和五个不同页面规则。四种来源 ID／目标父键 string/string、string/int64、int64/string、int64/int64 均执行实际生成 HTTP 与 Server-200 MySQL；身份由固定测试宿主建立，只可经测试头减权，不能称作真实正式登录。

实际操作覆盖原必填／只读／默认值、混合筛选、type=2 已选回读、复制、部分选择、字段省略及显式清空。两个级联任意一侧无效时比较全部来源物理记录，确认另一侧和多选都未落半笔。直接读取物理槽，跨表只存所选层、自树只存所选节点、名称不落库；复制后的记录不受原记录后续清空影响。目标表在测试隔离样本中改名后，R0 跨表、自树和多选都显示当前名称。

两个完整包分别使用 string/int64、int64/string；实际编译包内后端，按原三动作预览／应用更新并保护手写 partial。包内原详情同时挂载真实 Vue 3 级联组件，验证跨表部分选择与自树选择互不覆盖、多选保持、长字符串 ID、清空、只读及原整 entity 保存。网络和基础渲染由测试替代，此证据不是浏览器。

另有隐藏有效同伴，以及隐藏坏自树／跨表、两种目标归属、全局自树和未确认路径导入等反例。首次测试模型沿用 R1 物理多选名称，先由存储规则拒绝；明确只读联接及 choice.name 路径后才得到真正的完整包误拒绝。各次失败日志均保留，没有放宽存储冲突或联接规则。
