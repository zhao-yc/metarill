# V630 平台分库与本地附件恢复演练

2026-11-08。固定产品 `5c8fcb823491e2e25029ffa40cb2cfdc851c0abb`，复用 [V620](current-platform-files-v619-v620.md) 逐份核对的 51 个 Windows Production 宿主文件和合成元数据。Server-200 的源、目标各使用独占平台库、业务库、MySQL 账号和 Redis。数据来自原 HTTP 上传、绑定和退出。

| 阶段 | 实测结果 |
| --- | --- |
| 停写及备份 | 源普通写者上传公开和受保护附件，绑定到同一客户后注销。确认源宿主停止监听，分别用源库级账号逻辑导出平台 24 表和业务 13 表，并逐对象核对本地附件备份。SQL 只在远端进程内传递。 |
| 恢复与目录对照 | 用目标库级账号把两份备份导入对应空库。复核两库默认字符集和排序规则，以及表、列、索引、表约束、键列及 CHECK 六类目录。平台、业务库在复导出时分别补写 315、122 处冗余 `CHARACTER SET`，逐项验证有效字符集及排序规则相同。仅折叠匹配的重复词组后，完整 SQL 摘要与源相同，所有数据语句逐字一致。源再次导出的原始字节相同。 |
| 独立文件恢复 | 目标使用自己的目录。在源附件原路径暂时移开后，目标按原接口返回公开附件 32 字节和受保护附件 35 字节，两份内容的 SHA-256 均匹配。独立 SQL 复核业务行、两个有效引用、两条就绪文件和一条未上传计划仍在业务库，合成账号及会话在平台库。 |
| 原接口和权限 | 两端共 22 个请求。目标按正常方式启动，用恢复的只读和无页面权限账号登录。只读可读详情及受保护附件，匿名只可下载公开附件。匿名受保护下载、无权限角色、源端已注销会话及只读写入均被拒绝。最终三条会话均为已注销，源及目标业务记录和文件摘要保持一致。 |

首轮在复导出的原始文本比较停下。第二轮确认源原文稳定，差异为恢复后的列声明。最终按真实目录逐项核实后通过。三轮的四库、两个账号、两个 Redis、转发、所有权、私有工作配置和合成附件副本均独立核清。验收凭据按项目另行私有归档。

本轮覆盖同实例内分库与本地附件恢复，源端会话已在快照前注销。跨实例恢复、S3 对象版本和包含仍活动会话的备份列为独立场景。
