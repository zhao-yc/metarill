## 实现归属

公开源位于 [tools/acceptance/sample-host](../tools/acceptance/sample-host/README.md)，只向独占完整验收包手动安装。普通业务项目继续按自己的元数据生成，不自动获得固定样板的三个按钮、负金额规则或回滚动作。原元数据、uni-app模板、页面、样式和交互没有修改。

Controller只绑定严格请求和响应，Business管理外层事务，生成Service处理标准更新与文件/关系规则，金额规则保留在手写Service partial。preview、complete、rollback分别固定原86000/86001/86002按钮，不能从请求选择来源。完整包使用现有 `HostCustomization` partial 注册，五份手写C#源经两轮原生成器核对字节不变。

## 原业务行为

| 动作 | 本批实现 |
| --- | --- |
| preview | 调用生成的按钮记录读取入口，返回当前名称/备注、拟改备注及expectedDigest，不打开写事务 |
| complete | 同一外层事务先按按钮范围读，再调用生成的锁定入口；锁后重算摘要与“待处理”状态，然后使用UpdateButtonRecord81002Async写备注 |
| rollback | 先执行同一生成更新，再调用同一核心写负金额；实际BeforeSave规则抛错，DatabaseSession将内层失败传递为外层回滚 |

摘要严格沿原顺序：记录ID、名称、金额普通表示、备注；null取空串，每项使用UTF-16代码单元长度、冒号和值拼接，最后UTF-8 SHA-256。金额保留decimal的scale，不使用当前文化或指数格式；大小写与原MessageDigest比较语义一致。

预览过期和错误状态在首笔更新前拒绝。Web显式冲突保持HTTP409/R409；Agent使用单独的公开冲突类型，公共中间件在账本记录成功时保留HTTP409/`YZP_CONFLICT`，但任务仍为unknown并要求查询/回读。不能通过抛错声明此前一定没有写入；账本失败和未知内部异常维持503/通用unknown，普通CRUD也不套用这个业务动作分类。
